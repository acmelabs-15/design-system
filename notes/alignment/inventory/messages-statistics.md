## M-01 Alert and Banner

acme-alert props variant: default|success|error|warning|secondary|violet|cyan=default; size small|medium|large=medium; dismissible=false; heading="". acme-banner uses the same meaningful status treatments for page/app-wide placement, with dismissible=false. Default description/content; heading/start/end/actions slots; root/icon/heading/content/actions/close parts.

They are presentation of supplied messages, not notification queues or server-error processors. Do not assign role=alert to every neutral static message; live urgency comes from an explicit role/live setting appropriate to the operation. Dismiss emits cancelable acme-request { action:"dismiss" }; the application removes or updates the supplied message. Banner persistence belongs to the application. Note becomes Alert; Project Banner is a Banner recipe. Standalone Error/Error Card are removed; field errors stay with Field.

Acceptance: static/live announcements once, heading hierarchy, action focus, no color-only meaning, dismiss/restore, long text, RTL and section versus page placement.

## M-02 Toast and viewport

Family acme-toast-viewport and acme-toast; supporting createToastStore() is explicit and optional per scope. Viewport store is a required/shared store reference, placement: top-start|top-end|bottom-start|bottom-end=bottom-end proposed; limit=3 from the reviewed Base UI provider; expandOnInteraction=true. Toast records: id, heading?, description, variant, duration, action?, dismissible. Application owns action work; description is text or author-owned safe content, never executable HTML.

Store methods add(record)→id, update(id,patch), dismiss(id), clear(). Data record types are id:string, heading?:string, description:string, variant:default|success|warning|error, duration?:number, action?:{id:string,label:string}, dismissible:boolean=true; omitted id is generated by add. acme-toast has toastId:string and inherits its store from the viewport (or accepts an explicit store property); status/position/expanded are derived, not author-writable layout inputs. Its default slot can supply framework-owned custom content in place of generated text; actions/close remain documented parts. Default duration=5000 milliseconds, with duration=0 explicitly persistent, following the [Base UI provider contract](https://base-ui.com/react/components/toast). No hidden root-global store mutation from importing Button. acme-request { action:"toast-action", id, actionId } requests an action; acme-dismiss { id, reason } reports dismissal; no duplicate wrapper notification.

Newest messages are immediately visible; older beyond the limit are hidden from pointer/focus/announcements, as selected. Preserve overlapping presentation and expansion on interaction. Timer pause/resume accounts for focus, pointer and background document state. Swipe behavior follows the assigned Base reference only where tested; no accidental click while dragging. Shadow5 and shared Lit Motion; scope-correct themes and normal inherited density.

Acceptance: visible limit, rapid arrival/update/dismiss, persistence, action focus, close interruption, reduced motion, touch/keyboard expansion, timer cleanup, hidden-item access and exactly-once live announcements. Unknown application results are not automatically toasted. [Decision](../../decisions/toast-behaviour.md).

## M-03 Feedback

acme-feedback props value: { rating?:string, message:string, email?:string, topic?:string } default empty message; topics: readonly {value,label}[]=[]; collectEmail=false; requiredMessage=true proposed; submitting=false; error="". Root is a composed form using Field/Input/Textarea/Radio or Buttons. Default heading/description/actions slots; root/form/rating/message/email/topic/actions parts.

Emit cancelable acme-request { action:"submit", value }; the application sends data and supplies submitting/error/success. No endpoint, dryRun, siteType or implicit network request remains. Inline and Toggle Tip/Dialog examples reuse the same form; the component does not own a second popup interface. reset() restores the supplied initial value. User edits use acme-input { value } and committed acme-change where meaningful.

Acceptance: required validation, keyboard rating/message, repeated submit prevention, failure/retry without lost message, optional email/topic and explicit application submission. [Decision](../../decisions/feedback-component.md), compared form examples. Exact default fields are proposed final behavior, not an assumed backend schema.

## M-04 Empty State

Family acme-empty-state, acme-empty-state-indicator, acme-empty-state-content. Root size small|medium|large=medium, variant: default|outline|subtle=default. Slots indicator/heading/description/actions/default; parts root/indicator/content/heading/description/actions. No automatic alert role, polling, value state or network action. Heading level is authored with Heading. Action controls keep their native events.

Use for absent collections/views; loading, failure and permission denial are explicit different content contexts, not one empty catch-all. Preserve composed component plus examples as selected. Acceptance: no content, long text, optional action/illustration, screen-reader heading structure, themes/zoom and narrow layouts.

## M-05 Spinner, Progress and Skeleton

| Entry | Proposed input/default contract | Semantics and content |

| acme-spinner | size: small\|medium\|large\|extraLarge\|extraExtraLarge=medium; label="" | root part; decorative when surrounding busy region supplies status, otherwise labelled status; no numerical value or dots variant |
| acme-progress | value?: number; max=100; variant: default\|success\|error\|warning\|secondary=default; label=""; shape=linear | Native progress semantics; absent value is indeterminate, supplied 0 is real zero; root/track/range/label parts; optional default label content |
| acme-skeleton | loading=true; shape: rectangle\|circle=rectangle; width/height?: CSS sizes | Placeholder hidden from accessibility; default content can be shown when loading=false; root/content parts; no fake progress announcements |

Before any Material-based shape/treatment recommendation, close that specific coverage gap. An additional circular task-progress shape is not silently inferred from Meter's circular display.

## M-06 Meter

acme-meter replaces Gauge. value?: finite number; min=0, max=100; low?/high?/optimum? optional ordered bounds; size tiny|small|medium|large=small; showValue=false; loading=false; label required. Circular measured-value display remains selected; valueText?: string supplies accessible formatting. root/track/range/value parts.

Native meter semantics for a known value; loading/absent value removes the numerical announcement and shows a distinct loading/empty treatment. Never announce invented zero while waiting. Progress remains task completion. Threshold color mappings use theme semantic roles; no raw record of unlabeled magic cut points without declared meaning. acme-change is not emitted for a display update.

Acceptance: zero/negative ranges, min=max/invalid limits, thresholds, absent/error/loading, locale/valueText, reduced motion, contrast and true meter accessibility. [Decision](../../decisions/meter-component.md).

## M-07 Stat

Family acme-stat, acme-stat-label, acme-stat-value, acme-stat-unit, acme-stat-description, acme-stat-change, acme-stat-footer. Root size small|medium|large=medium; loading=false; no selected/value-form owner. Default slot composes parts; each part default content. Value may contain FormatNumber/FormatByte rather than root parsing display text.

Change props direction: up|down|flat; sentiment: positive|negative|neutral=neutral; value?: number; formatOptions? for explicit formatting. Direction and meaning remain separate: fewer failures can be down and positive. Parts root/label/value/unit/description/change/footer; accessible text states change meaning without relying on arrow/color. No standalone Trend.

Stat can contain Sparkline/Meter as authored content without owning their data. Missing data differs from zero. No independent click/selection event; Radio/Checkbox Card compositions own selectable stats. Replace Stat Delta/Desc/Foot with full-word family parts, Metric List with Stat+List, and Stat Strip/Strip Item with selection recipes. [Decision](../../decisions/stat-family.md).

## M-08 Status

acme-status replaces deployment-specific Status Dot. Props value: string required, label?: string, variant: neutral|info|success|warning|error=neutral; pulse=false. Default slot can supply visible label; parts root/indicator/label. Application maps domain states to labels/treatments; the component does not infer business meaning from arbitrary uppercase codes. Decorative indicator plus meaningful text; no automatic live role unless requested. User motion preference applies. Retain deployment examples as recipes and verify clear meaning without color.

## Family acceptance

All entries require controlled application data, safe text rendering, exact event ownership, native semantics, theme/density/RTL and matching framework behavior. Shared loading composition must not duplicate spoken announcements in Button, list sections and page status. Reference tokens are recorded through the generator and measured separately from behavioral acceptance.
