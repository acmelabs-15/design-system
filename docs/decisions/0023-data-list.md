# Replace Description with Data List

Use one Data List family for metadata labels and values, replacing Description. Peter selected **Use Data List**, following the shared Chakra/Radix concept and name.

Decided 2026-09-19 by Peter.

Support collections of pairs, horizontal or vertical presentation and richer values such as badges, links or formatted numbers. Keep Data List distinct from ordinary List items, Field/input associations and highlighted Stat measurements. This is a metadata definition-list concept, not HTML datalist suggestions.

Description at selection time rendered a label/value definition-list structure. Exact parts, formatting, separators, alignment, help, truncation and semantics across Lit boundaries were still inventory work at selection time. Peter later explicitly [removed KV](0015-component-removals.md). Its useful content must be mapped through the approved inventory and migration; removal itself is not an open choice.

Evidence: [review](../research/06-codebase-systematization.md#accelerated-capability-and-disposition-checkpoint), [choice record](../verification/systematization/capability-checkpoint-2026-09-19.json). The completed replacement retains no aliases.

The unresolved implementation details above describe the selection-time scope. Later [component contracts](../../spec/SPEC-design-system.md) and [release evidence](../releases/0.3.2.md) record subsequent work and its verification limits.
