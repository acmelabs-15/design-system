# RES-045: How style props with responsive values become CSS, and what a custom element can do

## Question
How do Chakra UI and Radix Themes turn style props with responsive values into CSS, and how can a custom element take a value for each breakpoint from an HTML attribute with no CSS-in-JS?

Needed by IDEA-003#15, where Peter decides which mechanism the style props of the layout components use in the Lit core. Settled context: DEC-131 (style props with responsive values, as in Chakra UI, also in the Lit components; no CSS-in-JS), DEC-127 (no server rendering), the no-build CDN page of IDEA-003 (Notes). Style-prop values are token values and the breakpoints are tokens.

## Answer
Sufficient answer: (1) Chakra UI 3: the syntax of a responsive value (object and array), how it becomes CSS, what runs at build time and what at run time, and what it needs from the consumer's build. (2) Radix Themes: the same points. (3) At least three web component libraries that take a value for each breakpoint in an HTML attribute or property: the attribute syntax and how the element turns it into style. (4) The platform means for a custom element with no CSS-in-JS and no build step (media and container queries with custom properties, attribute selectors and `attr()`, adopted style sheets, the `style` attribute, `matchMedia`), each with browser support and limits. (5) For each mechanism: whether it works from a plain HTML attribute, from a React prop that is an object, and inside a shadow root. Each fact with source, version and date.

This record states facts only. It makes no recommendation and no ranking. Each statement below rests on the Findings; statements derived from several findings are marked "derived", and claims with no direct source are marked UNVERIFIED.

Words used below:
- **Breakpoint**: a screen width from which a value applies (mobile-first: the value holds at that width and above).
- **Media query**: a CSS rule `@media (min-width: 48rem) { … }` whose styles apply only when the viewport is at least that wide.
- **Container query**: the same idea, `@container (inline-size > 500px) { … }`, but measured on an ancestor element (the "container") instead of the viewport.
- **Custom property**: a CSS variable (`--p-md: 1rem`), read with `var(--p-md)`.

### 1. Chakra UI 3 (`@chakra-ui/react` 3.38.0)
- **Syntax.** A style prop takes a plain value, an object keyed by breakpoint (`p={{ base: "2", md: "4" }}`), or an array in breakpoint order (`p={["2", null, "4"]}`, `null`/`undefined` skips one). Extra keys target ranges: `mdToXl`, `lgOnly`, `smDown`. Default breakpoints are `base` 0, `sm` 30rem, `md` 48rem, `lg` 62rem, `xl` 80rem, `2xl` 96rem, set in the theme config.
- **How it becomes CSS.** In the browser, during React render. The `chakra` factory collects the style props, turns an array into an object, turns each breakpoint key into the string `@media screen and (min-width: …)`, resolves token values, and gets a nested style object. Emotion serializes that object into CSS text, hashes it into a class name, and inserts the rules into a `<style>` element in a React insertion effect. So the media queries are written by script at run time, one class per distinct set of style props.
- **Build time vs run time.** Nothing is generated at build time; all of it runs at run time. 
- **Consumer build.** React 18 or later plus `@emotion/react` as peer dependencies and a root `Provider`; the Vite guide names no Chakra build plugin. Inside a shadow root the consumer must give Emotion a cache whose container is that shadow root, and scope the CSS variables and preflight to `:host`.
- **Panda CSS** (`@pandacss/dev` 2.5.0, same team, same syntax) is the build-time counterpart: it finds style objects by static analysis of the source and writes atomic classes inside `@media (width >= 48rem)` into a CSS file. A value known only at run time (state, a prop passed by the caller) gets no CSS unless pre-listed with `staticCss` or passed through a custom property. It needs the Panda compiler (CLI or PostCSS) in the consumer's build. Chakra UI 3 itself does not use Panda's compiler (derived from the Chakra source and dependencies).

### 2. Radix Themes (`@radix-ui/themes` 3.3.0)
- **Syntax.** A responsive prop takes a plain value or an object keyed by breakpoint: `p={{ initial: "2", md: "4" }}`. The docs show no array form. Breakpoints are fixed: `initial` 0, `xs` 520px, `sm` 768px, `md` 1024px, `lg` 1280px, `xl` 1640px. Only some props are responsive (those whose prop definition says so).
- **How it becomes CSS.** No CSS is generated at run time. The React component maps the object to class names: a token value gives `rt-r-p-2 md:rt-r-p-4`. A value outside the token list (for example `"13px"`) gives the bare class `rt-r-p md:rt-r-p` plus inline custom properties `--p: 13px; --p-md: …`.
- **The shipped CSS.** One static file, `styles.css`, holds every class for every token value at every breakpoint: `.rt-r-p-4 { padding: var(--space-4) }` and, inside `@media (min-width: 1024px)`, `.md\:rt-r-p-4 { … }`; plus `.md\:rt-r-p { padding: var(--p-md) }` for arbitrary values. The file is 812,667 bytes.
- **Build time vs run time.** The library's own build expands each rule into one copy per breakpoint (a PostCSS plugin that reads `@custom-media` breakpoint definitions). At run time only class names and inline custom properties are set.
- **Consumer build.** None beyond loading `styles.css` and React; no PostCSS or compiler is needed by the consumer.

### 3. Web component libraries with a value per breakpoint in an attribute
Four attribute shapes were found:

| Library | Attribute syntax | How the element turns it into style |
| --- | --- | --- |
| Ionic `ion-col` (9.0.11, Stencil) | One attribute per breakpoint: `size="12" size-md="6" size-lg="4"` | Script: on render it calls `window.matchMedia` for each breakpoint, takes the largest match, and writes `flex`, `width`, `max-width` into the host's inline `style`. It re-renders on every window `resize` event. Viewport only. |
| Carbon `cds-column` (`@carbon/web-components` 2.67.0, Lit) | One reflected attribute per breakpoint: `sm="2" md="4" lg="6"`, values `N`, `25%`, `span:N`, `start:S`, `end:E` | Static CSS: the library's Sass build enumerates every allowed value at every breakpoint as attribute selectors in the parent grid's shadow CSS (`:host(cds-grid) ::slotted(cds-column[md='4'])`) that extend Carbon's media-query classes. No script. The column renders in light DOM. |
| NVIDIA Elements (`@nvidia-elements/styles` 2.2.0) | One global attribute of space-separated tokens with a breakpoint prefix: `nve-layout="column pad:xs @lg|pad:xxl"`; `&lg|` for container queries | Static CSS: a PostCSS loop writes `@media (min-width: 1024px) { [nve-layout~='@lg|pad:xxl'] { padding: var(--nve-ref-space-xxl) } }` for every breakpoint and space token. For `&`, `*:has(> [nve-layout*='&'])` makes the parent a container. No script. |
| Shopify Polaris web components (CDN `polaris.js`) | One attribute with a small query language: `padding="@container (inline-size > 500px) large-400, small"`; several conditions, ranges, named containers | Script: the element parses the string at run time, maps scale tokens to CSS values, builds CSS text (`.cls{padding:…}@container (…){.cls{padding:…}}`) and renders it as a `<style>` element. Needs an `<s-query-container>` ancestor. |

A fifth shape follows from Lit's defaults (derived): a property declared `type: Object` takes JSON in its attribute, `p='{"base":"2","md":"4"}'`, which Lit turns into an object with `JSON.parse`. No library found uses this shape for responsive values.

### 4. Platform means for a custom element with no CSS-in-JS and no build step
Support is from @mdn/browser-compat-data 8.1.9, 2026-11-12.

- **Media queries with literal widths.** `@media (min-width: 48rem)` works everywhere, also in a shadow root's styles (where it still measures the viewport). Limit: the width must be written literally in each rule. `var()` is allowed only in property values, so `@media (min-width: var(--bp-md))` is invalid. `@custom-media` (a named breakpoint) exists only behind a flag in Firefox 148. So a breakpoint token reaches a media query only by being copied into the CSS text, by a build step or by script that writes CSS text (derived).
- **Container queries.** `@container` (Chrome 105, Firefox 110, Safari 16) measures the nearest ancestor with `container-type`, never the element itself. Rules apply to the container's flat-tree descendants, so a host with `:host { container-type: inline-size }` is a container for the elements in its own shadow root (derived from the spec sentence). The same literal-width limit applies to the condition. Container style queries, `@container style(--x: 4)`, test a custom property of an ancestor: Chrome 111, Firefox 151, Safari 18.
- **Attribute selectors.** `:host([p-md="4"])` inside `@media (min-width: …)` in the component's own styles lets CSS react to a host attribute with no script. `:host()` support starts at Chrome 54, Firefox 63, Safari 10. Limit: CSS cannot turn the text `4` into `var(--space-4)`, so each allowed token value at each breakpoint needs its own rule (as Carbon and NVIDIA do), or the attribute must hold a ready CSS value (derived).
- **`attr()`.** Modern `attr()` reads an attribute of the element the rule applies to, as a typed value: `padding: attr(p-md type(<length>), 0)`. Typed `attr()`: Chrome 133, Firefox 155, Safari 27.3. Limits: it yields a value, not a custom-property name, so it cannot pick `var(--space-4)` from the token name `4`. UNVERIFIED: a CSS function that builds a custom-property name from an attribute (`ident()`) is not in the browser data checked. URLs from `attr()` are blocked. Inside a shadow root, a `:host` rule applies to the host, so `attr()` there reads the host's attribute (derived from "reads the attribute of the selected element"; not tested).
- **`if()` with `media()`.** `padding: if(media(width >= 48rem): …; else: …)` picks a value per breakpoint inside one declaration. Chrome 137 and Safari 27.3; Firefox has none. It sets one property at a time. The width in `media()` is still a literal (derived: `var()` is only for values).
- **Adopted (constructable) style sheets.** Script can build CSS text, for example from the breakpoint tokens and an element's attributes, put it in `new CSSStyleSheet()` with `replaceSync`, and add it to `shadowRoot.adoptedStyleSheets` or `document.adoptedStyleSheets` (Chrome 73, Firefox 101, Safari 16.4). Lit already applies its `static styles` this way, evaluated once per class. A per-instance sheet or a `<style>` element per instance is the Polaris pattern. Lit warns that expressions inside a template `<style>` force a full re-parse on each change.
- **The `style` attribute.** It holds only declarations, never `@media` or `@container`. It can carry per-breakpoint custom properties (`--p: …; --p-md: …`) that a static rule in a media query reads (`@media (…) { :host { padding: var(--p-md, var(--p)) } }`), as Radix does for arbitrary values. In Lit this is `styleMap` or `this.style.setProperty`. Mapping a token name to `var(--space-4)` happens in script.
- **`matchMedia` in script.** `window.matchMedia(query).matches` with the `change` event (Chrome 39, Firefox 55, Safari 14) lets script choose the active value and write it as inline style, as Ionic does (Ionic listens to `resize` instead). Viewport only; the container-width equivalent is `ResizeObserver` (Chrome 64, Firefox 69, Safari 13.1). Before the element's script runs (before `define()`), there is no style (derived).

### 5. Each mechanism against the three entry points
"Object prop" means a React prop such as `p={{ base: "2", md: "4" }}`. React 19 sets a property on a custom element when that property name exists on the element, and otherwise sets a string attribute (an object becomes `"[object Object]"`). Lit reactive properties are defined on the class, so a Lit property named `p` is visible to that check (derived; not tested).

| Mechanism | From a plain HTML attribute | From a React object prop | Inside a shadow root |
| --- | --- | --- | --- |
| Runtime CSS generation into a style sheet (Chakra/Emotion, Polaris) | Yes, if the element parses the attribute (Polaris). Chakra itself is React-only. | Yes. | Yes, if rules go into the shadow root (an adopted sheet or `<style>` there); Chakra needs a cache with the shadow root as container. |
| Static CSS, one class or attribute selector per token × breakpoint (Radix, Carbon, NVIDIA) | Yes, with attribute selectors (Carbon, NVIDIA); Radix uses classes set by React. | Yes, if script or a wrapper turns the object into attributes or classes. | Yes, through `:host([…])`; for slotted children only top-level `::slotted([…])`. |
| Static CSS reading per-breakpoint custom properties from inline style (Radix arbitrary values) | Yes, with script mapping the attribute to `--p-md`. | Yes. | Yes; custom properties set on the host are inherited into the shadow tree. |
| Typed `attr()`, alone or in `if(media())` | Yes, no script, but only for values that are already CSS values; not in Firefox (`if()`), typed `attr()` needs Firefox 155 / Safari 27.3. | Only if the object is first turned into attributes. | Reads the host's attributes from `:host` rules (derived). |
| `matchMedia` / `ResizeObserver` in script writing inline style (Ionic) | Yes. | Yes. | Yes (host inline style or inner elements). |
| Container queries (Polaris, NVIDIA `&`) | Yes, as the condition inside any of the above. | Yes. | Yes; the host can be the container for its shadow content. |

## Findings
- Chakra UI 3 is a mobile-first system with `min-width` media queries; default breakpoints `base` 0rem, `sm` 30rem, `md` 48rem, `lg` 62rem, `xl` 80rem, `2xl` 96rem. A responsive value is an object (`fontWeight={{ base: "medium", lg: "bold" }}`) or an array in breakpoint order (`fontWeight={["medium", undefined, undefined, "bold"]}`, `undefined` skips a breakpoint); keys `mdToXl`, `lgOnly`, `smDown` target ranges; `hideFrom` / `hideBelow` hide by breakpoint. Source: https://chakra-ui.com/docs/styling/responsive-design, checked 2026-11-12.
- The current `@chakra-ui/react` release is 3.38.0 (published 2026-11-03); its peer dependencies are `react >=18`, `react-dom >=18` and `@emotion/react >=11`, and it depends on `@emotion/serialize`, `@emotion/utils` and `@emotion/use-insertion-effect-with-fallbacks`. Source: https://registry.npmjs.org/@chakra-ui/react, checked 2026-11-12.
- Chakra UI 3 install for Vite: `npm i @chakra-ui/react @emotion/react`, a root `Provider` that composes `ChakraProvider`; the guide names no Chakra-specific build plugin. Source: https://chakra-ui.com/docs/get-started/frameworks/vite, checked 2026-11-12.
- Chakra's `normalizeValue` turns an array value into an object keyed by the breakpoint names in order, dropping `null`/`undefined` entries. Source: https://raw.githubusercontent.com/chakra-ui/chakra-ui/4d3fda5dfd956188786a641ba47ec49dbe7dce93/packages/react/src/styled-system/system.ts lines 100-112, checked 2026-11-12.
- Chakra's breakpoint conditions are built as strings `@media screen and (min-width: <min>)`, with `<name>Down`, `<name>Only` and `<min>To<Max>` adding `max-width` set 0.04px below the next breakpoint, in rem. Source: https://raw.githubusercontent.com/chakra-ui/chakra-ui/4d3fda5dfd956188786a641ba47ec49dbe7dce93/packages/react/src/styled-system/breakpoints.ts lines 21-52 and 133-148, checked 2026-11-12.
- Chakra's `css()` function walks the normalized style object, resolves each condition key (a breakpoint key becomes its media query), transforms each property and token value, and nests the result under the at-rules, returning a style object. Source: https://raw.githubusercontent.com/chakra-ui/chakra-ui/4d3fda5dfd956188786a641ba47ec49dbe7dce93/packages/react/src/styled-system/css.ts lines 30-65, checked 2026-11-12.
- Chakra's `chakra` factory (forked from Emotion's `styled`) resolves style props in render (`useResolvedProps`), serializes them with Emotion's `serializeStyles`, adds the class `<cache.key>-<hash>`, and inserts the CSS rules with Emotion's `insertStyles` inside `useInsertionEffect`; so the CSS for a responsive value is generated in the browser at render time. Source: https://raw.githubusercontent.com/chakra-ui/chakra-ui/4d3fda5dfd956188786a641ba47ec49dbe7dce93/packages/react/src/styled-system/factory.tsx lines 1-70 and 150-200, checked 2026-11-12.
- Chakra UI 3 in a shadow root needs `@emotion/cache` with `container: shadow.shadowRoot` given through `CacheProvider`, `cssVarsRoot: ":host"`, preflight scoped to `:host`, and `EnvironmentProvider`. Source: https://chakra-ui.com/docs/get-started/environments/shadow-dom, checked 2026-11-12.
- Panda CSS (current `@pandacss/dev` 2.5.0, from the Chakra team) has the same object and array responsive syntax and `mdToXl` / `lgOnly` keys, mobile-first with `min-width`; default breakpoints `sm` 640px to `2xl` 1536px, set in `panda.config.ts`. Source: https://panda-css.com/docs/styling/responsive-design (page updated 2026-11-02) and https://registry.npmjs.org/@pandacss/dev/latest, checked 2026-11-12.
- Panda extracts styles by static analysis at build time; a value known only at run time (React state, a prop passed by the caller) produces no CSS unless pre-generated with `staticCss` or routed through a CSS custom property set in `style`; when a condition is not static, Panda generates CSS for every branch; generated output is atomic classes such as `@media (width >= 48rem) { .hover\:md\:text_red\.400:… }` in `@layer utilities`. Source: https://panda-css.com/docs/styling/dynamic-styling (page updated 2026-11-02), checked 2026-11-12.
- Radix Themes breakpoints are fixed `min-width` widths: `initial` 0px, `xs` 520px, `sm` 768px, `md` 1024px, `lg` 1280px, `xl` 1640px; most size and layout props take a `Responsive` object such as `size={{ initial: "3", md: "5", xl: "7" }}`. The docs show object syntax only. Source: https://www.radix-ui.com/themes/docs/theme/breakpoints, checked 2026-11-12.

- `@custom-media` (a named media query, the CSS way to define a breakpoint once) is supported only in Firefox 148 behind a flag; Chrome, Edge and Safari have no support; it is marked experimental. Source: @mdn/browser-compat-data 8.1.9 (`css.at-rules.custom-media`, data timestamp 2026-11-12), checked 2026-11-12.
- `@media` range syntax (`width >= 48rem`) is supported from Chrome/Edge 104, Firefox 102, Safari 16.4. Source: @mdn/browser-compat-data 8.1.9 `css.at-rules.media.range_syntax` (data timestamp 2026-11-12), checked 2026-11-12.
- Size container queries (`@container`, `container-type`) are supported from Chrome/Edge 105, Firefox 110, Safari 16; container style queries for custom properties (`@container style(--x: v)`) from Chrome/Edge 111, Firefox 151, Safari 18. Source: @mdn/browser-compat-data 8.1.9 `css.at-rules.container` and `.style_queries_for_custom_properties`, checked 2026-11-12.
- `if()` is supported in Chrome/Edge 137 and Safari 27.3, not in Firefox; `if()` with `style()` tests only in Chrome/Edge 137. Source: @mdn/browser-compat-data 8.1.9 `css.types.if`, checked 2026-11-12.
- `attr()` with a fallback and any declaration value is supported from Chrome/Edge 133, Firefox 119, Safari 18.4; typed `attr()` with `type()` or units from Chrome/Edge 133, Firefox 155, Safari 27.3; classic string `attr()` in all browsers. Source: @mdn/browser-compat-data 8.1.9 `css.types.attr` and subfeatures, checked 2026-11-12.
- Constructable style sheets (`new CSSStyleSheet()`, `replaceSync`, `Document.adoptedStyleSheets`, `ShadowRoot.adoptedStyleSheets`) are supported from Chrome 73, Edge 79, Firefox 101, Safari 16.4; `CSSStyleSheet.insertRule`, `HTMLElement.style` and `CSSStyleDeclaration.setProperty` in all browsers. Source: @mdn/browser-compat-data 8.1.9 `api.CSSStyleSheet`, `api.Document.adoptedStyleSheets`, `api.ShadowRoot.adoptedStyleSheets`, `api.HTMLElement.style`, checked 2026-11-12.

Source: @mdn/browser-compat-data 8.1.9 `api.Window.matchMedia`, `api.MediaQueryList.change_event`, `api.ResizeObserver`, checked 2026-11-12.
- `:host` is supported from Chrome 54, Edge 79, Firefox 63, Safari 10; `::slotted` from Chrome 50, Firefox 63, Safari 10; `:has()` from Chrome 105, Firefox 121, Safari 15.4; attribute selectors in all browsers; custom properties from Chrome 49, Edge 15, Firefox 31, Safari 9.1; `@property` from Chrome 85, Firefox 128, Safari 16.4. Source: @mdn/browser-compat-data 8.1.9 `css.selectors.*`, `css.properties.custom-property`, `css.at-rules.property`, checked 2026-11-12.
- `if()` takes a style query, a media query (`media(...)`) or a feature query, and "can be used inside the value of any property"; MDN notes that to set several declarations or rules on one media query "a regular @media construct is needed", and that container style queries test only custom properties. Source: https://developer.mozilla.org/en-US/docs/Web/CSS/Reference/Values/if, checked 2026-11-12.
- Modern `attr()` syntax is `attr(<attr-name> <attr-type>? , <fallback>?)` with `type(<length>)`, a unit such as `px`/`rem`, or `raw-string`; it reads the attribute of the selected element; `<url>` is not allowed and attr()-tainted values in URLs are invalid at computed-value time; feature test `@supports (x: attr(x type(*)))`. Source: https://developer.mozilla.org/en-US/docs/Web/CSS/Reference/Values/attr, checked 2026-11-12.
- The `style` attribute's value is a declaration list only (`declaration-list : S* declaration? [ ';' S* declaration? ]*`), with no selectors or at-rules, so an inline style cannot hold a media query. Source: https://www.w3.org/TR/css-style-attr/ (W3C Recommendation, 7 November 2013) section 3, checked 2026-11-12.
- An element's size container is "the nearest ancestor with containment", declared with `container-type: size | inline-size`; style queries for custom properties query "the custom properties … of a parent element". Source: https://developer.mozilla.org/en-US/docs/Web/CSS/Guides/Containment/Container_size_and_style_queries, checked 2026-11-12.
- Container query rules apply to a query container's flat-tree descendants; for `::part()` and `::slotted()` the query containers are the flat-tree ancestors of those elements. Source: https://drafts.csswg.org/css-conditional-5/ (Editor's Draft, 10 November 2026), checked 2026-11-12.
- Lit's default attribute converter: for `type: Object` or `Array`, an attribute value becomes `JSON.parse(attributeValue)`, and a reflected value becomes `JSON.stringify(value)`; custom converters take `fromAttribute(value, type)` / `toAttribute(value, type)`; the docs say reflecting properties of type object or array is not recommended. Source: https://lit.dev/docs/components/properties/, checked 2026-11-12.
- Lit `static styles` are evaluated once per class; the `css` tag only accepts nested `css` literals or numbers, and `unsafeCSS()` wraps a trusted string; `:host(selector)` styles the host only when it matches `selector`; expressions inside a `<style>` element in the template make the browser re-parse the whole element ("extremely inefficient"); `styleMap` and `classMap` set per-instance styles and classes. Source: https://lit.dev/docs/components/styles/, checked 2026-11-12.
- Lit applies static styles to a shadow root with `adoptedStyleSheets` when the browser supports it, and otherwise appends `<style>` elements. Source: https://raw.githubusercontent.com/lit/lit/b17fb14470c69a68205c10b69451883da07f4dde/packages/reactive-element/src/css-tag.ts lines 14-19 and 164-176, checked 2026-11-12.
- React passes JSX values to a custom element as attributes by default, serializing non-strings (`[1,2,3]` becomes `"1,2,3"`), but passes arbitrary values as properties when "the property name shows up on the class during construction". Source: https://react.dev/reference/react-dom/components#custom-html-elements, checked 2026-11-12.
