# RES-046: How a Figma library and a Figma plugin give components to designers

## Question
How do a published Figma library and a custom Figma plugin each give components to designers, and how does each stay in sync with new versions? How do the designers of an outside team, who are not members of the owning Figma team, get the components by each route, and what does each route need on Figma's Professional plan?

## Answer
Sufficient answer: for each route (published team library, Community file, custom plugin, and any other route that Figma documents): how a designer inside the team and a designer of an outside team get the components; how a new version reaches files that already use them, and what the designer must do; what the route needs on the Professional plan (plan, seats, publishing rights, review by Figma) and what it cannot do there; how variables and their modes travel with the components. Each fact has its source and date. The record names the limits and the points where sources disagree. It gives no choice, recommendation or ranking; IDEA-002#07 owns the choice.

The condition is met from Figma's documentation, read on 2026-11-12. No Figma call was made. Plan, seat and price facts are in RES-024 and are cited here, not repeated. Two points stay open because the documentation does not settle them; they are under "What remains unknown".

### Routes at a glance

| Route | Designer in "ACME Labs" | Designer of an outside team | How a new version arrives | Needs on Professional | Cannot do on Professional |
| --- | --- | --- | --- | --- | --- |
| Published team library | Adds the library to a file from the Assets tab, or the team admin makes it a default library for all team files | Gets at least `can view` access to the library file, then adds the library to a file where the designer can edit | Each file shows a badge; a person with edit access reviews and clicks Update or Update all. Nothing updates without that click | Library file in a folder, not in drafts; edit access to publish; RES-024: Full seat to edit Design files, View seat is free | Choose a publish destination (team or organization); organization-wide libraries; extended variable collections |
| Connected folder (a library route for one outside team) | Not applicable | The outside team works in a shared folder of "ACME Labs"; a host admin allows chosen libraries there, which gives view-only access to the library files | Same as the team library | Both parties on a paid plan; admins of both approve; at most 3 connected folders on Professional; different business domains | More than 3 connected folders; features beyond the host's Professional plan |
| Community file | Duplicates the file into drafts | Same: duplicates the file into drafts on any plan | Never into existing copies. The designer duplicates the new version and moves the work to it by hand or with Swap libraries | Any plan; edit access to publish; Figma names a review for paid files only | Push updates to copies |
| Custom plugin, published to the Community | Installs it from the Community page | Same | New plugin code reaches every user at once, with no action. Components that the plugin made earlier in a file do not change (see "Plugins") | Any plan; desktop app; two-factor authentication; Figma review before the first listing only | Private plugin for the team (needs Organization or Enterprise, RES-024) |
| Custom plugin in development (no publishing) | Imports the plugin from its `manifest.json` on the desktop app | Same, if given the source files | Only when the person imports new source files | Any plan; desktop app | Listing, review, automatic updates |
| UI kits | Not applicable | Not applicable | Updates are offered like a library | Not applicable | Only Figma and partners make UI kits; there are seven |

### Published team library
- Inside the team: a published library can be added to any file where a person has `can edit` access. A team admin can enable it for all files of the team. Instances keep a link to the main component in the library file.
- Outside team: Figma says "anyone with access to the library's source file can use the library in their files", and a person needs "at least `can view` access to the library". On Professional, a person who is invited only to a file or folder is a "limited access member" of the plan. Viewing needs no paid seat (RES-024). The outside designer edits the using file with a seat in that file's own plan.
- New versions: the author publishes again with a description. Each file that uses the library shows a blue badge. A person with edit access reviews side by side or as an overlay, then updates each instance or all of them. The documentation names no automatic acceptance on any plan.
- Variables and modes: variables and their collections are published with the library. A designer applies them in another file and switches the mode on a frame, group, component or section. Page-level mode switching is documented for local collections only. Professional allows up to 10 modes for each collection (RES-024). Extended collections, which let a brand override a parent collection and still receive its updates, need Enterprise, Government or Education (K-12). On Professional, a brand theme therefore has to be another mode in the same collection, another collection, or a separate library.
- Limits: Starter cannot publish a library. Removing a library from a file leaves the used assets on the canvas. Unpublishing, deleting or moving the library to a team that the user cannot reach disconnects the instances; Swap libraries can then match assets by name only.

### Connected folder
Figma documents this as the way for two plans (for example an agency and a client) to work in one folder, each with seats from its own plan. The host's plan sets the features in the folder, including the number of variable modes. The host admin chooses which of the host's libraries the folder may use. Both parties need a paid plan; Professional allows 3 connected folders.

### Community file
Publishing adds a snapshot to the Figma Community. Anyone with an account on any plan duplicates it into drafts. Changes to the original never reach a duplicate; the designer duplicates the new version. To use a duplicate as a library, a designer would move it into a folder and publish it from a paid plan; Swap libraries can then move a file to a newer library when the assets have the same names. UNVERIFIED: whether variable modes in a duplicate survive in a Starter draft, where modes are not included (RES-024). No page states it.

### Plugins
- A classic plugin is free to build and publish. A generative plugin costs AI credits to build. On Professional, either kind can be published only to the Community, after Figma's review. After the first approval, updates publish at once without review, every installed user gets the latest version, and users cannot go back to an older version.
- A plugin can create components and variables in the open file through the Plugin API, including collections and modes. A component or variable made in a file "is only accessible from that file" until it is published as a library. The documentation names no mechanism that updates components a plugin made earlier when the plugin changes. Any such update would have to be written into the plugin and run again by the designer in each file. This last sentence is a conclusion from the findings, not a documented feature.
- A plugin can also insert instances of published library components and variables by key (`importComponentByKeyAsync`, `importVariableByKeyAsync`), and list the variable collections of libraries already enabled in the file (`figma.teamLibrary`, which needs the `teamlibrary` permission). It cannot enable a library. Instances inserted this way are library instances and update as in the library route. This route therefore needs the published library as well.
- A plugin can call external domains that its manifest lists under `networkAccess`; the Community page shows the list.
- Running a plugin in Figma Design needs edit access to the file and, on a paid plan, a Full seat (RES-024).

### Disagreements between sources
- Libraries in drafts: "Enable access to libraries in your drafts" says "All plans" and lets drafts use "styles and components from published libraries in any Professional and Education teams", but limits this to "teams of which you're a member". "Add or remove a library from a design file" lists paid plans only. The drafts article does not name variables.
- Outside access: "Publish a library" says anyone with access to the source file can use the library. The Libraries modal's browse tabs list libraries "in teams you belong to"; it also has a search by name. No page says whether a limited access member finds the library by search, by link or not at all.
- Extended collections: RES-024 records them as Enterprise. "Extend a variable collection" lists Education (K-12), Government and Enterprise.
- Mode limit on Professional: RES-024 records 10 from Figma's plan pages; RES-023 records 4 from the files of the Figma plugin for Claude Code.

### What remains unknown
- Whether a designer of another Professional team, invited with `can view` to the library file of "ACME Labs" and not a full member, can add that library to a file in the designer's own team, and how the designer finds it. The documentation implies yes and does not show the steps. A live test with two accounts would settle it; this research made no Figma call.
- Whether a plugin's `importComponentByKeyAsync` needs the user to have access to the library file. The reference says only that it loads "from the team library" and fails when no published component has the key.
- Whether a file of a Starter team or a Starter draft can use a library from a Professional team, beyond the drafts article quoted above.

## Findings

### Published library: publishing and use
- Libraries need a Professional, Education, Organization, Government or Enterprise plan. A library is a collection of components, styles and variables that live in one file and can be reused in other files. Source: https://help.figma.com/hc/en-us/articles/360041051154-Guide-to-libraries-in-Figma, checked 2026-11-12, last-modified: 2026-11-12.
- A style, component or variable is at first "only accessible from that file"; to use it in other files it must be published as a library. Starter "can't publish them in a library". The file must hold at least one component, style or variable and must be in a folder, not in drafts. "Once published, anyone with access to the library's source file can use the library in their files". Source: https://help.figma.com/hc/en-us/articles/360025508373-Publish-a-library#h_01J688PTA7SPRDKBNDJ5RYVSP4, checked 2026-11-12, last-modified: 2026-11-08.
- Only Organization and Enterprise can choose where to publish a library; Enterprise can also publish to workspaces. Source: https://help.figma.com/hc/en-us/articles/360025508373-Publish-a-library#h_01J688PTA7N7AHMGZMA6QA1F1V, checked 2026-11-12.
- Changes in the library file appear only in that file until they are published. Each publish asks for a description, which Figma shows when people accept updates and in version history. Users see a blue badge on the Libraries icon. Source: https://help.figma.com/hc/en-us/articles/360025508373-Publish-a-library#h_01J688PTA7V9DE1KSKQXAMNXRZ, checked 2026-11-12.
- A person can use published libraries in any draft or team file where the person has `can edit` access. Admins can set default libraries for a team. "Anyone with can edit access to a file can review and accept or ignore the changes". Source: https://help.figma.com/hc/en-us/articles/360041051154-Guide-to-libraries-in-Figma#h_01HHN9HHAQWSTMV90EK92EFSQR, checked 2026-11-12.
- Adding a library to a file needs a paid plan and edit access to the file and applies to everyone with access to that file. "Users need at least can view access to the library." The Libraries modal browses Recommended, "Teams / Your teams: Browse libraries in teams you belong to", the organization, and UI kits, and has a search by name. Removing a library leaves used assets on the canvas. Source: https://help.figma.com/hc/en-us/articles/1500008731201-Add-or-remove-a-library-from-a-design-file, checked 2026-11-12, last-modified: 2026-10-28.
- On Professional and higher plans, a team admin can make a library available in all team files of chosen types (Design, FigJam, Slides, Buzz). On Enterprise, an admin can set a default mode for the team when a library collection has at least two modes. Source: https://help.figma.com/hc/en-us/articles/360039234953-Enable-a-library-for-a-team, checked 2026-11-12, last-modified: 2026-11-11.
- Libraries in drafts (all plans): "you can access style and component libraries from any teams of which you're a member". In drafts a person can enable "styles from published libraries in your drafts or Starter teams" and "styles and components from published libraries in any Professional and Education teams". The article does not name variables. Source: https://help.figma.com/hc/en-us/articles/360038743434-Enable-access-to-libraries-in-your-drafts, checked 2026-11-12, last-modified: 2026-10-26.

### Published library: updates
- When a main component, style or variable is updated in a library, "Figma makes the updates available in every file where the component, style, or variable is used." The feature needs a paid plan and edit access to the file. Source: https://help.figma.com/hc/en-us/articles/360039234193-Review-and-accept-library-updates, checked 2026-11-12, last-modified: 2026-10-27.
- The person opens "Review library updates", sees updates for the current page or all pages, and clicks Update for one asset or Update all. A selected instance shows "Update available" with "Update selected instance" or "Review update". Review shows side by side or as an overlay, instance by instance. Source: https://help.figma.com/hc/en-us/articles/360039234193-Review-and-accept-library-updates#h_01J9SJMQRTE8CXHS8MA3BTFT4M, checked 2026-11-12.
- Swap libraries replaces styles, instances and variables in a file with those of another published library, matched by name only, including to "use a different or newer version of a library" and to "swap to external or agency-provided libraries". It needs a paid plan, edit access to the file and at least view access to both libraries; both must be published. Unmatched assets stay linked to the old library. Source: https://help.figma.com/hc/en-us/articles/4404856784663-Swap-libraries, checked 2026-11-12, last-modified: 2026-10-28.
- Styles and instances are disconnected when the library file is unpublished, deprecated "or moved to a team you can't access". Source: https://help.figma.com/hc/en-us/articles/4404856784663-Swap-libraries#h_01KGG90QGY4E5FA0SM4N03Z5B4, checked 2026-11-12.
- Published components can be moved to another library file without breaking instance links; main components and instances copied between files otherwise keep their connection only "as long as they remain in the same file". Source: https://help.figma.com/hc/en-us/articles/4404848314647-Move-published-components, checked 2026-11-12, last-modified: 2026-11-05.
- A file saved to a computer and imported into another account "won't receive any library updates" if it uses team library styles or components. Source: https://help.figma.com/hc/en-us/articles/21051216849175-Guide-to-collaborating-with-clients-in-Figma#h_01HNK2AB624BS8V4YYDPW6QBV6, checked 2026-11-12, last-modified: 2026-08-03.

### Published library: variables and modes
- Variables "can also be published to team libraries"; an update to a variable value can update designs across files. Source: https://help.figma.com/hc/en-us/articles/14506821864087-Overview-of-variables-collections-and-modes, checked 2026-11-12.
- Publishing variables to team libraries needs Professional, Education, Organization, Government or Enterprise. Source: https://help.figma.com/hc/en-us/articles/15339657135383-Guide-to-variables-in-Figma, checked 2026-11-12, last-modified: 2026-11-12.
- A person can apply "variables from any published team library to which you have access". Source: https://help.figma.com/hc/en-us/articles/15343107263511-Apply-variables-to-designs, checked 2026-11-12, last-modified: 2026-11-12.
- Modes can be switched on frames, groups, components, component sets and sections when nested layers use a variable with several modes. Modes can be switched on pages "if any local collection of variables contains multiple modes". An object uses the default mode until a mode is set. String, number and boolean variables can switch variants of an instance by mode. Source: https://help.figma.com/hc/en-us/articles/15343816063383-Modes-for-variables#h_01H3ADKDF7JBTRV1Z5P1X1DZVE, checked 2026-11-12, last-modified: 2026-11-11.
- Extended collections let a design system author extend a parent collection for each brand; an extended collection inherits updates to variables it has not overridden. It cannot add variables or modes. The feature lists Education (K-12), Government and Enterprise plans. Source: https://help.figma.com/hc/en-us/articles/36346281624471-Extend-a-variable-collection, checked 2026-11-12, last-modified: 2026-11-03.

### Outside teams: accounts, sharing and connected folders
- On Starter and Professional, people are full members or "limited access members", who are "only directly invited to specific folders or files". Full members are included when something is shared with "Anyone in [plan]"; a full member can invite others to the team only with a View seat. Source: https://help.figma.com/hc/en-us/articles/4420557314967-Members-guests-and-limited-access#h_01KYSRVE25A83MYZ9ECF7SNERX, checked 2026-11-12, last-modified: 2026-11-05.
- On Organization and Enterprise, a guest can use organization-wide libraries only "if invited to source file", and cannot use private plugins. Source: https://help.figma.com/hc/en-us/articles/4420557314967-Members-guests-and-limited-access#h_01KYSRYG7X1W3SMY48AEEAJMW1, checked 2026-11-12.
- Any file can be shared by link or by email invitation, with audience "Anyone" (also outside the organization) or "Only invited people", and with view or edit rights. Source: https://help.figma.com/hc/en-us/articles/360040531773-Share-files-and-prototypes#h_01K6P3NP6T8BQHJPS75DJ05TMG, checked 2026-11-12, last-modified: 2026-11-12.
- Editing a file needs both `can edit` permission and a seat that includes the product. Source: https://help.figma.com/hc/en-us/articles/1500007609322-Guide-to-sharing-and-permissions#h_01K6P8WKVZEBENK20JNX32YR95, checked 2026-11-12.
- Figma's client guide gives a free View seat to clients who only comment; clients who edit "will need a paid seat on your team". Source: https://help.figma.com/hc/en-us/articles/21051216849175-Guide-to-collaborating-with-clients-in-Figma#h_01HNK2AB624BS8V4YYDPW6QBV6, checked 2026-11-12.
- Connected folders let two teams or organizations work in one shared folder "using billable seats from their own plans". They are for Professional, Organization, Government and Enterprise "for both parties", are set up by admins, and need approval from both. Source: https://help.figma.com/hc/en-us/articles/30124855491863-Guide-to-connected-folders, checked 2026-11-12, last-modified: 2026-11-10.
- Only the host admin can "allow people from the external team to use the host's libraries". "The host's plan determines which features are available", including "the number of variable modes". Source: https://help.figma.com/hc/en-us/articles/30124855491863-Guide-to-connected-folders#h_01JMJDKJFD8C3M4MDEVKBHAFEQ, checked 2026-11-12.
- "Host admins can curate which of the host's libraries are available to use in the connected folders. Allowing access to a library grants members of the connected folder view-only access to the library's source file". Source: https://help.figma.com/hc/en-us/articles/30124855491863-Guide-to-connected-folders#h_01JMJDKJFE31AZHCQ2J0P3F15G, checked 2026-11-12.
- In a connected folder, people use the seat of their own plan; the host is not billed for the external team. An external user who edits files outside the connected folder needs a seat on the host's plan. Source: https://help.figma.com/hc/en-us/articles/30124855491863-Guide-to-connected-folders#h_01KYW9VQ570H0JP76PE6CJ1YQB, checked 2026-11-12.
- Professional can have 3 connected folders, Organization 6, Enterprise 15, counting folders as host or external team and pending invites. One folder has one host and one external team. Host and external team must use different business domains. Source: https://help.figma.com/hc/en-us/articles/30124855491863-Guide-to-connected-folders#h_01M5X964WGMZEAZYZXE1Y20HHY, checked 2026-11-12.

### Community files and UI kits
- Publishing a file to the Community is available on Starter, Professional, Education, Organization and Enterprise with edit access. Figma adds "a snapshot" of the file. A duplicate is a new copy "without any updates, version history or comments from the original file". Source: https://help.figma.com/hc/en-us/articles/360040035974-Publish-files-to-the-Figma-Community, checked 2026-11-12, last-modified: 2026-10-22.
- An update to a Community file is "a new version of the file" and Figma "won't update any existing duplicates"; members must duplicate the new version. For a file on a team profile, only a team admin can publish updates. Paid files are reviewed by Figma's content team; the article names no review for free files. Source: https://help.figma.com/hc/en-us/articles/360040035974-Publish-files-to-the-Figma-Community#01H8CZTYDFWHZ6GMJT4YK2RMP4, checked 2026-11-12.
- Duplicating a Community file needs a Figma account on any plan and puts the copy in the person's drafts. "Changes made to the original file are not reflected in duplicated files". Source: https://help.figma.com/hc/en-us/articles/360038510873-Duplicate-Community-files, checked 2026-11-12, last-modified: 2026-11-09.
- A file published to a team's Community profile cannot then move to another team. Source: https://help.figma.com/hc/en-us/articles/360041423614-Community-publishing-permissions#team, checked 2026-11-12, last-modified: 2026-11-03.
- UI kits are libraries "curated by Figma and partners"; seven exist. "Unlike other Community resources, updates to UI kits are automatically available in your design files where you have the option to accept the updates." A copy of a UI kit receives no updates. Source: https://help.figma.com/hc/en-us/articles/24037724065943-Start-designing-with-UI-kits, checked 2026-11-12, last-modified: 2026-11-09.

### Plugins
- Creating a classic plugin for development is available on all plans in the desktop app; "Import new plugin from manifest..." adds a plugin whose source code is on the computer, and it is listed under Development. Source: https://help.figma.com/hc/en-us/articles/360042786733-Create-a-classic-plugin-for-development, checked 2026-11-12, last-modified: 2026-10-28.
- Publishing a classic plugin to the Community is available on Starter, Professional, Education, Organization and Enterprise. It needs the desktop app, a development plugin and two-factor authentication. Figma reviews it before listing; approval times vary. The "Publish to" choice of Organization or Community is on Organization and Enterprise only, and private organization plugins are not reviewed. Source: https://help.figma.com/hc/en-us/articles/360042293394-Publish-classic-plugins-to-the-Figma-Community#h_01HA2DQNF7RHF9B05B0SKA64C2, checked 2026-11-12, last-modified: 2026-11-03.
- The optional data-security disclosure is reviewed by Figma, which "may take up to two weeks". Source: https://help.figma.com/hc/en-us/articles/360042293394-Publish-classic-plugins-to-the-Figma-Community#h_01HA2DQNF7CMZW2Q5T6H7DSZX0, checked 2026-11-12.
- "Once Figma approves your plugin, you don't need to submit your plugin for further review." A new version updates the plugin "for every user"; installed users "will only have access to the latest version" and cannot revert. Unpublishing removes the plugin for everyone without notice. Source: https://help.figma.com/hc/en-us/articles/360042293714-Manage-classic-plugins-as-a-developer#h_01HA2WGKG50XJJX7BE3SN28FH3, checked 2026-11-12, last-modified: 2026-10-23.
- Generative plugins are built by prompting the Figma agent on Starter, Professional, Education (not K-12), Organization and Enterprise, and can be published to the Community after review; private publishing is for organizations. Source: https://help.figma.com/hc/en-us/articles/43029200314135-Publish-generative-plugins-to-the-Figma-Community, checked 2026-11-12, last-modified: 2026-11-03.
- Generative plugins: after approval, updates publish immediately for every user, and users cannot revert. Source: https://help.figma.com/hc/en-us/articles/43029048128023-Manage-generative-plugins-as-a-creator, checked 2026-11-12, last-modified: 2026-11-03.
- Classic plugins support third-party API calls and are free to build and publish; generative plugins do not support third-party API calls and cost AI credits to build. Both: "Private plugins for Org; Publishable to Community". Source: https://help.figma.com/hc/en-us/articles/41407987481879-About-building-plugins-in-Figma, checked 2026-11-12, last-modified: 2026-11-05.
- `figma.importComponentByKeyAsync`, `importComponentSetByKeyAsync`, `importStyleByKeyAsync` and `importVariableByKeyAsync` load a component, component set, style or variable "from the team library" and reject when no published item has the key. Source: https://developers.figma.com/docs/plugins/api/figma/, checked 2026-11-12.
- `figma.teamLibrary` works with libraries enabled for the current file; "it is not possible to enable libraries via the Plugin API". The manifest must list the `teamlibrary` permission. Source: https://developers.figma.com/docs/plugins/api/figma-teamlibrary/, checked 2026-11-12.
- The Plugin API creates variable collections, adds modes and sets values for each mode (`createVariableCollection`, `addMode`, `setValueForMode`), and can extend a library collection with `extendLibraryCollectionByKeyAsync`, which is "limited to the Enterprise plan". Source: https://developers.figma.com/docs/plugins/working-with-variables/, checked 2026-11-12.
- A plugin's manifest sets `networkAccess.allowedDomains`; the list is shown on the plugin's Community page. Source: https://developers.figma.com/docs/plugins/manifest/, checked 2026-11-12.
