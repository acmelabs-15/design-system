# RES-030: How libraries ship MCP servers and agent skills, and how agent hosts find them

<!-- Add outcome: answered, partial or blocked to frontmatter when an answer or a block is known. Only answered work can become resolved. -->

## Question
How do other libraries ship MCP servers and agent skills (inside the library package or apart), how do they install them into a consumer project, and how do agent hosts find them?

## Answer
Partly answered. The sweep of 2026-11-12 established where Ant Design, shadcn/ui, Chakra UI, MUI, Nuxt UI, Storybook and TanStack Intent ship their MCP servers and skills, how each installs them, which host files the installs write, how each keeps versions in step, and what the Agent Skills format requires. The sufficient-answer condition is not met; see "Still open".

Needed by: IDEA-005#03 (the `init` trial), IDEA-005#04 (inside the package or separate packages) and IDEA-005#09 (guidance for an agent with no project).

Sufficient-answer condition:

- Named libraries and tools, each with where its MCP server and its skills ship: inside the library package, in a separate package, or on a hosted server.
- How each installs them into a consumer project, and which files the install writes.
- How each agent host finds MCP servers and skills.
- How each keeps the server and the skills in step with the installed library version.
- Both sides of each disagreement between sources.

The record gives facts, sources and disagreements only. It gives no recommendation.

### What the run established
The summary of the run's report, in its own words:

> As of November 2026, the libraries checked ship MCP servers and agent skills in four ways. 1. A separate npm package run through npx: MUI uses @mui/mcp, Chakra UI uses @chakra-ui/react-mcp and Ant Design uses @ant-design/cli. 2. A subcommand of the library's existing CLI: shadcn runs `shadcn mcp`. 3. A hosted HTTP server: Nuxt UI runs one at ui.nuxt.com/mcp, and Chromatic can host a published Storybook MCP. 4. A dev-server addon released together with the library: Storybook's @storybook/addon-mcp. Agent skills come either from GitHub through the third-party skills CLI (Nuxt UI and Chakra UI) or inside the library's own npm package (the TanStack Intent model). Installation ranges from fully manual edits to each agent host's config (MUI, Chakra UI and Nuxt UI) to an init or setup command that writes project files for named clients: `shadcn mcp init --client ...` and `antd setup --client claude|cursor|vscode|codex --mode mcp|skill|both`. Storybook uses the third-party mcp-add CLI. The config files named are .mcp.json (Claude Code), .cursor/mcp.json, .vscode/mcp.json (under a `servers` key), ~/.codex/config.toml (user level, which shadcn's CLI cannot write), ~/.gemini/settings.json, Windsurf's mcp_config.json and ~/.copilot/mcp-config.json. Version alignment also varies. MUI's documented config floats on @latest, and Nuxt UI's hosted server is not tied to any installed version. TanStack Intent skills live in node_modules, so they are pinned to the installed version and change with npm update. From 10.6, Storybook releases its MCP packages with Storybook itself, uses caret peer dependencies, and serves version-matched skills from the installed Storybook through `storybook skills get`.

### Claims that the check refuted
These are not findings. Two of three checking agents or more voted against each one.

- The server's version is not tied to the version installed in the project. The documented default config runs the latest CLI through `npx -y @ant-design/cli mcp`. To pin the antd version that the docs data comes from, the user adds a `--version` argument by hand. Vote 0-3. Claimed source: https://ant.design/docs/react/mcp/
- On the consumer side, `npx @tanstack/intent install` scans dependencies for intent-enabled packages and writes their skills into agent configuration files such as CLAUDE.md or .cursorrules; `npx @tanstack/intent list [--json]` shows which dependencies are intent-enabled. Vote 0-3. Claimed source: https://tanstack.com/blog/from-docs-to-agents

### The question sent to the workflow
> As of November 2026, how do UI component libraries and developer tools ship MCP (Model Context Protocol) servers and agent skills for coding agents? (1) Where do they ship them: inside the library's own npm package, as separate packages, or as hosted servers? Name concrete projects and what each does, for example shadcn/ui, Chakra UI, MUI, Ant Design, Mantine, Storybook, Astro, Tailwind CSS, TanStack (including TanStack Intent), Nuxt UI, Vercel and Figma. (2) How do they install the server and the skills into a consumer project: an init command or a package.json bin script, and which files it writes, such as .mcp.json, AGENTS.md, CLAUDE.md, .claude/skills or .cursor/rules? (3) How do agent hosts find MCP servers and skills: Claude Code, Codex, Cursor, VS Code Copilot, Gemini CLI and Windsurf, including configuration files, plugins and marketplaces, and the Agent Skills format? (4) How do they keep the server and the skills in step with the installed version of the library, and how does an update reach a consumer project? Context: a design system plans to ship its MCP server and its agent skills inside its npm package, with an init script. Prefer primary sources: official documentation, source repositories and release notes, with their dates. Report facts and the disagreements between sources. Give no recommendation and no opinion.

## Findings
- Ant Design's official MCP server is not in the antd component package. It ships in the separate @ant-design/cli package (v6.3.5 or later) and starts with `antd mcp` (or `npx -y @ant-design/cli mcp`), which provides 8 tools and 2 prompts. The same CLI has `antd setup --client &lt;claude|cursor|vscode|codex>`, which writes project configuration in three modes (mcp, skill or both) and takes --dry-run, --check and --write-instructions flags. Evidence: Two claims merged, both voted 3-0. The quote: 'Starting from @ant-design/cli v6.3.5, you can launch an official MCP server with the antd mcp command, providing 8 tools and 2 prompts.' The npm registry shows that antd defines no bin, while @ant-design/cli defines bin { antd: 'dist/index.js' } (v6.7.0, 2026-11-04). The docs show the setup examples and list the supported clients and modes. They do not say which files setup writes or what --check and --write-instructions do. A server-side --version argument pins the antd version the docs data comes from. Confidence high; vote 3-0, 3-0. Source: https://ant.design/docs/react/mcp/, checked 2026-11-12.
- shadcn/ui's MCP server is the `mcp` subcommand of the shadcn CLI package (`npx shadcn@latest mcp`). It is not a separately named package. It browses, searches and installs items from shadcn-compatible registries configured in the consumer's components.json. `npx shadcn@latest mcp init --client claude|cursor|vscode|codex|opencode` runs in the project, and the docs place the config in .mcp.json for Claude Code, .cursor/mcp.json for Cursor and .vscode/mcp.json for VS Code with Copilot. For Codex the CLI cannot write ~/.codex/config.toml. It installs the dependency and prints manual steps. Evidence: Three claims merged, each voted 3-0. Docs quote: 'The MCP server acts as a bridge between your AI assistant, component registries and the shadcn CLI.' Docs quote on Codex: 'The shadcn CLI cannot automatically update ~/.codex/config.toml.' In the CLI source, the codex branch installs shadcn, prints instructions and exits without calling runMcpInit, even though the CLIENTS table lists configPath .codex/config.toml. npm shows shadcn 4.23.0 with the single bin `shadcn`. A third-party guide (shadcn.io) says Codex also reads a project-level .codex/config.toml in trusted projects. The official shadcn docs do not say this. Confidence high; vote 3-0, 3-0, 3-0. Source: https://ui.shadcn.com/docs/mcp and https://github.com/shadcn-ui/ui (packages/shadcn/src/commands/mcp.ts; apps/v4/content/docs/(root)/mcp.mdx), checked 2026-11-12.
- Chakra UI ships its MCP server as the separate npm package @chakra-ui/react-mcp. The server supports only stdio. Installation is manual, one host at a time: a server block that runs `npx -y @chakra-ui/react-mcp` goes in .vscode/mcp.json (servers key), .cursor/mcp.json, ~/.codeium/windsurf/mcp_config.json or a custom client (mcpServers key), or Zed settings.json (context_servers). For Claude Code the user runs `claude mcp add`. Chakra documents no init or bin script. Skills are installed separately from GitHub with the third-party `npx skills add` CLI. Evidence: Two claims merged, both voted 3-0. The quote: 'The MCP server currently supports only stdio transport and is published at @chakra-ui/react-mcp.' The latest npm version is 2.1.1, published about a year ago, with 9 versions. The two sources disagree on tool names. The docs list list_components and list_component_templates. The npm README lists get_components and list_blocks. Confidence high; vote 3-0, 3-0. Source: https://chakra-ui.com/docs/get-started/ai/mcp-server and https://chakra-ui.com/docs/get-started/ai/skills and https://www.npmjs.com/package/@chakra-ui/react-mcp, checked 2026-11-12.
- MUI ships its MCP server as the separate package @mui/mcp. It runs locally over stdio. Every documented config uses `npx -y @mui/mcp@latest`, so the server version follows the latest npm publish and not the @mui/material version installed in the project. MUI provides no init or bin script. Users add the server through each host's own UI or CLI. For Claude Code that is `claude mcp add`, which uses local scope by default and user scope with -s user; the README says this writes ~/.claude.json and never the repository's shared .mcp.json. Guidance files (.github/instructions/mui.md and a CLAUDE.md block) are created by hand. Evidence: Three claims merged, each voted 3-0. The quote: 'The MCP is available as a separate package that runs locally and communicates via your AI client using the stdio transport.' The README arrived with mui-x commit 1cf504e, '[mcp] Add @mui/mcp server and @mui/x-agent-tools (#22947)', dated 2026-07-06. VS Code also needs the chat.mcp.enabled and chat.mcp.discovery.enabled settings. Zed can install the server as an extension. That the server is absent from @mui/material is an inference: the docs do not state it. Confidence high; vote 3-0, 3-0, 3-0. Source: https://mui.com/material-ui/getting-started/mcp/ and https://github.com/mui/mui-x/blob/master/packages/mcp/README.md, checked 2026-11-12.
- Nuxt UI hosts its MCP server at https://ui.nuxt.com/mcp over HTTP. It is not a local process from the @nuxt/ui package. Installation is manual, with one snippet per host: `claude mcp add --transport http` for Claude Code; .cursor/mcp.json or a deeplink for Cursor; ~/.gemini/settings.json (httpUrl) for Gemini CLI; .vscode/mcp.json (servers key) for VS Code; .codeium/windsurf/mcp_config.json (serverUrl) for Windsurf; and /mcp add or ~/.copilot/mcp-config.json for Copilot CLI. Its agent skill lives on GitHub at skills/nuxt-ui/SKILL.md on the v4 branch. It is installed with the third-party skills CLI (`npx skills add nuxt/ui`, which supports 35+ agents and takes --agent, --global or the website URL), with `claude skill add &lt;github url>`, or with a Cursor deeplink. It is not shipped in the npm package. Evidence: Four claims merged, each voted 3-0. The quote: 'The Nuxt UI MCP server uses HTTP transport ... MCP server URL: https://ui.nuxt.com/mcp.' The server is built with @nuxtjs/mcp-toolkit, which serves /mcp on the deployed docs site. A verifier ran `npm pack @nuxt/ui` on 4.12.0 (2026-10-15): the package has no bin and no skill, AGENTS or mcp files. The docs call the skills CLI 'the easiest way', which is not the same as calling it recommended. Claude Desktop reaches the server through a local `npx mcp-remote` proxy. Confidence high; vote 3-0, 3-0, 3-0, 3-0. Source: https://ui.nuxt.com/docs/getting-started/ai/mcp and https://ui.nuxt.com/docs/getting-started/ai/skills and https://nuxt.com/blog (Building an MCP Server for Nuxt), checked 2026-11-12.
- TanStack Intent (@tanstack/intent) is a CLI for library maintainers. It generates, validates and ships Agent Skills inside the library's own npm package. The skills reach consumers through npm updates and stay pinned to the installed version. On the consumer side, `npx @tanstack/intent install` writes lightweight guidance blocks into AGENTS.md (the default), CLAUDE.md or .cursorrules. These blocks point at node_modules/&lt;pkg>/skills/.../SKILL.md, so the skill content itself is not copied. Evidence: Two claims merged, both voted 3-0. The announcement post (2026-03-04, Gerrard and Kyle Mathews) says: 'Skills ship inside your npm package', 'They're pinned to the installed version' and 'Update the package, and skills update too.' The TanStack AI docs show a generated mapping such as `load: node_modules/@tanstack/ai/skills/ai-core/SKILL.md`. A claim saying install 'writes their skills into' CLAUDE.md or .cursorrules was refuted 0-3, because it writes pointers and not the skill content. The mapping block may need re-running when a package adds or renames skills. TanStack AI also offers paths that do not pin to the installed version: a Claude Code plugin marketplace and `npx skills add -g`. Confidence high; vote 3-0, 3-0 (related consumer-side claim refuted 0-3). Source: https://tanstack.com/blog/from-docs-to-agents and https://tanstack.com/intent/latest and TanStack Table and TanStack AI agent-skills docs pages and https://www.npmjs.com/package/@tanstack/intent, checked 2026-11-12.
- Storybook ships MCP as the addon @storybook/addon-mcp, installed with `npx storybook add @storybook/addon-mcp`. It was introduced in Storybook 10.3 for React only, and as of 10.6 the server works in every project. The server is a local HTTP endpoint on the dev server, http://localhost:6006/mcp. It is registered with the agent host at project scope by the third-party mcp-add CLI (`npx mcp-add --type http --url ... --scope project`) or by hand; no Storybook step writes .mcp.json. Users edit AGENTS.md or CLAUDE.md by hand. A published Storybook MCP can also be hosted remotely, and Chromatic hosts it free with versioning and authorization, so teammates can use it without running Storybook. Evidence: Three claims merged, each voted 3-0. The blog post by Kyle Gach was published 2026-03-23 and modified 2026-09-11. The 10.6 docs say 'The MCP server is part of the dev server.' The 10.4 release notes (2026-05-18) describe `storybook ai setup`, which can install the addon, and say integration with agent harnesses is being made easier. Only the Storybook blog says Chromatic hosting is free. The Chromatic page names no price. Confidence high; vote 3-0, 3-0, 3-0. Source: https://storybook.js.org/blog/storybook-mcp-for-react/ and https://storybook.js.org/docs/ai/mcp/overview and https://storybook.js.org/docs/ai/setup and https://www.chromatic.com/ai, checked 2026-11-12.
- Storybook moved @storybook/addon-mcp, @storybook/mcp, its Claude and Codex plugins and their skills into the Storybook monorepo. From 10.6 these packages are versioned and released with Storybook and declare caret peer dependencies; @storybook/mcp has no Storybook dependency. Each capability is implemented once as a core toolset. The MCP addon, the hosted @storybook/mcp and a public `storybook tools` CLI are thin adapters over those toolsets. A `storybook skills get &lt;id>` CLI (PR #35757, merged into `next` on 2026-08-13) serves skill workflows from the installed Storybook, version-matched to it. It is planned to replace `storybook ai setup` and the MCP write-story-instructions tool. MCP stays supported: migration starts no earlier than 11.0 and retirement no earlier than 12.0. Evidence: Three claims merged, each voted 3-0. The tracking issue was opened 2026-07-17 and closed 2026-08-31. On npm, @storybook/addon-mcp@latest is 10.6.7, the same as storybook, with peer dependencies storybook ^10.6.7 and @storybook/addon-vitest ^10.6.7. The 10.6.0 release notes list Skills M4 and M5a. A caret range accepts any 10.x at or above 10.6.7, so it is not an exact match. The 11.0 and 12.0 dates are plans. Milestone 7, which moves the plugins to `skills get`, was blocked on other milestones. Confidence high; vote 3-0, 3-0, 3-0. Source: https://github.com/storybookjs/storybook/issues/35526 and https://github.com/storybookjs/storybook/pull/35757 and npm registry: @storybook/addon-mcp, @storybook/mcp and @storybook/react 10.6.0 release notes (newreleases.io mirror), checked 2026-11-12.
- In the Agent Skills format, a skill is a folder that contains a required SKILL.md. Its frontmatter has at least `name` (at most 64 characters, lowercase letters, numbers and hyphens) and `description` (at most 1024 characters), followed by instructions. The optional subfolders are scripts/, references/ and assets/. Optional fields include license, compatibility, metadata and the experimental allowed-tools. Evidence: Voted 3-0. The /home quote: 'a skill is a folder containing a SKILL.md file. This file includes metadata (name and description, at minimum) and instructions.' The specification page lists the directory tree and the frontmatter table, and it allows extra files beyond the three named subfolders. Confidence high; vote 3-0. Source: https://agentskills.io/home and https://agentskills.io/specification, checked 2026-11-12.
- Across the projects checked, the documented agent-host MCP config locations are: Claude Code, project .mcp.json or `claude mcp add` (local scope in ~/.claude.json by default, or -s user); Cursor, .cursor/mcp.json or ~/.cursor/mcp.json; VS Code with Copilot, .vscode/mcp.json under a `servers` key, not `mcpServers`; Codex, ~/.codex/config.toml [mcp_servers.&lt;name>] or `codex mcp add`; Gemini CLI, ~/.gemini/settings.json (httpUrl for remote servers); Windsurf, ~/.codeium/windsurf/mcp_config.json (serverUrl for remote servers); Copilot CLI, ~/.copilot/mcp-config.json or /mcp add. Key names and transport fields differ between hosts, so each project documents a separate snippet for each host. Evidence: This finding is synthesized from library documentation in claims 3, 4, 6, 9 and 11, each voted 3-0. No agent host's own primary documentation was among the verified claims, so the host-side facts are second-hand. Confidence medium; vote derived from 3-0 claims. Source: https://ui.shadcn.com/docs/mcp and https://chakra-ui.com/docs/get-started/ai/mcp-server and https://mui.com/material-ui/getting-started/mcp/ and https://ui.nuxt.com/docs/getting-started/ai/mcp, checked 2026-11-12.
