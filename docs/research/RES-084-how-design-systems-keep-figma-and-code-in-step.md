# RES-084: How large design systems keep their Figma library and their code in step

## Question
How do large and popular design systems keep their Figma library and their code in step: which side is the source of truth, how do tokens and components move between the two, how is a Figma component linked to its code, and how are larger compositions such as patterns, templates and blocks handled?

Peter asked for this research on 2026-11-20, with `/deep-research`, in his reply to IDEA-011#02. His words: "I'd like you to research what is provided by figma, how other large/popular design-systems handle this exact type of thing - you should fan out and cover a lot of ground here."

Needed by: IDEA-011#02, the source of truth of a block. The facts also bear on IDEA-002 rows 07, 10 and 11. RES-049 holds how nine systems bring token changes from Figma into their repo.

## Answer
Answered on 2026-11-20. The survey has 50 design systems: 46 that the main session named and 4 that a critic added. A second agent checked each record against the sources and corrected each.

Which side is the source of truth for components:
- 27 of 50 name none. Some of them name a source of truth for tokens only.
- 14 name code, or their wording points to code: Polaris, Primer, SAP, MUI, Mantine, shadcn/ui, HeroUI, PrimeTek, Web Awesome, Tailwind Plus, GitLab Pajamas, USWDS, Elastic EUI and Porsche. Five of them use the words "source of truth"; for the others the value is read from words such as "mirror" and "recreated".
- 7 name Figma, or their wording points to Figma: Carbon, Spectrum, Untitled UI, Skyscanner Backpack, Uber Base, Telefonica Mistica and Flowbite. Carbon and Spectrum name the design spec in Figma as the source for the visual side.
- 2 share the tokens and keep the components apart: Twilio Paste and PatternFly.

How the two sides are kept in step:
- Tokens are the one thing that teams move by machine, in both directions: from code to Figma (Pajamas, Clarity, Mistica, Primer) and from Figma to code (Workday Canvas, Backpack, Orbit, Cedar, PatternFly, Pine). Several of these use the Variables REST API, which needs the Enterprise plan (RES-083).
- Components are kept the same by hand in nearly each system: a checklist or a definition of done, a review, or a redraw. No system generates its components from the other side.
- The link of a Figma component to its code: Code Connect in eight systems (Carbon, Primer, Pajamas, Backpack, Porsche, Mistica, Pine, Coinbase). PatternFly removed it in 2026 and names "significant overhead". Others use links, embeds or a shared naming rule.

Patterns, templates and blocks:
- In code only in many systems, among them Polaris, Chakra UI Pro, Mantine UI, HeroUI Pro, Tailwind Plus, shadcn/ui and Web Awesome.
- On both sides in a second group, among them Atlassian, SAP, Untitled UI, Nuxt UI, Vuetify, PrimeTek, Twilio Paste, PatternFly and Porsche.
- Only six records state which side leads: Figma in Carbon, Flowbite and Wise's editorial patterns; code in USWDS, Tailwind Plus and Polaris.

What maintainers state as problems: the Figma library lags the code (Salesforce, Web Awesome, PrimeTek, SAP, Atlassian, Vuetify, EUI, USWDS); Figma cannot express some features of code, such as calc and color-mix (PrimeTek, Web Awesome, SAP, MUI, Primer); structures differ, so a mapping fails (Carbon, USWDS, Polaris); and Code Connect has a cost, with snippets that go stale (PatternFly, Pajamas, Mistica, Pine).

What teams document for agents: three systems have a skill that builds Figma designs with their library through the Figma MCP (Mistica, PatternFly, Pine), and several have a skill that reads designs through it (Spectrum, Workday Canvas, Backpack, Coinbase).

For IDEA-011#02: no surveyed system that names Figma as its source of truth generates code from Figma. In each of them a person builds the code to the Figma spec, and a checklist or a review keeps the two the same.

2. How tokens move
- From code to Figma, with a script or pipeline:
  - GitLab Pajamas: `yarn sync-tokens`, run by hand from main, through the Figma REST Variables API.
  - VMware Clarity: the Figma Token Publisher pushes on each release through the Variables API.
  - Telefonica Mistica: the repository JSON is pushed to Figma by a GitHub Action on push or by hand, and is also built into code.
  - Atlassian: Style Dictionary "Figma synchronizers" write figma/ JSON. Who pushes it into Figma today is not confirmed.
  - GitHub Primer: `build:figma` output is imported with the Primer Design Token Manager plugin.
  - Adobe Spectrum (native path): from design-data to Figma.
  - SAP: theming-base-content feeds the central Figma variables. The tool is not named.
- From code to Figma, with a plugin a user runs:
  - HeroUI: the Theme Sync plugin. The user pastes the theme CSS.
  - shadcncraft kit: the user pastes a preset URL into the plugin.
- From code to Figma, by hand:
  - USWDS, Web Awesome, Twilio Paste, the unofficial Radix file.
  - Wise: colors.json is pasted into an import plugin.
  - Nord: by hand in practice.
- From Figma to code, with a script or CI:
  - Workday Canvas: a GitHub workflow started by hand, through the Figma REST variables API, to DTCG JSON.
  - Skyscanner Backpack: token-sync on a daily cron, to DTCG and Style Dictionary.
  - Kiwi.com Orbit: a daily cron for palette colours; icons by hand only.
  - REI Cedar: a workflow started by hand. The way back from tokens to Figma is not implemented.
  - Coinbase: the illustration palette and icons.
  - Ionic: the v10 "next" branch only, through the OutSystems tokens package.
- From Figma to code, with a plugin or Tokens Studio:
  - PatternFly: the Export Patternfly Tokens plugin, run by hand, then Style Dictionary.
  - Kajabi Pine: Tokens Studio, connected to the ds-tokens repository.
  - Adobe Spectrum (inbound path): Tokens Studio, then a PR.
  - Pinterest Gestalt: vr-theme in Tokens Studio. The trigger is not confirmed.
  - PrimeTek: the Theme Generator plugin.
  - Material 3: the Theme Builder plugin.
  - MUI: the Sync plugin, which is suspended.
  - Progress Kendo: the ThemeBuilder plugin, for customer themes.
  - Obra kit (for shadcn/ui): a plugin that writes globals.css.
  - Microsoft Fluent: from design to code. The current tool is private.
- No documented flow or not confirmed:
  - IBM Carbon, Shopify Polaris, Salesforce SLDS (which claims sync but names no tool), Ant Design, Chakra UI, Mantine, Radix team, Nuxt UI, Vuetify core.
  - Ionic released code, Tailwind Plus, Vercel Geist, GOV.UK, Zendesk Garden, Elastic EUI, Untitled UI, Porsche.
  - NVIDIA Elements, AWS Cloudscape, Flowbite, Decathlon Vitamin (icons only), Grafana Saga (code defines the theme), Coinbase UI theme tokens, Uber Base.

7. Problems that maintainers state
- The Figma library lags the code:
  - Salesforce SLDS ("published only a few times a year"), Web Awesome (each component is built by hand), PrimeTek (the kit trails the libraries), SAP (2023).
  - Atlassian (the public Community file), Vuetify (the free file), Elastic EUI (no one dedicated, about 5 years ago), USWDS (inconsistencies; QA traded for publishing).
  - IBM Carbon: v17 toolkit "coming soon"? No: that statement is VMware Clarity's. Grafana Saga is not a lag statement.
- Community copies and duplicated files get no updates: Material 3, Salesforce SLDS, MUI, HeroUI, Web Awesome, Obra (shadcn kit), Kiwi.com Orbit, PatternFly.
- Figma cannot express code features (calc, math, scaling, color-mix, methods, modes): PrimeTek, Web Awesome, Radix (the third-party maintainer), SAP, MUI, Primer (only colour and size variables), Clarity (density strokes), Progress Kendo (plugin export limits).
- Structures differ, so mapping fails: IBM Carbon (props, skeletons, Menu), USWDS (grade names, Dev Mode deferred), Shopify Polaris (2022 challenges).
- Code Connect cost and limits:
  - PatternFly: "significant overhead", and Code Connect was removed.
  - MUI: plan cost.
  - GitLab Pajamas: errors are silent, and publishing goes straight to the main library.
  - Telefonica Mistica: snippets are stale or map to the wrong slot.
  - Kajabi Pine: publishing was manual and snippets went stale.
  - Carbon: modes were not supported in 2024.
- Token sync friction:
  - Workday Canvas: sync was manual before the tool.
  - Adobe Spectrum: the Figma variables drift as a copy kept by hand.
  - REI Cedar: different vocabularies in design and code.
  - Skyscanner Backpack: needs a Figma Enterprise org; sometimes needs a person to step in.
  - Kajabi Pine: a workflow across two repositories.
  - GitLab Pajamas: deprecated tokens are moved by hand.
- Specs drift: Uber Base. Engineers build from assumptions when specs fall behind.
- A Figma library without a manager: GOV.UK. Users cannot tell whether it is up to date; the team calls this a reputational risk.
- Cost reasons for having no Figma library: Ant Design, Mantine, Tailwind Plus.
- Context switching: Coinbase (2025 talk).
- Detached instances: Salesforce SLDS, Twilio Paste (theming).
- Not stated: Chakra UI, Nuxt UI, Untitled UI (Figma file size only), Zendesk Garden, NVIDIA Elements, Ionic, Vercel Geist, Wise (only related statements), Decathlon Vitamin, Twilio Paste (sync), shadcn/ui maintainers.
