# RES-086: Plugins from a marketplace of our own in five agent hosts

## Question
Which agent hosts load a plugin from a marketplace that is a repository of the project, and not only from their official marketplace (Claude Code, Codex, Cursor, Gemini CLI, VS Code with GitHub Copilot)? What can a plugin of each host hold? Can its entry for an MCP server start the server of a package that is installed in the open project? What does each host do when the project holds the same skill and the same server entry too?

Settled context: the guidance ships inside the main npm package. A command line tool in its `bin` writes the server entry, the skills and a managed block for each host. DEC-161 adds a thin plugin from a marketplace of our own. It holds pointers only: a skill that reads the installed package, and an entry that starts the installed server.

Needed by: IDEA-005#25 (which hosts the new system supports and which get the plugin), and the spec of the plugin and of the command.

## Answer
Sufficient answer, for each of the five hosts, with its version and the date of the check:
1. Whether the host has plugins or extensions with the same role, their name, and what one holds (skills, MCP entries, commands, hooks, instructions), quoted from the host's documentation.
2. Where a user installs one from: only the official marketplace, or also a Git repository or a local folder of a third party. Exact commands or settings. Whether a project file can name the marketplace and the plugin for a team, and whether it can pin a version, tag or commit.
3. How a plugin updates.
4. The MCP entry in a plugin: its working directory; whether it can start a command of a package installed in the open project; the path variables; what the host shows on failure.
5. Duplicates of a skill or an MCP server between a plugin and the project: from the documentation, and from a test where possible.
6. Whether a plugin's skill is held as a link or a copy, and where.

### Claude Code (installed here: 2.1.329; docs read as `.md` from code.claude.com on 2026-11-20, pages carry no date)
- Plugins hold skills, commands, agents, hooks, MCP servers, LSP servers, output styles and `userConfig`; the manifest `.claude-plugin/plugin.json` is optional, and `name` is its only required key. Its example sets `"skills"`, `"commands"`, `"agents"`, `"hooks"`, `"mcpServers"` and `"lspServers"`. Source: https://code.claude.com/docs/en/plugins-reference.md ("Manifest file", "Fields"), checked 2026-11-20.
- A plugin holds no always-loaded instructions: "To include instructions in a plugin, write them as a skill. Claude Code doesn't load a `CLAUDE.md` at the plugin root, and `claude plugin validate` warns `CLAUDE.md at the plugin root is not loaded as project context`". Source: https://code.claude.com/docs/en/plugins/components.md ("Skills"), checked 2026-11-20.
- A user adds a third-party marketplace with `/plugin marketplace add <source>` or `claude plugin marketplace add <source>`. Sources: "GitHub repository `owner/repo`. Add `#ref` to pin a branch or tag", "Git repository on any host: the full clone URL. Add `#ref`", "Local directory or file", and "Hosted `marketplace.json`". Install: `claude plugin install <name>@<marketplace> [--scope user|project|local]`; `--marketplace <source>` installs from a marketplace not yet added (v2.1.275 or later). Source: https://code.claude.com/docs/en/discover-plugins.md ("Add a marketplace", "Install from your shell"), checked 2026-11-20.
- A project file can name the marketplace and the plugin: `extraKnownMarketplaces` (a map of name to `source`) and `enabledPlugins` (`"<name>@<marketplace>": true`) in the committed `.claude/settings.json`. "Committing that entry turns the plugin on for your collaborators but doesn't download it to their machines. Each collaborator also runs `claude plugin install <name>@<marketplace> --scope project` once per clone." `extraKnownMarketplaces` and project plugins load only after the workspace trust dialog. Source: https://code.claude.com/docs/en/discover-plugins.md ("Choose an install scope") and https://code.claude.com/docs/en/plugins/loading.md ("Trust check and component limits for repository plugins", "Enabled in project settings but not installed"), checked 2026-11-20.
- Pinning: a marketplace source of type `github` or `git` takes `ref`; "To keep refreshes and auto-updates from moving a `github` or `git` marketplace off a commit you've reviewed, set `ref` to that commit's full SHA". A plugin entry's `github` source takes `ref` and `sha`; its `url` source takes `ref`. A `version` in `plugin.json` "keeps users on that version until you change it". Source: https://code.claude.com/docs/en/plugins/marketplace-reference.md ("github plugin source", "url plugin source", "Source objects in settings") and https://code.claude.com/docs/en/plugins-reference.md ("Fields"), checked 2026-11-20.
- Updates: "Plugins update automatically when the marketplace they came from has auto-update turned on." Auto-update is on by default for the official marketplace names and "Off by default: every other marketplace, including the community marketplace, third-party marketplaces, and local development marketplaces." It is turned on per marketplace in `/plugin` > Marketplaces or with `autoUpdate` on the `extraKnownMarketplaces` entry. Otherwise the user runs `claude plugin update`. After an update in a session: "Run /reload-plugins to apply". Source: https://code.claude.com/docs/en/discover-plugins.md ("Keep plugins updated") and https://code.claude.com/docs/en/plugins/loading.md ("When auto-update runs"), checked 2026-11-20.
- Copy on disk: "Every other marketplace plugin: Claude Code copies the plugin into `cache/<marketplace>/<plugin>/<version>/` at install and loads that copy"; a relative-path plugin of a marketplace added from a local path "loads in place". `${CLAUDE_PLUGIN_ROOT}` points at the cache folder. Source: https://code.claude.com/docs/en/plugins/loading.md ("In-place and copied plugins"), checked 2026-11-20.
- Plugin MCP entries: in `.mcp.json` at the plugin root or `mcpServers` in `plugin.json`; the server name is `plugin:<plugin>:<server>` and its tools `mcp__plugin_<plugin>_<server>__<tool>`. In stdio `command`, `args` and `env`, Claude Code substitutes `CLAUDE_PLUGIN_ROOT`, `CLAUDE_PLUGIN_DATA` and `CLAUDE_PROJECT_DIR` ("The project root"). It also sets `CLAUDE_PROJECT_DIR` in the environment of each spawned stdio server. Source: https://code.claude.com/docs/en/plugins/components.md ("Server names, tool names, and reloads"), https://code.claude.com/docs/en/plugins-reference.md ("Environment variables") and https://code.claude.com/docs/en/mcp.md ("Option 3: Add a local stdio server"), checked 2026-11-20.
- Working directory: the MCP page gives a table for the `headersHelper` command only, where a plugin's helper runs in "The plugin's root directory" and a project `.mcp.json` helper in "The project directory the server is declared in". The pages read state no working directory for a plugin's stdio server command itself. Source: https://code.claude.com/docs/en/mcp.md ("headersHelper" working-directory table), checked 2026-11-20.
- Failure display: `claude mcp list` shows `✘ Failed to connect` with the failure detail appended, `claude mcp get <name>` shows it on an `Issue:` line, and `/mcp` shows an `Issue:` row. Source: https://code.claude.com/docs/en/mcp.md ("Server status"), checked 2026-11-20.
- Duplicate MCP servers: "When the same server is defined in more than one place, Claude Code connects to it once, using the definition from the highest-precedence source." Order: local, project, user, plugin-provided servers, claude.ai connectors. "Claude Code matches duplicates across the three scopes by name. It matches plugins and connectors by endpoint, so one that points at the same URL or command as an enabled server above counts as a duplicate", and the docs name no warning. Source: https://code.claude.com/docs/en/mcp.md ("Scope hierarchy and precedence"), checked 2026-11-20.
- Duplicate skills: "A plugin skill and a skill at any of the locations above: Both load, because plugin skills are namespaced as `/plugin-name:skill-name`." The bare name of a plugin skill "also invokes the skill unless another command already uses that name". Source: https://code.claude.com/docs/en/skills.md ("Resolve skills that share a name", "How a skill gets its command name"), checked 2026-11-20.
