# RES-047: How design systems with web components build their documentation websites

## Question
How do other design systems with web components and several framework packages build their documentation websites: which site tools they use, how one page shows an example for each framework, how they hold a blocks section, and which TanStack packages (Table, Virtual, Form) work with Lit and with each framework target?

Needed by: IDEA-007#04 (where the records of the website come from), IDEA-007#05 (which tool builds the website and where it is published), IDEA-007#06 (how a page shows one example in plain HTML and in each framework package), and the open point whether the Blocks section gets tables and forms with TanStack packages (DEC-146).

## Answer
Sufficient answer: (1) for at least six named design systems that ship web components and one or more framework packages, the site tool, where the page records come from (hand-written pages, a Custom Elements Manifest, generated metadata), how one example is shown for each framework, and whether live examples run in the page, each from the system's own repository or documentation; (2) the blocks sections of shadcn/ui and Chakra UI: how a block is stored, shown, previewed and copied or installed, and how many blocks each has today; (3) TanStack Table, Virtual and Form: which adapters exist today, with version, for Lit, React, Preact and Solid, what the documentation says about use with Lit or custom elements, and what is known for TanStack Redact. Each fact has its source, version and date, and what could not be confirmed is named.

The condition is met. All facts were checked on 2026-11-12. The record makes no recommendation.

Patterns across the six systems with a framework package:
- Only Ionic and UI5 show a separate snippet for each framework in each example.
- Shoelace pairs HTML and React snippets by hand in Markdown.
- Web Awesome and Spectrum show HTML examples and put framework use on guide pages.
- Every Lit system whose React package is generated makes it with @lit/react from the CEM.
- Ionic and UI5 store each example as separate files per framework in a folder, outside the prose page.

**(2) Blocks.**
- shadcn/ui: each block is a registry item of type `registry:block`. Its files live in a folder such as `registry/new-york-v4/blocks/dashboard-01/` (page.tsx, components, data). The /blocks page previews each block in an iframe of `/view/<style>/<name>`. The viewer has Desktop, Tablet and Mobile widths (100, 60 and 30 percent), a Code view with a file tree, a refresh button and "Open in v0". It copies the command `npx shadcn add <name>`. Today the new-york-v4 registry has 97 blocks: 27 page and layout blocks (dashboard-01, sidebar-01 to 16, login-01 to 05, signup-01 to 05) and 70 chart blocks. dashboard-01 depends on @tanstack/react-table.
- Chakra UI: the documentation site (chakra-ui.com) has no blocks section; /blocks returns 404. Blocks are on a separate commercial site, Chakra UI Pro. It has four groups: application 151, marketing 114, e-commerce 23 and documentation 50, so 338 blocks, plus 7 free blocks. A block page has Preview and Code tabs and previews the block in an iframe. Installation is `chakra blocks add`, which needs a Pro subscription and the API key in CHAKRA_UI_PRO_API_KEY. The CLI also has `chakra snippet add` for the free snippets.
- Web Awesome (not asked, but a web-component precedent): a Patterns section of copy-and-paste HTML. There are 50 pattern pages in four groups: App 12, Blog and News 18, E-commerce 12, Layouts 8. The pattern pages are not in the public repository.

What the documentation says about Lit:
- Lit Table is built around TableController, a Lit ReactiveController. Its docs have a Lit virtualization guide that pairs it with @tanstack/lit-virtual. One guide notes that Lit renders into shadow DOM, so styles go in `static styles`.
- Lit Virtual provides VirtualizerController and WindowVirtualizerController.
- Lit Form provides TanStackFormController. Its composition guides pass the controller or a FieldApi to child custom elements as a property, and subscribe to it with TanStackStoreSelector.
- No TanStack page mentions form-associated custom elements or ElementInternals.
- The TanStack Form installation page lists React, Vue, Angular, Solid, Lit and Svelte, but not Preact, although the preact-form package exists.

TanStack Redact (0.3.1): no TanStack Table, Virtual or Form document mentions Redact. The Redact repository does not mention them either. Its test suite has tests that render and hydrate custom elements. Whether react-table, react-virtual and react-form run under Redact is UNVERIFIED.

Not confirmed: Calcite's page records and how it shows examples, because its site source is not public. Also not confirmed: whether Chakra Pro block code can be viewed without signing in, and the host of the Carbon and Spectrum sites.

## Findings

### Web component systems
- Web Awesome 3.14.0 (released 2026-09-24) builds its documentation site with Eleventy from `packages/webawesome/docs`. Vercel builds it, with outputDirectory `packages/webawesome/_site`. Source: https://github.com/shoelace-style/webawesome/tree/1828b3992c/packages/webawesome/docs and https://github.com/shoelace-style/webawesome/blob/1828b3992c/vercel.json, checked 2026-11-12.
- Each Web Awesome component page is hand-written Markdown with front matter: title, layout: component, category, synonyms and use-cases. The component layout reads the summary, slots, properties and methods through `getComponent`. `getComponent` parses `dist/custom-elements.json`. Source: https://github.com/shoelace-style/webawesome/blob/1828b3992c/packages/webawesome/docs/docs/components/badge.md, https://github.com/shoelace-style/webawesome/blob/1828b3992c/packages/webawesome/docs/_layouts/component.njk and https://github.com/shoelace-style/webawesome/blob/1828b3992c/packages/webawesome/docs/_utils/manifest.js, checked 2026-11-12.
- Web Awesome examples are `html {.example}` code blocks. An Eleventy transformer "turn[s] `<code class="example">` blocks into live examples". Each component page has an import tab group with CDN, npm, self-hosted and React tabs. The React tab gives the React 18 wrapper import. Source: https://github.com/shoelace-style/webawesome/blob/1828b3992c/packages/webawesome/docs/_transformers/code-examples.js and component.njk (as above), checked 2026-11-12.
- Web Awesome makes its React wrappers with `createComponent` from @lit/react from custom-elements.json (scripts/make-react.js). Its React guide says: "React 19+ supports custom elements natively … No wrappers needed!" It keeps the wrappers as "Legacy React Wrappers (React 18 & Below)". Source: https://github.com/shoelace-style/webawesome/blob/1828b3992c/packages/webawesome/scripts/make-react.js and https://github.com/shoelace-style/webawesome/blob/1828b3992c/packages/webawesome/docs/docs/frameworks/react.md, checked 2026-11-12.
- Web Awesome has framework guide pages for Angular, Astro, Express, React, Svelte, Vue 2 and Vue. Source: https://github.com/shoelace-style/webawesome/tree/1828b3992c/packages/webawesome/docs/docs/frameworks, checked 2026-11-12.
- Web Awesome's site has a Patterns section. The index page calls a pattern "a code snippet composed of components, style utilities, and native HTML that you can copy and paste into any project". The page says patterns are "written as standard HTML". It links 50 pattern pages in four groups: app 12, blog-news 18, ecommerce 12 and layouts 8. The public repository tree holds a `pattern.njk` layout and pattern images, but no pattern pages. Source: https://webawesome.com/docs/patterns/ and https://github.com/shoelace-style/webawesome/tree/1828b3992c, checked 2026-11-12.
- Shoelace (shoelace-style/shoelace, archived, last release v2.20.1 on 2025-03-11) builds its docs with Eleventy (`docs/eleventy.config.cjs`). It reads component metadata through `getComponent` and a `cem.cjs` utility. Source: https://github.com/shoelace-style/shoelace/tree/25bd8ec776/docs, checked 2026-11-12.
- A Shoelace component page puts each example as a `html:preview` block, followed by a hand-written `jsx:react` block. The code-preview utility renders the preview with HTML and React source buttons and an "Edit on CodePen" button. Source: https://github.com/shoelace-style/shoelace/blob/25bd8ec776/docs/pages/components/badge.md and https://github.com/shoelace-style/shoelace/blob/25bd8ec776/docs/_utilities/code-previews.cjs, checked 2026-11-12.
- The Spectrum Web Components 1st-gen documentation (`1st-gen/projects/documentation`) is built with Eleventy and bundled with Rollup. It has a Lunr search index. Its README says a copy-docs step works "from the README.md files … in the individual packages as well as the content in custom-elements.json". The step creates the overview pages and the API tables of attributes, properties, events, slots and CSS custom properties. Source: https://github.com/adobe/spectrum-web-components/blob/a6d0b06445/1st-gen/projects/documentation/README.md, checked 2026-11-12.
- Spectrum Web Components package READMEs show examples as `html demo` blocks. The Eleventy config renders code blocks into a `code-example` element. React use is described on one guide page, "Using React Wrappers". That page says swc-react "relies on the @lit/react package". The wrappers are generated by a Custom Elements Manifest analyzer plugin (`cem-react-wrapper.config.js`, `scripts/cem-plugin-react-wrapper.js`). @swc-react/badge is 1.12.6, the same as @spectrum-web-components/badge. Source: https://github.com/adobe/spectrum-web-components/blob/a6d0b06445/1st-gen/packages/badge/README.md, https://github.com/adobe/spectrum-web-components/blob/a6d0b06445/1st-gen/projects/documentation/content/using-swc-react.md, https://github.com/adobe/spectrum-web-components/blob/a6d0b06445/1st-gen/cem-react-wrapper.config.js and https://registry.npmjs.org/@swc-react/badge/latest, checked 2026-11-12.
- Spectrum Web Components 2nd-gen (`gen2/packages/swc`) documents its components in Storybook (`.storybook/DocumentTemplate.mdx`). Source: https://github.com/adobe/spectrum-web-components/tree/a6d0b06445/gen2/packages/swc/.storybook, checked 2026-11-12.
- Ionic's documentation (ionic-team/ionic-docs) is a Docusaurus site (@docusaurus/core ^3.10.2) with a vercel.json. A local plugin, docusaurus-plugin-ionic-component-api, generates the API pages from `https://unpkg.com/@ionic/docs@<tag>/core.json`. Another local plugin is docusaurus-plugin-llms-txt. Source: https://github.com/ionic-team/ionic-docs/tree/f365b3a071 and https://github.com/ionic-team/ionic-docs/blob/f365b3a071/plugins/docusaurus-plugin-ionic-component-api/index.js, checked 2026-11-12.
- Each Ionic example is a folder under `static/usage/v<N>/<component>/<example>/` that holds demo.html, javascript.md, react.md, vue.md and angular/*.md. An index.mdx passes them to a `<Playground>` component. The Playground README says that every playground needs `code` with "a snippet for each framework", a `src` demo page and a `version`. Source: https://github.com/ionic-team/ionic-docs/blob/f365b3a071/static/usage/v8/button/basic/index.mdx and https://github.com/ionic-team/ionic-docs/blob/f365b3a071/src/components/global/Playground/README.md, checked 2026-11-12.
- The Ionic Playground renders the demo in two iframes, one for ios mode and one for md mode. It saves the chosen framework ("usage target") and mode in localStorage and sends an event so that all playgrounds on the page switch together. It opens HTML, Angular, React and Vue editors on StackBlitz. Source: https://github.com/ionic-team/ionic-docs/blob/f365b3a071/src/components/global/Playground/index.tsx, checked 2026-11-12.
- Ionic's framework packages @ionic/react, @ionic/vue and @ionic/angular are at 9.0.11, the same as @ionic/core. Source: https://registry.npmjs.org/@ionic/core/latest, https://registry.npmjs.org/@ionic/react/latest, https://registry.npmjs.org/@ionic/vue/latest and https://registry.npmjs.org/@ionic/angular/latest, checked 2026-11-12.
- The UI5 Web Components website (`packages/website`) is Docusaurus (@docusaurus/core 3.10.2). Its homepage is https://ui5.github.io/webcomponents/. Its build scripts include api-reference-generation (reads `dist/custom-elements-internal.json`), samples-generation and llms-txt-generation. Source: https://github.com/UI5/webcomponents/tree/ad911f3bd8/packages/website and https://github.com/UI5/webcomponents/blob/ad911f3bd8/packages/website/build-scripts/api-reference-generation/manifest.mjs, checked 2026-11-12.
- Each UI5 sample folder holds sample.html, main.js and sample.tsx. Its Markdown passes them as `<Editor html={html} js={js} react={react} />`. The Editor has an "HTML/React toggle". It runs the HTML sample with playground-elements (patched 0.18.1) and loads a React playground on demand. The React sample wraps the class with `createReactComponent` from @ui5/webcomponents-base. Source: https://github.com/UI5/webcomponents/tree/ad911f3bd8/packages/website/docs/_samples/main/Button/Basic and https://github.com/UI5/webcomponents/blob/ad911f3bd8/packages/website/src/components/Editor/index.js, checked 2026-11-12.
- @ui5/webcomponents is 2.28.1 and @ui5/webcomponents-react is 2.28.2. Source: https://registry.npmjs.org/@ui5/webcomponents/latest and https://registry.npmjs.org/@ui5/webcomponents-react/latest, checked 2026-11-12.
- Calcite components (@esri/calcite-components 5.2.1; next 6.0.0-next.23) depend on lit ^3.3.0 and @arcgis/lumina. The React package @esri/calcite-components-react is 5.2.1, with peers react and react-dom >=18.3. The documentation is at developers.arcgis.com/calcite-design-system. Its button page carries `<meta name="generator" content="Gatsby 5.13.7">`. The repository holds a Storybook (`build-storybook`, published with storybook-to-ghpages for screenshot tests) but not the documentation site source. Source: https://registry.npmjs.org/@esri/calcite-components, https://registry.npmjs.org/@esri/calcite-components-react/latest, https://developers.arcgis.com/calcite-design-system/components/button/ and https://github.com/Esri/calcite-design-system/blob/2e6cc41a07/packages/components/package.json, checked 2026-11-12.
- Fluent UI Web Components 3.2.1 (published 2026-11-10) is built on @microsoft/fast-element. Its documentation is a Storybook (`@storybook/html-vite`, stories and MDX under src). It is published at https://storybooks.fluentui.dev/web-components/, and web-components.fluentui.dev also resolves there. The package ships a CEM and documents CDN use with `<script type="module" src="https://unpkg.com/@fluentui/web-components">`. No framework wrapper package is in the package or its README. Source: https://github.com/microsoft/fluentui/tree/f9720c35ba/packages/web-components, https://github.com/microsoft/fluentui/blob/f9720c35ba/packages/web-components/.storybook/main.cjs and https://registry.npmjs.org/@fluentui/web-components, checked 2026-11-12.
- Carbon Web Components (@carbon/web-components 2.67.0) is built on lit ^3.1.0. It is documented in Storybook at https://web-components.carbondesignsystem.com/, with one MDX page per component that embeds stories through `<Canvas>`. It builds custom-elements.json with web-component-analyzer. Its README says v3 replaces that file with the standard Custom Elements Manifest. Its welcome page says the package "can also be used within other JavaScript frameworks such as Angular and Vue". It ships no framework package. Source: https://github.com/carbon-design-system/carbon/blob/1e17b61f5d/packages/web-components/package.json, https://github.com/carbon-design-system/carbon/blob/1e17b61f5d/packages/web-components/README.md, https://github.com/carbon-design-system/carbon/blob/1e17b61f5d/packages/web-components/src/components/button/button.mdx and https://github.com/carbon-design-system/carbon/blob/1e17b61f5d/packages/web-components/docs/welcome.mdx, checked 2026-11-12.

The README says MWC "is in maintenance mode pending new maintainers". It ships no framework package. Source: https://github.com/material-components/material-web/tree/37aa14b843/catalog, https://github.com/material-components/material-web/blob/37aa14b843/catalog/eleventy-helpers/shortcodes/playground-example.cjs and https://github.com/material-components/material-web/blob/37aa14b843/docs/components/button.md, checked 2026-11-12.

The portal README says the site "is rendered from the library's own docs/ tree". It publishes with gh-pages to a public GitHub Pages site. The previous Rocket site is frozen in `prev-portal/`. Source: https://github.com/ing-bank/lion/blob/d6a3ef21df/portal/README.md, https://github.com/ing-bank/lion/blob/d6a3ef21df/portal/package.json and https://github.com/ing-bank/lion/blob/d6a3ef21df/docs/components/button/use-cases.md, checked 2026-11-12.

It notes "you need to handle updating the element and form yourself". The composition guides pass the FieldApi or the controller to child custom elements as a property. They use TanStackStoreSelector from @tanstack/lit-store, "because Lit child elements that receive a controller by property do not automatically re-render". Source: https://tanstack.com/form/latest/docs/framework/lit/quick-start, https://github.com/TanStack/form/blob/eba4084b70/docs/framework/lit/guides/form-composition.md and https://github.com/TanStack/form/blob/eba4084b70/docs/framework/lit/guides/form-groups.md, checked 2026-11-12.
