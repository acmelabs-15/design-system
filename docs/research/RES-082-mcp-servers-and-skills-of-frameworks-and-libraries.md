# RES-082: Where frameworks and libraries keep their MCP servers and agent skills

## Question
Where do the MCP servers and the agent skills of large frameworks, packages and libraries live, over a large sample that is not limited to design systems: inside the main package, in a package of their own, on a hosted server, in a repository or a marketplace of plugins? How does a consumer install each, and how does each stay at the version of the installed library?

Peter asked for this research on 2026-11-20, with `/deep-research`, in his reply to IDEA-005#04. His conditions: a large sample, not only design systems, and comprehensive. His examples: Storybook, AG Grid and Chakra UI. He decided in the same reply that 1.0 does not use TanStack Intent (DEC-154); the survey records what Intent does as a fact of the landscape.

Needed by: IDEA-005#04, inside the package or apart; IDEA-005#05, what `init` installs and how it updates; IDEA-005#09, an agent with no project.

Earlier records with a smaller sample: RES-030, about twelve libraries and the folders of each agent host; RES-070, the skills and the tools of fifteen design systems; RES-077, the trial of an `init` command.

## Answer
Answered on 2026-11-20. The survey has 112 projects: frameworks, component libraries, data grids, chart libraries, build tools, test tools and backend libraries. A second agent checked each record against the sources and corrected 108 of them.

Where the MCP server lives:
- No official server: 34 projects.
- Several forms: 25. A package of its own: 24. A hosted server: 18. Inside the command line tool or the dev server of the project: 11, for example the Angular CLI, the Next.js dev server, the shadcn CLI and Playwright.
- No project has its MCP server only inside its main library package.

Where the guidance for coding agents lives:
- Several places: 88 projects. Documentation pages only: 9. Copied by a command: 3. A plugin marketplace only: 2. A package of its own: 1. None: 7.
- Inside the main package only: 2, Web Awesome and Redux Toolkit. About 25 more of the "several" projects have one part inside the main package, among them TanStack, Next.js, Turborepo, Prisma, SolidJS, React Router, Base UI, tRPC, Apollo Client, the Vercel AI SDK, Panda CSS, Payload, Quasar, Effect, Playwright and Angular.
- Six projects have neither a server nor guidance: Django, Lit, Ruby on Rails, Electron, Biome and Recharts.

How skills are distributed:
- The `skills` command line tool, `npx skills add`, is the most used: about 60 projects.
- Plugin marketplaces of agent hosts: about 47 projects.
- An own command or `init` of the project: about 35 projects, such as `antd setup`, `ng new --ai-config`, `storybook`, Laravel's `boost:install` and `prisma skills sync`.
- TanStack Intent: 3 projects, TanStack, tRPC and Redux Toolkit. Peter decided that 1.0 does not use it (DEC-154).

How each stays at the version of the installed library:
- Guidance that points at the installed package needs no step after an update: about 23 projects, among them Web Awesome, Next.js, Turborepo, Base UI, SolidJS, React Router, tRPC and Redux Toolkit.
- Prisma runs a script on install. About 20 projects ask the developer to run a command again. About 16 update with a plugin.
- MCP servers: about 16 read the installed package or the project; about 14 take a version as an argument; about 31 serve only the latest documentation.

The reasons that maintainers state:
- Inside the package, so that versions match: about 25 projects.
- Hosted, so that the documentation stays current: about 11 projects.
- Against an MCP server: Remotion dropped its server for cost, staleness and unreliable use; Shopify removed MCP from its plugin, because skills and MCP overlap; Playwright says that its command line tool with skills uses fewer tokens; Bootstrap and Lit have none.

For IDEA-005#04: the common shape is a mix. The guidance for agents is inside or beside the package, and the `skills` tool or a plugin marketplace installs it. The MCP server, where one exists, is a package of its own, a hosted server, or a subcommand of the project's command line tool. One package that holds the server and the skills, as the kickoff prompt describes it, is not what most projects do; the nearest cases are the projects whose command line tool holds the server and whose package holds the documentation.

HOW A CONSUMER INSTALLS EACH KIND

MCP server in a separate package:
- The consumer adds a stdio entry to the host configuration. The entry runs npx (most subjects), dnx (Fluent UI Blazor), jbang (Quarkus), docker (Terraform) or `dart mcp-server` (Flutter).
- Or the consumer runs the host command, for example `claude mcp add`.
- Some projects write the configuration with their own command: `antd setup`, `@primeui/cli plugin install`, `kendo mcp config`, `sf mcp init`, `@vuetify/mcp config`, `php artisan boost:install`, `npx storybook add @storybook/addon-mcp` and `nve project.setup`.
- Payload's server is a plugin that the consumer adds to payload.config.

MCP server in a CLI or dev server:
- The host starts the CLI subcommand. Examples: `npx -y @angular/cli mcp`, `antd mcp`, `npx shadcn@latest mcp`, `drizzle-kit mcp`, `npx -y convex@latest mcp start`, `npx -y firebase-tools@latest mcp`, `genkit mcp`, `nve mcp` and `aspire agent mcp`.
- Some projects have an init that writes the configuration: `ng new --ai-config`, `shadcn mcp init`, `shadcn-vue mcp init`, `aspire agent init --mcp` and `nve project.setup`.
- Vite's endpoint mounts in the dev server when @vitejs/devtools is installed.

Hosted MCP server:
- The consumer adds the URL with `claude mcp add --transport http`, a JSON url entry, a deeplink or a connector.
- Some projects also register it through their own CLI or plugin. Examples: `npx motion-ai`, `clerk mcp install`, `stripe agent setup`, `sanity mcp configure`, `npx auth@latest mcp`, the Cypress plugin and the Cloudflare plugin.

Guidance inside the package:
- It arrives with the package install.
- The agent is pointed at it in one of these ways:
  - TanStack Intent `install` writes a block in AGENTS.md or CLAUDE.md (TanStack, tRPC, Redux Toolkit).
  - `next dev` or `create-next-app` writes a managed AGENTS.md block (Next.js).
  - `turbo` writes the block when agentGuidance is true (Turborepo).
  - `create-payload-app` writes it (Payload 4.x).
  - The skills CLI makes symlinks into node_modules (Web Awesome).
  - `pnpm approve` links the skills (Panda CSS, Vercel AI SDK).
  - `uvx library-skills` reads them from the package (Pydantic AI).
  - `prisma skills sync` copies them (Prisma).
  - `drizzle-kit skills` copies them (Drizzle).
  - A hand-written rules line in AGENTS.md (amCharts, SolidJS).

Guidance in a separate repository:
- `npx skills add <org/repo>`.
- Host plugin commands, for example `claude plugin marketplace add` plus `claude plugin install`, `codex plugin add` and `/add-plugin`.
- `gh skill install`.
- A manual copy.

Guidance on docs pages only:
- Agents fetch llms.txt or .md URLs. Nothing is written into the project.

Guidance copied by a CLI:
- create-astro writes AGENTS.md (Astro).
- `npx @uidotsh/install` writes paid ui.sh skills (Tailwind).
- `salt-ds init` writes an AGENTS.md block (Salt, pre-release only).
