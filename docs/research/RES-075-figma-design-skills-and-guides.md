# RES-075: How skills and guides teach an agent to design with a Figma library

## Question
How do existing skills and guides teach an agent to build designs from a Figma library through a Figma MCP (Figma's own skills, Code Connect, the design system skills of other libraries), and what does each need from the library and from the agent host?

Context: a new design system keeps its design specs and tokens in Figma, and a published Figma library will hold its components and blocks. The owner wants to know whether a "design skill" or "Figma skill" can know every component and block in that library, what each is and how to use it, so that an agent on a Figma MCP builds new Figma designs accurately. Needed by IDEA-009#02 (a trial of a draft skill) and IDEA-009#03 (the decision on the skill and its form).

## Answer
Sufficient answer:
1. Figma's own skills for agents, with version or date and repository: each skill, what it tells the agent, how it finds and places library components, and what it needs from the library (published library, component descriptions, variables, Code Connect mappings).
2. Code Connect: what it is, what it gives an agent, what it needs from the library and the code, and which plan it needs.
3. Skills, rules or guides of at least four other design systems or companies that teach an agent to design in Figma with their library, or a count and where the search looked. For each: how it holds per-component knowledge and how it stays in step with the library.
4. What the agent host needs: which server, sign-in, plan and seat, and the state of the write tools.
5. Limits and failures that the sources name.

Answered from Figma's documentation, Figma's skills at version 2.2.207, and the repositories of other systems, all read on 2026-11-13. No Figma tool was called. Each statement below has a line under Findings, except lines marked UNVERIFIED. Facts already in RES-023, RES-028, RES-030 and RES-046 are cited, not repeated.

### 1. Figma's own skills

| Skill (repository figma/mcp-server-guide, 2.2.207) | What it tells the agent | How it finds and places library components | What it needs from the library |
|---|---|---|---|
| `figma-use` | Rules for every `use_figma` script; mandatory before the call | Import by key (`importComponentByKeyAsync`, `importComponentSetByKeyAsync`); keys over names; set text through `setProperties` with `#uid` property keys | Published components; component-set `description` for intent and usage |
| `figma-generate-design` | Build screens and views from the published design system, not from shapes and raw values | 1. Code Connect files in the codebase give the Figma URL, then the key. 2. `get_libraries`, then `search_design_system` scoped to library keys, one intent per query, with a whole-view query first. 3. An inventory of existing screens. Then a wrapper frame, instances in section frames, variables and styles bound, a read-back and one screenshot | "a published design system with components (or access to a team library)"; variables and text and effect styles; Code Connect files help but are not required |
| `figma-generate-library` | Build the library itself (tokens, components, documentation) | Not for composing screens | Writes `description` with purpose and usage |
| `figma-code-connect` | Write `.figma.ts` templates | `get_code_connect_suggestions`, `get_context_for_code_connect` | Components published to a team library |

Figma documents custom skills for this purpose: "Build screens from existing library components, with checks to catch mismatches". It says custom skills work best with `figma-use`, and it suggests `references/` and `assets/` folders for component rules and lookup tables. No Figma skill reads a shipped list of a library's components; discovery is live, by Code Connect files, library search and existing screens. Figma's guidance on file structure names components, Code Connect, variables, clear names, auto layout, annotations and dev resources as what gives an agent context.

What the search matches: Figma's skill reference says components are searched "by name/description via a recommendation engine (relevance-ranked, not exact match)"; variables are searched by name. Figma's developer page does not say which fields are matched. UNVERIFIED: whether text in a component description changes search ranking in practice.

### 2. Code Connect

- What: a mapping from a Figma component to code, made with the CLI (template files `.figma.ts`, the recommended form; parser files no longer get updates) or with Code Connect UI in Figma (GitHub integration). The HTML integration covers Web Components and shows a Lit example.
- What it gives an agent: the MCP returns the real component and its code in place of guessed code. For building in Figma, `figma-generate-design` uses Code Connect files in the codebase as the first, authoritative route from a code component to a Figma component key.
- What it needs: published library components; a `figma.config.json`; Node.js 18 or newer; a personal access token with Code Connect Write and File content Read; `npx figma connect publish`.
- Plan: Figma's documentation says a Dev or Full seat on Professional, Organization or Enterprise; Professional allows one active library and one active framework. Figma's own `figma-code-connect` skill (2.2.87) says Organization or Enterprise only. The two disagree.

### 3. Skills of other design systems

Three design systems publish a skill that builds Figma designs with their own library. One more company publishes a read-only Figma skill. The search also found library-agnostic skills by an agency and by one author.

| System | Skill | How it holds per-component knowledge | How it stays in step |
|---|---|---|---|
| Telefónica Mística (`mistica-figma`, plugin 1.3.0) | A layer on top of Figma's skills | Written rules: library roles, name suffixes, text-preset scale, which variable collection to bind, layout and grid rules mapped to code components, overlay placement, slot use. Deprecation is flagged in each component's Figma description. No key list: "there is no static catalog" | Reads keys, styles and variables live per run; rules change with commits in the code repository |
| Kajabi Pine (`pine-figma`, Pine 4.11.0) | A layer on top of Figma's skills | Exact library names to use and two "DO NOT USE" libraries to avoid; no per-component list; variant names come from search results; primitives mapped to `pds-text` and `pds-box`; Code Connect files in the repository | Live library search; an audit gate (detached instances, unbound values, off-library styles) with `get_variable_defs` and `get_design_context` |
| Red Hat PatternFly (`pf-figma-design-mode`, plugin 1.0.0) | Manual only, needs `figma-use` and `figma-generate-design` | Two allowed Figma files by URL; larger patterns marked `🧰` in their names come first; stop and ask when something is missing | File names and URLs, searched per run; a separate REST-API audit script (`pf-figma-check`) |
| Bitwarden (`using-figma`, plugin 0.1.0) | Read-only; no designing in Figma | — | — |

None of the three holds a written entry for each component. Each relies on the library's own names, descriptions and properties, read live, plus written rules for what the library cannot say about itself (layout, placement, which libraries to avoid, what to do when a component is missing). The library-agnostic skill natdexterra/work-with-design-systems puts the per-component knowledge into the Figma description with a fixed template (PURPOSE, BEHAVIOR, COMPOSITION, USAGE, CODE GENERATION NOTES), written in plain text because the MCP alters Markdown.

The search found no such skill for Atlassian, Primer, Polaris, Carbon, Fluent, Salesforce or Elastic in the indexes searched; see "Where the search looked".

### 4. What the agent host needs

- Server: the remote server `https://mcp.figma.com/mcp`. `use_figma`, `get_libraries`, `search_design_system` and `html_to_figma` are remote only. The desktop server cannot write (RES-023).
- Sign-in: each person signs in to Figma (Okta Cross App Access can replace this for Claude). The account must already have access to the file and the library.
- Plan and seat for writing: Professional, Education, Organization or Enterprise; edit access to the file; a Full seat to write outside drafts.
- State of writing: beta, free during the beta, later "a usage-based paid feature"; "Output is beta quality and may need manual review and cleanup".
- Rate limits: 200 calls a day and 10 a minute for a Full or Dev seat on Professional; 20 a month for View and Collab seats. Write tools are exempt; `use_figma` is not named in the exempt list. UNVERIFIED: whether `use_figma` counts (also open in RES-023 and RES-025).
- Skills: the host needs skill support; Figma's skills come with the host's Figma plugin, not with a manual server setup (RES-030). The other systems' skills ask for Figma's skills to be installed beside them.

### 5. Limits and failures named by the sources

- Wrong variant: Figma ("easy to miss"; read source-code defaults), edenspiekermann (do not take the default variant blindly).
- Detached instances: `detachInstance()` on a nested instance can detach the parent library instance (Figma); detached rectangles that only look like the system (Pine); detaching to "tweak" is an anti-pattern (Pine, Figma's `figma-generate-library`).
- Local copy in place of a library instance: `generate_figma_design` and `html_to_figma` make plain layers without library links (Figma; code-connect issue #362).
- Silent failures: a wrong property key in `setProperties`; `appendChild()` across calls leaves orphaned frames; binding a variable to a token published only as a style (Mística).
- Import failures: import times out; search finds a component the target file cannot import (edenspiekermann).
- Other: unloaded fonts with brand-bound font families, default white frame fills in dark mode, `gridColumnSpan` reset (Mística); wrong font family loads without error, placeholder text left in instances (Figma).
- Platform limits: 48,000 UTF-8 bytes for one tool call (this replaces the 20 KB that RES-023 recorded); no new images inside `use_figma`; no import of components with images or videos; fonts must be uploaded to the account; components must be published before Code Connect mappings; rate limits as in section 4.

### Remaining unknowns

- UNVERIFIED: whether `search_design_system` ranks on description text for a real library; the only source is Figma's skill reference.
- UNVERIFIED: whether `use_figma` counts against the rate limit.
- The plan that Code Connect needs: Figma's documentation and Figma's own skill disagree (Professional versus Organization or Enterprise).

## Findings

### Figma's own skills (repository figma/mcp-server-guide, version 2.2.207)

- Figma's skills live under `skills/` in github.com/figma/mcp-server-guide. On 2026-11-13 the folder holds 17 skills, and the last commit, "skills: Update Figma skills to 2.2.207", is dated 2026-11-12. `server.json` and `plugin.json` both say version 2.2.207. The installed plugin on this machine is 2.2.157. Source: https://github.com/figma/mcp-server-guide/tree/main/skills and the main-branch archive (`server.json`, `plugin.json`), checked 2026-11-13.
- A second tree, `skills-figquery/`, holds 16 "FigQuery" variants of the skills. Only Cursor reads it; Claude Code, Copilot and Gemini CLI read `skills/`. Both trees are generated from Figma's internal monorepo `figma/figma` by a sync step, and the README says "Do not hand-edit either tree". Source: `skills-figquery/README.md` in the main-branch archive, checked 2026-11-13.
- Three skills cover building with a library: `figma-generate-design` (screens and views from a design system), `figma-use` (rules for every `use_figma` call, mandatory before it) and `figma-generate-library` (building the library itself). `figma-generate-design` sends library-primitive work to `figma-generate-library` and mapping work to `figma-code-connect`. Source: `skills/figma-generate-design/SKILL.md` (last changed 2026-11-09, release 2.2.193), lines 27-31, checked 2026-11-13.
- `figma-generate-design` states its prerequisites: a connected Figma MCP server; "The target Figma file must have a published design system with components (or access to a team library)"; a target file key; and the source code or a description of the view. Source: `skills/figma-generate-design/SKILL.md`, lines 33-38, checked 2026-11-13.
- `figma-generate-design` finds components in this order. (1) Code Connect files in the codebase (`*.figma.ts`, `*.figma.tsx`, Kotlin `@FigmaConnect`, Swift `FigmaConnect`): it reads the Figma URL from each file and resolves the component key with a `use_figma` read of the library file. (2) `get_libraries`, then `search_design_system` restricted to the chosen libraries with `includeLibraryKeys`, starting with one query for the whole view to find a composite that covers two or more sections. (3) An inventory script over an existing screen in the target file, which returns its component keys, bound variables and text and effect styles. (4) Searches only for the remaining gaps. Source: `skills/figma-generate-design/SKILL.md`, lines 75-152, checked 2026-11-13.
- `figma-generate-design` tells the agent how to search: "Use one intent per query. `search_design_system` does not apply OR semantics"; use an exact design-system name, or search by UI role such as "primary submit button". Variable search "matches against variable names ... not categories". It warns that `getLocalVariableCollectionsAsync()` sees only local variables, so an empty result does not mean the library has none. Source: `skills/figma-generate-design/SKILL.md`, lines 171, 190-205, checked 2026-11-13.
- `figma-generate-design` tells the agent to read each component's properties before use: make a temporary instance, read `componentProperties` and those of nested instances, then remove it. It sets text through `setProperties()` with the property keys, not through text layers. It warns to read the default props in the source code, because a wrong variant "produces a visually incorrect result that's easy to miss". Source: `skills/figma-generate-design/SKILL.md`, lines 174-186, 301-321, checked 2026-11-13.
- `figma-generate-design` places components this way: create one auto-layout wrapper frame first, then in each call import the component sets, variables and styles by key (`importComponentSetByKeyAsync`, `importVariableByKeyAsync`, `importStyleByKeyAsync`), pick a variant by name or fall back to `defaultVariant`, create instances inside section frames, and bind spacing and colour to variables. It builds by hand only the wrapper, section frames and layout grids. Anything that repeats and is not in the library becomes a local component with instances. Icons come in as SVG with `createNodeFromSvg` when the library has no icon component. Source: `skills/figma-generate-design/SKILL.md`, lines 219-363, checked 2026-11-13.
- `figma-generate-design` checks its work: a `use_figma` read of the wrapper with node counts, one composition screenshot, a comparison of instance, style and variable keys against the component map, and checks for placeholder text, wrong variants, wrong font family, clipped text and blank images. Source: `skills/figma-generate-design/SKILL.md`, lines 365-386, checked 2026-11-13.
- For a new design with no running UI to copy, `figma-generate-design` tells the agent to write a self-contained HTML document and pass it to `html_to_figma`, when that tool is available. Source: `skills/figma-generate-design/SKILL.md`, lines 19-25, checked 2026-11-13.
- `figma-use` reference "Using Components": prefer component keys to names, "since names are not unique"; import a published library component before making an instance; a component-set key fails with `importComponentByKeyAsync`; TEXT, BOOLEAN and INSTANCE_SWAP property names carry a `#uid` suffix and "Using the wrong key in `setProperties` will silently do nothing"; an instance swap needs the key of the target component. Source: `skills/figma-use/references/working-with-design-systems/wwds-components--using.md`, checked 2026-11-13.
- `figma-use` reference "Components": the `description` of a component or component set "appears in Figma's dev mode and component panel, and is surfaced when reading component metadata"; it should explain intent and non-obvious usage limits; set it on the component set, not on each variant. `figma-generate-library` says: "Put human-readable component purpose and usage guidance in the component or component-set `description`". Source: `skills/figma-use/references/working-with-design-systems/wwds-components.md`, lines 21-40, and `skills/figma-generate-library/SKILL.md`, line 121, checked 2026-11-13.
- `figma-code-connect` writes parserless template files (`.figma.ts` with `figma.code`) only. Its prerequisites: a connected Figma MCP server; "Components must be published ... to a Figma team library"; "Organization or Enterprise plan required — Code Connect is not available on Free or Professional plans"; a URL with `node-id`. It finds unmapped published components with `get_code_connect_suggestions` and reads their property definitions (TEXT, BOOLEAN, VARIANT, INSTANCE_SWAP, SLOT) with `get_context_for_code_connect`. Source: `skills/figma-code-connect/SKILL.md` (last changed 2026-07-30, release 2.2.87), lines 1-80, checked 2026-11-13.

### Code Connect (Figma developer documentation)

- Code Connect "is a bridge between your codebase and Figma's Dev Mode, connecting components in your repositories directly to components in your design files". The connections let the Figma MCP server "guide AI agents with more precise implementation details by giving them direct references to your actual code". Published connections show real code snippets in Dev Mode in place of generated code. The page was served from a Firecrawl cache of 2026-11-12. Source: https://developers.figma.com/docs/code-connect/, checked 2026-11-13.
- Plan and seat: "Available on a Dev or Full seat on the Professional, Organization, and Enterprise plans. Professional plans can have one active library and one active framework." On Professional, the first publish sets the active framework; connections of an older framework stay but "aren't returned by the Figma MCP server". Source: https://developers.figma.com/docs/code-connect/, checked 2026-11-13.
- Two ways to make connections: the Code Connect CLI with files in the repository, and Code Connect UI inside Figma with a GitHub integration, which maps one design component to several code implementations. CLI connections appear in the UI but can be edited only in the CLI. Template files (`.figma.ts`) are the recommended CLI format; "Framework-specific parsers will no longer receive updates or support". Source: https://developers.figma.com/docs/code-connect/ and https://developers.figma.com/docs/code-connect/html/, checked 2026-11-13.
- The HTML integration documents Web Components and has a Lit example (`import figma, { html } from '@figma/code-connect/html'`). Code Connect files are not executed; the CLI treats the snippets as strings. Source: https://developers.figma.com/docs/code-connect/html/, checked 2026-11-13.
- CLI requirements: Node.js 18 or newer; a personal access token with the Code Connect scope set to Write and the File content scope set to Read; `npm install --global @figma/code-connect@latest`; a `figma.config.json` at the project root; publish with `npx figma connect publish --token=...`. Source: https://developers.figma.com/docs/code-connect/quickstart-guide/, checked 2026-11-13.
- Disagreement: the `figma-code-connect` skill (2.2.87) says Code Connect needs Organization or Enterprise and is "not available on ... Professional plans". Figma's developer documentation says Professional, with one active library and one active framework. Source: `skills/figma-code-connect/SKILL.md` line 18 and https://developers.figma.com/docs/code-connect/, checked 2026-11-13.
- What Code Connect gives an agent that builds in Figma: in `figma-generate-design`, a Code Connect file in the codebase is the first and "authoritative" route from a code component to its Figma component URL and key. Without a codebase that holds these files, that skill falls back to library search. Source: `skills/figma-generate-design/SKILL.md`, lines 81-108 and 150, checked 2026-11-13.

### Figma's guide to custom skills and to file structure

- Figma documents custom skills for the MCP server on the page "Create skills for the Figma MCP server": available on Starter, Professional, Education, Organization and Enterprise, and it "Requires an MCP client that supports skills". It says custom skills "teach your agent to build on your existing design system": "search your libraries first, use your variable names and modes, and build with your real components and auto layout". One named example is "Build screens from existing library components, with checks to catch mismatches". Source: https://developers.figma.com/docs/figma-mcp-server/create-skills/, checked 2026-11-13.
- The same page says to try Figma's skills first and that "Custom skills work best alongside the figma-use skill". A skill is a folder with a `SKILL.md` (Claude Code: `.claude/skills/<skill-name>/`). It names sections (When to use, Instructions, Examples, Common edge cases) and supporting folders: `scripts/`, `references/` ("a naming guide, variable structure, component rules") and `assets/` ("lookup tables"). Its example skill `figma-apply-palette` declares `compatibility: Requires the figma-use skill` and `metadata: mcp-server: figma`, and passes `skillNames` to `use_figma` for logging. It advises making high-risk skills manual only, such as with `disable-model-invocation`. Source: https://developers.figma.com/docs/figma-mcp-server/create-skills/, checked 2026-11-13.
- Figma's page on file structure lists what gives an agent context: components for anything that repeats; Code Connect, "the most effective way to get your agent to reuse your real components. Without it, your agent has to guess which code component matches"; variables for spacing, colour, radius and typography; clear layer and component names; auto layout; annotations; and dev resources. The page is written for code generation from Figma. Source: https://developers.figma.com/docs/figma-mcp-server/structure-figma-file/, checked 2026-11-13.

### What the agent host needs (Figma documentation)

- Writing to the canvas: "Professional, Education, Organization, and Enterprise plans"; "Requires edit access to the file"; "Requires a supported MCP client connected to the remote Figma MCP server"; "currently in beta and free to use during the beta period. It will eventually become a usage-based paid feature." The introduction adds that writing needs "a Full seat to write outside your drafts". Source: https://developers.figma.com/docs/figma-mcp-server/write-to-canvas/ and https://developers.figma.com/docs/figma-mcp-server/, checked 2026-11-13.
- The desktop server runs through the Figma desktop app, "is intended for specific organization and enterprise needs", and needs a Dev or Full seat on a paid plan. `get_libraries`, `search_design_system`, `use_figma` and `html_to_figma` are marked "Remote only". Source: https://developers.figma.com/docs/figma-mcp-server/ and https://developers.figma.com/docs/figma-mcp-server/tools-and-prompts/, checked 2026-11-13.
- Sign-in: each person usually signs in to Figma separately; for Claude, Okta Cross App Access can replace that sign-in. The server works only with files the signed-in account can already open; `whoami` shows the account, plans and seats. Source: https://developers.figma.com/docs/figma-mcp-server/rate-limits-access/, checked 2026-11-13.
- Rate limits: View and Collab seats on every plan get up to 20 calls a month. Full and Dev seats get 200 a day and 10 a minute on Professional, 200 a day and 15 a minute on Organization, 600 a day and 20 a minute on Enterprise. "Rate limits apply to tools that read data from Figma. Some tools are exempt, including tools that write to Figma files, such as: add_code_connect_map create_new_file generate_figma_design whoami". `use_figma` is not in that list. Source: https://developers.figma.com/docs/figma-mcp-server/rate-limits-access/, checked 2026-11-13.
- Figma's skills arrive with the host's Figma plugin (Claude Code, Cursor, Codex app, Copilot, Gemini CLI); a manual server setup does not install them. That fact is in RES-030 and is not repeated here. Source: `docs/research/RES-030-mcp-and-skills-shipping-landscape.md`, lines 261-263, checked 2026-11-13.

### Limits and failures named by Figma's documentation and skills

- Current limits on the write-to-canvas page: "Each tool call can return up to 48,000 UTF-8 bytes"; `use_figma` cannot add new images; components that contain images or videos cannot be imported; fonts must be uploaded to the Figma account; "Components must be published manually before Code Connect mappings can be completed"; "Output is beta quality and may need manual review and cleanup". Figma advises testing "on a duplicate of your library or a draft file". Source: https://developers.figma.com/docs/figma-mcp-server/write-to-canvas/, checked 2026-11-13.
- Correction to RES-023: RES-023 recorded an output limit of 20 KB for one tool call on 2026-11-12. The write-to-canvas page now states 48,000 UTF-8 bytes. Source: `docs/research/RES-023-figma-mcp-capabilities.md`, line 52, and https://developers.figma.com/docs/figma-mcp-server/write-to-canvas/, checked 2026-11-13.
- Named failures in `figma-generate-design`: a wrong variant ("Neutral instead of Primary") that is "easy to miss"; placeholder text left in instances; the wrong font family, which loads without error; moving nodes between `use_figma` calls with `appendChild()` "silently fails and produces orphaned frames"; appending children to an instance is not allowed; blank image frames when the image capture is skipped. Source: `skills/figma-generate-design/SKILL.md`, lines 221-223, 319-321, 373-384, checked 2026-11-13.
- Named failures in `figma-use`: a wrong property key in `setProperties` "will silently do nothing"; reading `componentPropertyDefinitions` on a variant throws; `detachInstance()` on a nested instance can also detach the parent library instance, which then becomes a frame with a new ID. `figma-generate-library` lists "Importing remote components and immediately detaching them" as an anti-pattern. Source: `skills/figma-use/references/working-with-design-systems/wwds-components--using.md`; `skills/figma-use/references/gotchas.md`, lines 977-993; `skills/figma-generate-library/SKILL.md`, line 302, checked 2026-11-13.
- Recovery rule: after a failed `use_figma` call, retry directly only if `safeToRetryWithoutCanvasRead` is true; otherwise read the canvas first. Source: `skills/figma-generate-design/SKILL.md`, lines 456-463, checked 2026-11-13.

### Search behaviour of `search_design_system`

- Figma's developer page says `search_design_system` "Searches all connected libraries for components, variables, and styles that match a text query", and `get_libraries` returns libraries added to the file and libraries that can be added, each with name, key, description and source. Both are remote only. The page does not say which fields the search matches. Source: https://developers.figma.com/docs/figma-mcp-server/tools-and-prompts/, checked 2026-11-13.
- Figma's `figma-generate-library` reference says components are "published library components, searched by name/description via a recommendation engine (relevance-ranked, not exact match)". `figma-generate-design` says variable search matches variable names. Source: `skills/figma-generate-library/references/discovery-phase.md` (2.2.207), section "Step 2: Search with `search_design_system`", and `skills/figma-generate-design/SKILL.md` line 199, checked 2026-11-13.

### Skills of other design systems

- Telefónica, Mística: the repository Telefonica/mistica-web ships a Claude Code plugin `mistica-web` (version 1.3.0) under `plugin/` with four skills; `mistica-figma` (frontmatter version 1.0.0, MIT) "Teaches the agent how to build Figma screens with Mistica". Last commits to the skill: 2026-07-10 (Code Connect mappings for all components), 2026-08-18 (overlay placement rules), 2026-09-03. Source: https://github.com/Telefonica/mistica-web/tree/master/plugin and GitHub commits API for `plugin/skills/mistica-figma/SKILL.md`, checked 2026-11-13.
- `mistica-figma` calls itself "the Mistica-specific layer under the generic Figma build skills. It does not replace them — load all together." It applies when the file subscribes to the Mística libraries: Desktop, Mobile, Skins (styles and variables), Icons and Accessibility Annotation. Source: https://raw.githubusercontent.com/telefonica/mistica-web/master/plugin/skills/mistica-figma/SKILL.md, lines 13-34, checked 2026-11-13.
- How `mistica-figma` holds component knowledge: written rules only, no list of keys. "Discover live, per run ... Never hardcode keys; there is no static catalog." It names library roles, the `[D]` suffix of desktop component names, the text-preset scale ("higher N = larger"), which variable collection to bind (`brand`, never `mode`), frame sizes for three form factors, layout and grid rules mapped to the code components `ResponsiveLayout`, `GridLayout` and `Inline`, a list of components that must be direct children of the screen, placement rules for overlays, and the use of slots (`Slot` BOOLEAN with `🔄 Replace Slot` INSTANCE_SWAP). Deprecated components are flagged "in the component description". Source: same file, lines 36-499, checked 2026-11-13.
