# RES-066: Storybook's MCP server and MCP tools that return rendered UI

## Question
How do Storybook's skills and its MCP server work, and in particular its MCP tools that return rendered UI? Who else returns rendered UI from an MCP tool, and how does that work?

Settled context: a new design system has a core of Lit web components and framework packages over it. It will have an MCP server and agent skills. The owner asked to study Storybook's skills and MCP, especially the tools that return rendered UI, to find who else does this and how, and what makes sense for the new system. Needed by IDEA-005#12: whether the new MCP server has tools that return rendered UI.

## Answer
Sufficient answer: (1) Storybook, with its version: its MCP server and where it ships; every tool with name, inputs and return; its skills and what each tells the agent; what the server needs to run. (2) How a tool returns rendered UI: mechanism and specification, its status, which hosts show the UI, and the limits the sources name. (3) Who else returns rendered UI from an MCP tool, design systems first. (4) A separate assessment against the new system's decisions, which names what stays open and does not choose.

The evidence answers all four parts. Versions: Storybook 10.6.7 (`latest`) and 11.0.0-beta.2 (`next`); MCP Apps specification 2026-01-26 (stable); SDK `@modelcontextprotocol/ext-apps` 2.0.4. All checks on 2026-11-13.

1. Storybook. The MCP server is the addon `@storybook/addon-mcp`, which runs inside `storybook dev` at `/mcp`. It has nine tools in three toolsets: dev (`stories-preview`, `stories-changed`, `stories-find-by-component`, `review-create`, `get-storybook-story-instructions`), docs (`docs-list`, `docs-show`, `docs-show-story`) and test (`test-run`). The docs toolset needs a components manifest, which web-components projects do not get in 10.6. Only the docs toolset can be shared, through Chromatic or the library `@storybook/mcp`. Preview, review and test need the running dev server. The skills (`stories`, `write-story`, `setup` in 10.6.7; `component-docs`, `write-stories`, `test-stories`, `ui-review` in 11.0 beta) tell the agent to fetch the instructions, preview or review affected stories after each visual change, use only tool-returned story IDs, and not finish while tests fail.
2. Mechanism. `stories-preview` is an MCP Apps tool. It names a `ui://` resource of type `text/html;profile=mcp-app`. The host renders that HTML in a sandboxed iframe and pushes the tool result to it. The result holds story URLs; the view loads each live story in a nested iframe from the dev-server origin, which it allows through `_meta.ui.csp.frameDomains`. On hosts without MCP Apps the tool returns links. MCP Apps (SEP-1865, extension `io.modelcontextprotocol/ui`) is marked stable as of 2026-01-26. The community matrix ticks Claude (web), Claude Desktop, VS Code Copilot, Microsoft 365 Copilot, ChatGPT, Cursor, Goose, Postman and others; Claude Code has no tick, and Codex and Gemini CLI are not listed. The spec requires a sandboxed iframe, a restrictive default CSP that blocks network and nested frames, and a text fallback for every UI tool. The other route is the core MCP image content type (a screenshot), as Figma's `get_screenshot` uses.
3. Others. NVIDIA Elements, a Lit-based web-component design system, ships MCP Apps views in its CLI's MCP server: an example preview that renders any validated `nve-*` template with the component bundle inside the view, an icon list and a token explorer. Figma Console MCP renders a token browser and a design-system audit dashboard (experimental, local mode only). Salesforce HXL widgets and OpenAI's `@openai/apps-sdk-ui` target MCP Apps hosts. Figma's own server returns screenshots. The WordPress design-system MCP renders nothing.
4. See "Assessment against the decisions of the new system" below, kept apart from the findings.

Could not confirm: whether Claude Code, Codex or Gemini CLI render MCP Apps (only the matrix's absence of a tick or listing); whether Storybook's nested story iframes load in every ticked host (no host test was run); the full Salesforce HXL rendering stack; the share of real users on ticked hosts. No server was run in this research.

## Assessment against the decisions of the new system

This section assesses; the Findings do not. It chooses nothing.

- Agent with no project (AI-written artifacts). Storybook's `stories-preview` depends on a running dev server on the user's machine (Finding: `requiresDevServer: true`, nested iframe to the dev-server origin). An agent without a project has no such server. The Elements pattern does not need one: the view carries the component bundle and renders the template from the tool data (Finding: example-preview view). Claude (web) and ChatGPT, where such agents often run, are ticked for MCP Apps in the matrix. Open: which hosts these agents actually run in for the new system's users.
- No server rendering. MCP Apps renders in the host's browser iframe, so it fits this decision (Finding: sandboxed iframe). A screenshot tool, like Figma's `get_screenshot`, needs something to render the component before it returns an image. For a web-component system that means a browser on the server side of the MCP connection. Open: whether a headless browser in the MCP server counts as "rendering on the server" under this decision.
- One HTML page from a CDN, no build. A view is one HTML5 document (Finding: content requirements). It can inline the bundle, as Elements does, or load it from a CDN by declaring the CDN in `resourceDomains` (Finding: CSP). Both match a page that needs no build. Open: whether hosts accept a CDN domain without warnings; the spec says hosts SHOULD warn when a view needs external domains.
- MCP server inside the npm package. Elements ships its server and views in its CLI package; Storybook ships its server as a dev-server addon. If the view HTML ships in the same package as the components, the preview matches the installed version (Findings: Elements `?raw` views; Storybook addon). OpenAI's docs treat the `ui://` URI as a cache key and ask for a new URI on breaking changes (Finding: ChatGPT docs). Open: whether the package's URI carries its version.
- Documentation website with live examples per component. A view could frame those pages, as Storybook frames its stories, but the spec blocks nested frames unless `frameDomains` is declared, and OpenAI reviews that field (Findings: sandbox proxy; ChatGPT CSP). Rendering inside the view, as Elements does, avoids the nested frame. Open: whether the website's example pages should be reused or the view should render examples itself.
- Applications, outside teams, marketing and content sites. Host support differs, and the coding agent of many teams (Claude Code; Codex and Gemini CLI unlisted) shows no MCP Apps support in the matrix (Finding: matrix). The spec requires a meaningful text result anyway (Finding: graceful degradation). So any UI tool is an addition for some hosts, not a replacement. Open: whether the value for the human (a visible preview) justifies a second code path, given that the model itself sees only the text result; the spec deferred external-URL views partly over "model visibility, inability to screenshot content".
- Further open points: which views would be worth building (example preview, token explorer, icon list are the patterns found); how validation of agent-written markup is shown (Elements pairs `examples_render` with validation messages); security review of views that render agent-supplied HTML.

## Findings

### Storybook's MCP server (10.6.7, with notes on 11.0.0-beta.2)

- On npm, `@storybook/addon-mcp` and `@storybook/mcp` are at 10.6.7 (`latest`, published 2026-11-10) and 11.0.0-beta.2 (`next`, published 2026-11-12). Both depend on `tmcp`, `@tmcp/transport-http`, `@tmcp/adapter-valibot` and `valibot`. The addon has peer dependencies `storybook ^10.6.7` and an optional `@storybook/addon-vitest ^10.6.7`. Source: https://registry.npmjs.org/@storybook/addon-mcp and https://registry.npmjs.org/@storybook/mcp, checked 2026-11-13.
- The docs mark Storybook's AI features as "preview": "The API may change in future releases." That is the wording of the 10.6 docs. Source: https://storybook.js.org/docs/ai/mcp/overview (docsearch version 10.6), checked 2026-11-13.
- The server ships as the addon `@storybook/addon-mcp`, installed with `npx storybook add @storybook/addon-mcp`. It runs inside the dev server at `http://localhost:6006/mcp` over HTTP. Opened in a browser, that URL shows a page that lists the tools. The dev server's host validation (`core.allowedHosts`) applies to it. The docs register it with the agent through `npx mcp-add --type http --url "http://localhost:6006/mcp" --scope project` or by hand, and tell the user to add a block to `AGENTS.md` or `CLAUDE.md` that orders the agent to call `docs-list`, `docs-show`, `get-storybook-story-instructions` and `test-run`. Source: https://storybook.js.org/docs/ai/mcp/overview#installation, checked 2026-11-13.
- The server works in every Storybook project. The docs toolset needs a components manifest, which only the React frameworks, `@storybook/angular-vite` and `@storybook/vue3-vite` generate in 10.6. "Every other framework" has "No manifest support", so a web-components Storybook gets no docs toolset. The manifest is off by default (`features.componentsManifest: true`). Source: https://storybook.js.org/docs/ai/mcp/overview#framework-support, checked 2026-11-13.
- The addon option `toolsets: { dev, docs, test }` turns each toolset on or off; all default to true. `dev` holds `stories-changed`, `get-storybook-story-instructions`, `stories-preview`, `stories-find-by-component` and `review-create` "when their feature requirements are enabled". `docs` holds `docs-list`, `docs-show` and `docs-show-story` when a manifest exists. `test` holds `test-run` when `@storybook/addon-vitest` is installed. Source: https://storybook.js.org/docs/ai/mcp/api#toolsets, checked 2026-11-13.
- Tool names come from core toolset methods: `stories.preview` becomes `stories-preview`, likewise `stories.changed`, `stories.findByComponent`, `test.run` and `review.create`; `get-storybook-story-instructions` is named directly. The 11.0.0-beta.2 addon has the same five method-derived names. Source: `@storybook/addon-mcp@10.6.7` package/dist/preset.js (src/tools/tool-names.ts) and `@storybook/addon-mcp@11.0.0-beta.2` package/dist/preset.js, checked 2026-11-13.
- Tool `docs-list`: input `withStoryIds` (optional boolean, adds story names and IDs under each component). Returns an index of components and unattached docs entries. Source: `storybook@10.6.7` package/dist/chunk-CAhv0_wr.d.ts:6954-7256 and https://storybook.js.org/docs/ai/mcp/overview#toolsets, checked 2026-11-13.
- Tool `docs-show`: input `id` (component or docs entry ID, for example `button`). Returns the component's documentation: props, the first three stories, an index of the other stories and extra docs. Source: `storybook@10.6.7` package/dist/chunk-CAhv0_wr.d.ts:6954-7256 and https://storybook.js.org/docs/ai/mcp/overview#toolsets, checked 2026-11-13.
- Tool `docs-show-story`: input `storyId`, or `componentId` with `storyName`; in a composed Storybook also `storybookId` (default `local`). Returns the full story and its documentation. Source: `storybook@10.6.7` package/dist/chunk-CAhv0_wr.d.ts:6954-7256 and https://storybook.js.org/docs/ai/mcp/overview#toolsets, checked 2026-11-13.
- Tool `stories-preview`: input `stories`, an array of either `{ storyId }` or `{ absoluteStoryPath, exportName, explicitStoryName? }`, each with optional `props` (custom args) and `globals` (for example `theme`, `locale`, `backgrounds`). Output schema: `stories`, each `{ title, name, previewUrl }` or `{ input, error }`. Marked `requiresDevServer: true`. Title "Get story preview URLs". Source: `storybook@10.6.7` package/dist/chunk-CAhv0_wr.d.ts:6954-7256 and https://storybook.js.org/docs/ai/mcp/overview#toolsets, checked 2026-11-13.
- Tool `stories-changed`: no input. Returns stories with a status of new, modified or affected, counts, and unreachable files. Source: `storybook@10.6.7` package/dist/chunk-CAhv0_wr.d.ts:6954-7256 and https://storybook.js.org/docs/ai/mcp/overview#toolsets, checked 2026-11-13.
- Tool `stories-find-by-component`: input `componentPaths` (at least one) and optional `maxDistance` (default 3). Returns, per path, matching stories with their import-graph distance. Source: `storybook@10.6.7` package/dist/chunk-CAhv0_wr.d.ts:6954-7256 and https://storybook.js.org/docs/ai/mcp/overview#toolsets, checked 2026-11-13.
- Tool `review-create`: input `title`, `description`, `collections` (each `title`, `rationale`, `storyIds`) and `changedFiles`. Returns `reviewUrl`, with counts. Marked `requiresDevServer: true`. Source: `storybook@10.6.7` package/dist/chunk-CAhv0_wr.d.ts:6954-7256 and https://storybook.js.org/docs/ai/mcp/overview#toolsets, checked 2026-11-13.
- Tool `test-run` (from `@storybook/addon-vitest`): input optional `stories` (same two shapes) and optional `a11y` (default true). Runs the story tests and returns pass and fail results, with accessibility results when the a11y addon is on. Source: `@storybook/addon-vitest@10.6.7` package/dist/preset.js (`runInputSchema`, `createTestToolset`), checked 2026-11-13.
- Tool `get-storybook-story-instructions`: no input. Returns instructions for writing stories in this project's framework and renderer. Source: `@storybook/addon-mcp@10.6.7` package/dist/preset.js (`getStorybookStoryInstructionsToolMetadata`) and https://storybook.js.org/docs/ai/mcp/overview#get-storybook-story-instructions, checked 2026-11-13.
- Every toolset tool returns text content (Markdown), and `structuredContent` when the method declares an output schema. Source: `@storybook/addon-mcp@10.6.7` package/dist/preset.js (`callToolsetMethod`), checked 2026-11-13.
- The docs say `stories-preview` "Returns story previews rendered in the agent's chat interface, if the agent supports MCP Apps. Otherwise, it returns links to relevant stories in Storybook." So the text result stands in for the view. Source: https://storybook.js.org/docs/ai/mcp/overview#stories-preview, checked 2026-11-13.
- What the server needs: the development and testing toolsets are "only relevant to the locally-running Storybook instance". Only the docs toolset can be shared: through Chromatic, which publishes an MCP server with a published Storybook (private when the Storybook is private), or by self-hosting `@storybook/mcp`. Source: https://storybook.js.org/docs/ai/mcp/sharing, checked 2026-11-13.
- `@storybook/mcp` is a library with no `bin` and no CLI. It registers only `docs-list`, `docs-show` and `docs-show-story` on a server the user owns, over `@tmcp/transport-http`, and reads `./manifests/components.json` (required) and `docs.json` (optional). It needs Node.js 20 or later. Source: `@storybook/mcp@10.6.7` package/README.md lines 7-12 and 85-100, checked 2026-11-13.

### How `stories-preview` renders UI (10.6.7 code)

- The tool is registered with `_meta: { ui: { resourceUri: "ui://stories-preview/preview.html" } }`. Source: `@storybook/addon-mcp@10.6.7` package/dist/preset.js (`addonToolDefinitions`), checked 2026-11-13.
- The server registers a resource at that `ui://` URI with MIME type `text/html;profile=mcp-app`. The resource is one inline HTML page. Its `_meta.ui` sets `prefersBorder: false`, `domain` to the Storybook origin, and a `csp` whose `connectDomains`, `resourceDomains`, `frameDomains` and `baseUriDomains` all hold only the Storybook origin. Source: `@storybook/addon-mcp@10.6.7` package/dist/preset.js (`addPreviewStoriesResource`), checked 2026-11-13.
- The page speaks JSON-RPC over `window.parent.postMessage` with protocol version `2025-11-21`. It sends `ui/initialize`, applies the host's theme and CSS variables from `hostContext`, and sends `ui/notifications/initialized`. On `ui/notifications/tool-result` it reads `structuredContent.stories` and, for each story, adds a nested iframe whose `src` is the story's `iframe.html?id=...` URL on the running Storybook, with `mcp-app=true`. It reports its height with `ui/notifications/size-changed`. Source: `@storybook/addon-mcp@10.6.7` package/dist/tools/preview-stories/preview-stories-app-script.js:84-174, checked 2026-11-13.
- So the rendered story is not in the tool result. The result carries story URLs; the host's sandboxed view loads the live story from the local dev server in a nested iframe. The page's CSS cites the draft MCP Apps specification for its theming fallbacks. Source: same file and package/dist/preset.js (`preview_stories_app_template_default`), checked 2026-11-13.
- The 11.0.0-beta.2 addon still contains the `ui://` resource and `text/html;profile=mcp-app`. Source: `@storybook/addon-mcp@11.0.0-beta.2` package/dist/preset.js, checked 2026-11-13.

### Storybook's skills

- In 10.6.7, `storybook skills [id]` knows three skills: `stories` ("The mandatory, ordered workflow for UI changes: discover affected stories, test, and present results"), `write-story` ("How to write, update, and test Storybook stories for this project: imports, patterns, and conventions") and `setup` ("Setup instructions to write stories for the real components in this project"). The same text serves the MCP and the CLI: over MCP, `write-story` maps to the tool `get-storybook-story-instructions`; otherwise the reference is `npx storybook skills <id>`. The workflow text tells the agent to call the story instructions before editing components or stories, to preview the affected stories after any visual change ("no exceptions") and include every preview URL in the final answer, to use only story IDs returned by tools, and to run the story tests, never a package.json script, and not to report completion while tests fail. Source: `storybook@10.6.7` package/dist/cli/skills/content/index.js:10-60, checked 2026-11-13.
- In 11.0.0-beta.2, the skills in storybookjs/skills are `component-docs`, `write-stories`, `test-stories` and `ui-review` (with `storybook-init` and `storybook-upgrade` named as other skills). Each is a short pointer: it requires Storybook 11.0 or later, says to run CLI commands from the package where Storybook is installed, and tells the agent to run `npx storybook skills <id>` and follow its output. `component-docs` looks up components, props and examples before reading source. `write-stories` gives the rules for stories. `test-stories` runs the story tests with accessibility checks. `ui-review` publishes a Storybook review of the stories a change affects and tells the agent to end its answer with the three lines `review create` prints. Source: https://github.com/storybookjs/skills/blob/v11.0.0-beta.2/skills/ (SKILL.md of each), checked 2026-11-13.
- How the skills reach a project (10.6.7 prints them; 11.0 copies them with the `skills` CLI) is recorded in RES-030 and not repeated here. Source: docs/research/RES-030-mcp-and-skills-shipping-landscape.md:72-81, checked 2026-11-13.

### The mechanism: MCP Apps (`io.modelcontextprotocol/ui`)

- MCP Apps is SEP-1865, an extension to MCP with the identifier `io.modelcontextprotocol/ui`. Its status line reads "Stable (2026-01-26)"; it was created 2025-11-21. The repository holds two versions, `specification/2026-01-26` and `specification/draft`. It is optional and must be negotiated through the extension capabilities. Source: https://github.com/modelcontextprotocol/ext-apps/blob/main/specification/2026-01-26/apps.mdx lines 1-50, checked 2026-11-13.
- The SDK `@modelcontextprotocol/ext-apps` is at 2.0.4 (`latest`, published 2026-10-27). Its `App` class is "a convenience wrapper, not a requirement"; a View can speak the postMessage protocol directly, with any framework or none. Source: https://registry.npmjs.org/@modelcontextprotocol/ext-apps and https://modelcontextprotocol.io/extensions/apps/overview#framework-support, checked 2026-11-13.
- How it works: a tool declares `_meta.ui.resourceUri` pointing to a `ui://` resource. The host can fetch and preload that resource before the tool is called. The resource is one HTML5 document with MIME type `text/html;profile=mcp-app`, given as `text` or base64 `blob`. The host renders it in a sandboxed iframe. View and host talk JSON-RPC over `postMessage`: `ui/initialize`, then the host pushes `ui/notifications/tool-input` and `ui/notifications/tool-result`; the View can call `tools/call`, `ui/message`, `ui/open-link` and other methods. Source: https://modelcontextprotocol.io/extensions/apps/overview#how-mcp-apps-work and spec lines 55-60, 959-1231, checked 2026-11-13.
- The template and the data are separate by design. The spec chose "predeclared resources" over returning the HTML inside the tool result (the older MCP-UI way) so hosts can prefetch, cache and review templates. It also deferred "external URLs" as a content type, citing "model visibility, inability to screenshot content, and review process". Source: spec "Design Decisions" lines 1584-1633, checked 2026-11-13.
- Fallback is required: "Servers SHOULD provide text-only fallback behavior for all UI-enabled tools" and "Tools MUST return meaningful content array even when UI is available". Servers should check the client's UI capability and may register text-only variants. Source: spec "Server Behavior" lines 1529-1560, checked 2026-11-13.
- `_meta.ui.visibility` can be `["model", "app"]` (default) or `["app"]`; a tool visible only to the app is hidden from the agent's tool list but callable from the View. Source: spec lines 332-401, checked 2026-11-13.
- Sandbox and security: all View content "MUST be rendered in sandboxed iframes". A web host must use a sandbox proxy on a different origin. The host builds a CSP from `_meta.ui.csp` (`connectDomains`, `resourceDomains`, `frameDomains`, `baseUriDomains`); without it, the default is `default-src 'none'`, inline scripts and styles only, `connect-src 'none'`, and nested frames are blocked (`frame-src 'none'`) unless `frameDomains` is set. Hosts "MUST NOT allow undeclared domains". `permissions` may request camera, microphone or geolocation. `domain` asks for a dedicated sandbox origin, in a host-dependent format (examples: `{hash}.claudemcpcontent.com`, `www-example-com.oaiusercontent.com`). Named risks: malicious HTML, sandbox escape, unauthorized tool calls, data exfiltration, phishing, social engineering and resource use. Source: spec lines 200-320, 470-489 and 1680-1764, checked 2026-11-13.
- Theming: the host passes CSS variables (for example `--color-background-secondary`, `--font-sans`) and a theme in `hostContext`; the View applies them. Source: spec "Theming" lines 791-920, checked 2026-11-13.
- Host support, from the community-maintained matrix (last commit a40b29a of 2026-11-11): MCP Apps is ticked for Claude (web), Claude Desktop, VS Code GitHub Copilot, Microsoft 365 Copilot, Goose, Postman, MCPJam, ChatGPT, Cursor, Archestra.AI, PostHog Code, Kiro Crew and Glean. MCP Inspector is "Partial". Claude Code, fast-agent and mcpc have no tick. OpenAI Codex, Gemini CLI and Windsurf are not in the matrix. Source: https://github.com/modelcontextprotocol/modelcontextprotocol/blob/main/docs/extensions/client-matrix.mdx, checked 2026-11-13.
- Disagreement: the MCP Apps overview page names only eight supporting clients (Claude, Claude Desktop, VS Code GitHub Copilot, Microsoft 365 Copilot, Goose, Postman, MCPJam, Archestra.AI) and points to the matrix for the full list. Source: https://modelcontextprotocol.io/extensions/apps/overview#client-support (Firecrawl cache of 2026-11-13), checked 2026-11-13.
- The core MCP specification (2025-11-25) also lets any tool return image content (`type: "image"`, base64 `data`, `mimeType`), audio, resource links, embedded resources and `structuredContent`. A screenshot in a tool result uses this core image type and needs no extension. Source: https://modelcontextprotocol.io/specification/2025-11-25/server/tools#image-content, checked 2026-11-13.
- OpenAI's ChatGPT docs: ChatGPT "implements the open MCP Apps standard". `_meta["openai/outputTemplate"]` and `window.openai.*` remain as compatibility aliases and ChatGPT-only extensions. The docs say to "Keep the MCP tools useful without a component so ChatGPT and Codex can complete the workflow without UI". They recommend separate data tools and render tools; only the render tool carries `_meta.ui.resourceUri`. They say to treat the resource URI as a cache key and publish a new URI on a breaking change. Nested frames are blocked by default; `frameDomains` must be justified in plugin review. Source: https://developers.openai.com/plugins/build/chatgpt-ui (Firecrawl cache of 2026-11-12), checked 2026-11-13.
- MCP-UI is the earlier community project. The spec credits it with the bidirectional model and three content types (HTML, external URL, remote DOM), and names its adopters Postman, HuggingFace, Shopify, Goose and ElevenLabs. OpenAI's Apps SDK (November 2025) also informed the spec. The `@mcp-ui/client` package now gives hosts React components that render MCP Apps views. Source: spec lines 17-33 and https://modelcontextprotocol.io/extensions/apps/overview#client-support, checked 2026-11-13.
- On npm: `@mcp-ui/server` 6.1.0 (2026-02-13) and `@mcp-ui/client` 7.1.1 (2026-05-09), both Apache-2.0. Source: https://registry.npmjs.org/@mcp-ui/server and https://registry.npmjs.org/@mcp-ui/client, checked 2026-11-13.

### Others that return rendered UI from an MCP tool

Design systems and design tools:

- NVIDIA Elements (Apache-2.0; `@nvidia-elements/core` 2.24.0 on `main`, a web-component library that depends on `lit`; MCP server in `@nvidia-elements/cli` 2.2.17, run as `nve mcp` over stdio). Its MCP docs list 17 tools, among them `api_list`, `api_get`, `api_validate`, `api_tokens_list`, `api_icons_list`, `examples_list`, `examples_get`, `examples_render` ("Render a custom Elements HTML template inline in the MCP Apps preview view"), `playground_create` and `project_setup`, plus four prompts. The same command advertises `io.modelcontextprotocol/ui` with `text/html;profile=mcp-app` and registers three views: `ui://elements/example-preview` (for `examples_get` and `examples_render`: renders stored examples or validated custom `nve-*` HTML "with the Elements bundle and themes already loaded"), `ui://elements/icons-list` (searchable icons with copyable markup) and `ui://elements/tokens-list` (token values, theme switch, copyable `var(--nve-*)`). "Hosts without Apps support still receive the normal text and structured tool output." The views are part of the server, with no separate setup. Source: https://github.com/nvidia/elements/blob/main/projects/site/src/docs/mcp/index.md (last commit 5cf5f51 of 2026-09-29) and https://github.com/nvidia/elements/blob/main/projects/core/package.json and https://github.com/nvidia/elements/blob/main/projects/cli/package.json, checked 2026-11-13.
- In the Elements code, each view is an HTML file imported raw into the CLI build; the example-preview view imports the Elements themes, styles and the full component bundle and `@modelcontextprotocol/ext-apps`, defines a custom element that renders the template string it receives, and applies the host theme to `nve-theme`. The registered resource contents carry only `uri`, `mimeType` and `text`, with no `_meta.ui.csp`. The docs say each view is "a self-contained HTML document" and that message handling "validates the parent origin". So the rendered UI needs no running app server: the template travels in the tool data and the components are inside the view. Source: https://github.com/nvidia/elements/blob/main/projects/cli/src/mcp/ui/index.ts, .../ui/examples-render.html lines 1-60 and .../mcp/index.ts lines 22-40, checked 2026-11-13.
- Elements also documents using its web components inside anyone's MCP App: "Because Elements registers native custom elements ... the app view does not need a React, Vue, or Svelte adapter to render." The page shows an example server with `registerAppTool` and `registerAppResource`. Source: https://github.com/nvidia/elements/blob/main/projects/site/src/docs/integrations/mcp-apps.md, checked 2026-11-13.
- Figma Console MCP (Southleft; npm `figma-console-mcp` 1.46.0, 2026-10-29, MIT; not Figma's own server). Two MCP Apps: `figma_browse_tokens` renders a Token Browser (variables by collection, mode columns, swatches, click to copy) and `figma_audit_design_system` renders a Design System Dashboard (a 0-100 score over six categories, with a refresh button). A "Component Gallery" for previewing components is on its roadmap, not shipped. Source: https://docs.figma-console-mcp.southleft.com/mcp-apps and https://registry.npmjs.org/figma-console-mcp, checked 2026-11-13.
