# RES-070: Skills and MCP tools of other design systems

<!-- Add outcome: answered, partial or blocked to frontmatter when an answer or a block is known. Only answered work can become resolved. -->

## Question
Which skills do other design systems ship and what does each skill do, and which tools do their MCP servers expose and what does each tool do?

Settled context: a new design system with a core of Lit web components and framework packages over it will have an MCP server and agent skills for its consumers and their coding agents. RES-030 covers how libraries package and distribute these; this record covers what the skills and tools are and do.

## Answer
Answered on 2026-11-13 for fifteen systems. Fourteen ship an MCP server: shadcn/ui, Chakra UI, MUI, Ant Design, Mantine, Nuxt UI, GitHub Primer, Atlassian, Adobe Spectrum, PrimeTek (PrimeVue, PrimeReact, PrimeNG), HeroUI, Ark UI, IBM Carbon and Shopify (Polaris). Eleven ship skills: shadcn/ui, Chakra UI, MUI, Ant Design, Mantine, Nuxt UI, Adobe Spectrum, IBM Carbon, Web Awesome, Shopify, and Storybook (out of scope here). Web Awesome is the only web-component library in the set; it ships skills and `llms.txt` but no MCP server. Each tool, prompt, resource and skill is under Findings, with its version and source. Storybook is listed by tool names only. Angular CLI is added as a framework for comparison, because its package contains a written audit of tool design.

### What sources say about why, and what did not work
- Stale model knowledge: Carbon ("Carbon training data is stale on props, imports, variants, composition rules, and component existence"), Chakra ("to help avoid AI hallucination"), Shopify ("catches hallucinated components, props, and prop values").
- Agents skip the server: MUI saw hosts pick built-in edit tools over `generateReactCode` and suggests a `CLAUDE.md` block. Web Awesome: "the agent never looked".
- Agents break their own rules in long output: Web Awesome adds a mechanical verification pass for this reason.
- Server and skill divide the work: Carbon, "The server supplies the facts; the skill tells the agent when to ask for them"; Next.js (RES-030), framework knowledge in docs, workflows in skills.
- Context cost: Angular CLI measures 200 to 500 tokens per tool and plans fewer tools; Nuxt UI, Primer and Atlassian add section filters, batches and a `plan` tool to cut calls and response size; Carbon sets result sizes; Web Awesome prefers progressive skills over a single `llms.txt`.
- Query pitfalls: Carbon's capability matrix lists failure modes per tool (framework words in queries, partial `component_id` matches, DataTable missing from the index).
- Successor without parity: Adobe's new design-data server drops value queries and prop validation.

### Disagreements and gaps
- Chakra UI: the README names seven tools (`get_components`, `list_blocks`); the 2.1.1 code registers nine with other names.
- Atlassian: the README lists fewer tools than the code registers (21).
- shadcn: descriptions refer to an `init_project` tool that 4.23.0 does not register.
- MUI: `useMuiDocs` is absent when the docs backend is unreachable at start.
- Not confirmed: the input schemas of Carbon's hosted server (no public code; inputs come from its docs and skill); which Shopify validator names are registered together; the full descriptions of HeroUI's `get_theme_variables` and of Shopify's `learn_shopify_api`; the inputs of Ark UI's `search_docs` and `list_examples` beyond those named. ## Findings
Method: npm tarballs (the `latest` tag of 2026-11-13) were unpacked in the session scratchpad and read. No server was started and nothing was installed. Tool names, inputs and descriptions come from the registration code; where the code takes the description from another package, the README is the source.

### `llms.txt` across the systems
- On 2026-11-13 these URLs returned HTTP 200 with a text `llms.txt`: ant.design (537 lines), mui.com/material-ui (169), atlassian.design (158) and atlassian.design/llms-a11y.txt (784), react-spectrum.adobe.com (122), react-aria.adobe.com (218), heroui.com/react (388), ark-ui.com (359), chakra-ui.com (19), webawesome.com (4,602), carbondesignsystem.com (165), mantine.dev (509), ui.shadcn.com (162), ui.nuxt.com (280). primer.style/llms.txt and primevue.org/llms.txt returned 404; Primer serves one `llms.txt` per component page instead (its MCP server reads `/product/components/<slug>/llms.txt`), and PrimeTek serves `llms.txt` through MCP resources. Chakra's file is an index of split files: `llms-full.txt`, `llms-components.txt`, `llms-charts.txt`, `llms-styling.txt`, `llms-theming.txt` and `llms-v3-migration.txt`. Source: HTTP GET of each URL, @primer/mcp 1.1.2 package/src/server.ts:141 and @primeuix/mcp 2.0.1 package/README.md, checked 2026-11-13.

### MUI (`@mui/mcp` 0.1.10, published 2026-11-13)
- The server registers three tools and no prompts or resources. `useMuiDocs` (input `sources`: llms.txt URLs or bare package names such as `@mui/material`) returns the docs catalogue, URLs with summaries, for those packages; "Agents typically use this first to find the right docs page". `fetchDocs` (input `urls`) returns the full content of those docs pages. `generateReactCode` (inputs `prompt`, optional `threadId`, `designContext`, `muiPairing` and `model`) returns generated React and Material UI files, a short explanation, the `threadId` and the effective `muiPairing`; it can be grounded in a Figma frame and needs `MUI_RECIPES_API_KEY`. Source: @mui/mcp 0.1.10 package/README.md:5-13 and package/docs/register.js, package/codegen/register.js, checked 2026-11-13.
- `useMuiDocs` registers only after the docs catalogue loads from `chat-backend.mui.com`, announced through `tools/listChanged`; when the catalogue is unreachable at start, only `fetchDocs` and `generateReactCode` exist. `generateReactCode` also declares an `outputSchema` (files, threadId, muiPairing). Source: @mui/mcp 0.1.10 package/docs/register.js and package/codegen/register.js, checked 2026-11-13.
- What did not work, in MUI's words: "hosts like Claude Code Agent (WebStorm/Cursor) sometimes pick built-in file-edit tools instead of the MCP"; MUI suggests a `CLAUDE.md` block that tells the agent to prefer `generateReactCode` and to pass `muiPairing` from `package.json`, because otherwise "the agent will silently get v9 code on a v7 codebase". In MUI's tests the host agent discards the generated `App.tsx`, renames files to project conventions, and keeps the component bodies. Source: @mui/mcp 0.1.10 package/README.md, sections "Targeting a MUI version" and "Tips for best results", checked 2026-11-13.

- MUI's consumer skills live in `skills/` of mui/material-ui (last change 2026-09-03), four skills at version 1.0.0, each a short `SKILL.md` (35 to 38 lines: when to apply, a section index) that points at a full guide in `AGENTS.md`, plus `reference.md` and `metadata.json`. `material-ui-styling` chooses between `sx`, `styled`, theme overrides and global CSS. `material-ui-theming` covers `createTheme`, palette, colour schemes, CSS variables, dark mode and TypeScript augmentation. `material-ui-nextjs` covers the App and Pages routers with `@mui/material-nextjs`, the Emotion cache, `next/font`, CSS layers and Link props. `material-ui-tailwind` covers Tailwind v4 cascade layers and v3 interoperability. The repository's `.agents/skills/` and `.claude/skills/` hold maintainer skills (`material-ui-review`, `mui-release`). Source: https://github.com/mui/material-ui/tree/master/skills (README.md and the four SKILL.md files), checked 2026-11-13.

### Chakra UI (`@chakra-ui/react-mcp` 2.1.1, last published 2025-11-03)
- The code registers nine tools; the README lists seven, under partly different names (`get_components`, `list_blocks`). From the code: `list_components` (no input) returns all component names. `get_component_props` (input: a component name from that list) returns props such as size and variant. `get_component_example` (input: component name) returns example code for basic and advanced use. `get_theme` (no input) returns the theme: colours, fonts, text styles, layer styles, semantic tokens. `customize_theme` (input `category`, one of the token categories or `conditions` and `globalCss`) returns how to define or change tokens in that category. `installation` (input `framework`, such as `next-app`) returns setup steps for Vite, Next.js App Router, Pages Router or general use. `list_component_templates` (no input) and `get_component_templates` (inputs `category` and `id`) list and return Chakra UI Pro blocks; the second is disabled without `CHAKRA_PRO_API_KEY`. `v2_to_v3_code_review` (input `scenario`, from a fixed list such as `extend_theme_to_create_system`) returns before and after code for one v2 to v3 migration case. No prompts or resources are registered. Source: @chakra-ui/react-mcp 2.1.1 package/dist/stdio.js:280-300, :357-372, :404-416, :451-475, :520-523, :727-736, :755-761, :788-800, :1745-1752 and package/README.md, checked 2026-11-13.
- The description of `v2_to_v3_code_review` gives its reason: it tells the agent to "ALWAYS use this tool to review any generated code" and says the before and after snippets help "to avoid AI hallucination". Source: @chakra-ui/react-mcp 2.1.1 package/dist/stdio.js:1746, checked 2026-11-13.

- Chakra UI's skills live in `skills/` of the chakra-ui/chakra-ui repository (last change 2026-04-28), three skills for Chakra UI v3 that "activate automatically". `chakra-ui-builder` (374 lines; references theming.md, charts.md and component-decision-tree.md, the last covering "all ~114 Chakra components with head-to-head comparisons") reads `package.json` first (Chakra version, framework, TypeScript, package manager), asks when requirements are vague, then covers install, CLI snippets, the Provider, layout primitives, "use tokens, not raw values", responsive styles, forms, accessibility, where Next.js needs `"use client"`, and when to extract components, use recipes or customise the theme. `chakra-ui-migrate` (494 lines) migrates v2 to v3: inspect the project, update packages, run the codemod, update the Provider, migrate colour mode, rename props, compound components, theming and recipes. `chakra-ui-refactor` (284 lines) reviews Chakra code or converts plain HTML and CSS, Tailwind, CSS Modules or styled-components to Chakra v3, with a review output format and the rule "Preserve behavior — non-negotiable". `https://chakra-ui.com/llms.txt` returns HTTP 200. Source: https://github.com/chakra-ui/chakra-ui/tree/main/skills (README.md and the three SKILL.md files), checked 2026-11-13.

### shadcn/ui (`shadcn` 4.23.0, published 2026-10-27; skills at commit of 2026-10-14)
- `shadcn mcp` registers seven tools and no prompts or resources. All work on the registries configured in the project's `components.json`. `get_project_registries` (no input) returns the configured registry names, or an error without `components.json`. `list_items_in_registries` (optional `registries`, `types`, `limit`, `offset`) lists items. `search_items_in_registries` (`query`, optional `registries`, `types`, `limit`, `offset`) returns fuzzy matches on names and descriptions. `view_items_in_registries` (`items`, such as `@shadcn/button`) returns name, description, type and file contents. `get_item_examples_from_registries` (`query` such as `accordion-demo`, optional `registries`) returns demo code with its dependencies. `get_add_command_for_items` (`items`) returns the `shadcn add` command that installs them; the server does not install. `get_audit_checklist` (no input) returns a checklist to run "after all required steps have been completed": correct named or default imports, `next/image` remote patterns, dependencies installed, lint, TypeScript errors, "Use the Playwright MCP if available". Source: shadcn 4.23.0 package/dist/chunk-I2VXPUS4.js (the `registerTool` calls and the checklist text), checked 2026-11-13.
- Three tool descriptions and an error text tell the agent to "use init_project" when `components.json` is missing, but the 4.23.0 bundle registers no `init_project` tool. Source: shadcn 4.23.0 package/dist/chunk-I2VXPUS4.js, checked 2026-11-13.
- The repository holds two skills, installed with `npx skills add shadcn/ui`. `shadcn` (296 lines, `user-invocable: false`, `allowed-tools` limited to the shadcn CLI through npx, pnpm dlx or bunx) runs `npx shadcn@latest info --json` as dynamic context at load, so the agent gets framework, Tailwind version, aliases, base library (`base`, `radix` or `aria`), icon library and installed components. It sets four principles (existing components first, compose, built-in variants, semantic colours) and critical rules with linked Incorrect and Correct files: styling (no `space-*`, `size-*`, no `dark:` overrides, `cn()`, no manual `z-index` on overlays), forms (`FieldGroup` and `Field`, `InputGroup`, `ToggleGroup`, `data-invalid` with `aria-invalid`), composition (items inside groups, `asChild` or `render` by base, titles on dialogs, full Card, `AvatarFallback`), icons (`data-icon`), chat UI primitives and presets. Its workflow: check installed components, `search`, `docs <component>` and fetch the URLs before writing, `add` with `--dry-run` and `--diff`, fix aliases in third-party registry items, read and review added files, never guess a registry, ask before switching presets, never `--overwrite` without approval. A section turns a `DESIGN.md` or brand spec into a themed app and a design system page. Reference files: rules/*.md, cli.md, registry.md, customization.md, design-system.md, design-system-page.md, mcp.md; `evals/evals.json` holds eight eval prompts with expected outputs. Source: https://github.com/shadcn-ui/ui/blob/main/skills/shadcn/SKILL.md and https://github.com/shadcn-ui/ui/tree/main/skills, checked 2026-11-13.
- `migrate-radix-to-base` migrates shadcn wrappers and Radix compositions to `@base-ui/react`, one component or a whole project. Preflight: run `shadcn info --json`, detect the package manager, require a clean git tree with one commit per component, run a baseline typecheck and build first, install Base UI beside Radix and remove Radix only after the last component; "never guess a mapping", check `node_modules/@base-ui/react/**/*.d.ts` when a mapping file lacks a prop. Eight reference files map class names, consumer props and component families. Source: https://github.com/shadcn-ui/ui/blob/main/skills/migrate-radix-to-base/SKILL.md, checked 2026-11-13.
- The docs say why the skill exists: it "reads your project's `components.json` and provides the assistant with your framework, aliases, installed components, icon library, and base library so it can generate correct code on the first try". `ui.shadcn.com/llms.txt` (162 lines) indexes the docs pages with one-line summaries. Source: https://github.com/shadcn-ui/ui/blob/main/apps/v4/content/docs/(root)/skills.mdx and https://ui.shadcn.com/llms.txt, checked 2026-11-13.

### Nuxt UI (hosted server at ui.nuxt.com/mcp, source on branch v4, last change to `docs/server/mcp` 2026-10-08; `@nuxt/ui` 4.12.0)
- The hosted server (built with `@nuxtjs/mcp-toolkit`) defines thirteen tools. Components: `search-components` (optional `category` such as form, overlay or chat; optional `search`) returns ranked components and matches alternate names from other ecosystems ("segmented control" finds FieldGroup, "combobox" finds InputMenu, "dialog" finds Modal). `get-component` (`componentName` in any casing; optional `sections`: usage, examples, api, theme, changelog) returns the docs. `get-component-metadata` (`componentName`, optional `full`) returns props, slots and events, compact by default. Composables: `search-composables` (optional single keyword) returns composables such as `useToast`. Docs: `search-documentation` (optional `search`, `section`) returns pages, all pages without input; `get-documentation-page` (`path`, optional `headings`) returns one page's Markdown or only the named h2 sections. Examples: `list-examples` (no input) returns names only; `get-example` (`exampleName`) returns its source code. Templates: `list-templates` (optional `framework`) and `get-template` (`templateName`) return template records with preview and repository links but no setup or code. `get-migration-guide` (no input) returns the guide from the previous major version. `search-icons` (`query`, `collection` defaulting to `lucide`, optional `limit`) returns icon names in the `i-{prefix}-{name}` format. Source: https://github.com/nuxt/ui/tree/v4/docs/server/mcp/tools (13 files), checked 2026-11-13.
- It serves five resources: `resource://nuxt-ui/components` (components with metadata and categories), `.../composables`, `.../documentation-pages`, `.../examples` (names only) and `.../templates`. It serves three prompts: `find-component-for-usecase` (`usecase`) sends the use case with the full component list; `implement-component-with-props` (`componentName`, optional `requirements`) asks for a complete implementation with the component's docs attached; `setup-project-with-template` (`projectType`) sends the template list. A client can send the header `x-mcp-tools` with a comma-separated list to receive only those tools; an unknown name returns HTTP 400. Source: https://github.com/nuxt/ui/tree/v4/docs/server/mcp (resources/, prompts/, index.ts), checked 2026-11-13.
- Several tool descriptions say why the tool is split: `get-component` points to `get-component-metadata` "when you only need structured props"; `get-documentation-page` and `get-migration-guide` offer `headings` "to reduce response size"; `search-composables` asks for "one keyword rather than a sentence" because matching is a substring match. Source: same files, checked 2026-11-13.
