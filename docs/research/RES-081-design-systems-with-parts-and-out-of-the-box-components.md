# RES-081: Design systems that export granular parts and out-of-the-box components from one package

## Question
Which of the more popular design systems and component libraries export, from one package, both the granular composable parts of a component and an out-of-the-box component for the same concept, which is one component or a much simpler composition? What do they call each of the two, and which name do documentation and widely cited writing give to this pattern?

Peter asked for this research on 2026-11-20, with `/deep-research`, in his reply to IDEA-003#06. He doubts the statement that no system ships both from one package. That statement rests on RES-072 and RES-069, which cover the five reference systems and thirteen libraries of web components only.

Needed by: IDEA-003#06, where the out-of-the-box component lives; IDEA-003#24, the names for the glossary (DEC-148); IDEA-001#09, the review of the parts.

## Answer
Partial, after the first run of 2026-11-20. The statement that Peter doubted does not hold outside the earlier sets: two systems export both ways from one package.

- Mantine: `@mantine/core` exports a `Modal` that props configure, and on the same export the parts `Modal.Root`, `Modal.Overlay`, `Modal.Content`, `Modal.Header`, `Modal.Title`, `Modal.CloseButton` and `Modal.Body`. Its documentation calls the parts "compound components" and gives them "to have full control over the Modal rendering". The `Modal` with props is first on the page and in nearly each example.
- Carbon React: `@carbon/react` exports `Modal`, which props configure, and `ComposedModal`, which a developer composes from `ModalHeader`, `ModalBody` and `ModalFooter`. Its documentation calls them "modal variants".
- Not confirmed for either: that the out-of-the-box component is built on the same parts that the package exports. The source code would show it.

Systems that split the two ways:
- Chakra UI 3: the package exports only the parts. The out-of-the-box form, a "closed component composition", is a snippet that a command copies into the project.
- MUI and Adobe: the layer with no style and the styled layer are separate packages. The evidence for both is old: MUI 6, and a post of Adobe of 2020.
- HeroUI 3: only compound components for a component such as Modal, under its principle "Composition over configuration".

The name of the pattern: the sources use no single name. See the last finding.

Sufficient answer: for each checked system, with its version and the date of the check: the components that it offers in both ways, with the export names of each way; whether both come from one package or from two; what its documentation calls each way and says about when to use which; and which way it presents as the default. Then the name that sources give to the pattern, each with a quote. Then the systems that offer only one of the two ways.

What the first run did not reach, so the answer is partial: no claim was verified for Ant Design, Fluent UI (React 9 and Web Components), the Atlassian Design System, Polaris, Primer, PrimeReact, Carbon Web Components, Base UI and React Aria Components. No widely cited text on the pattern was among the verified claims. The run fetched 21 sources and verified 25 of 104 extracted claims; none was refuted.

## Findings
First run: the `deep-research` workflow, run `wf_ae21e3d2-395` of 2026-11-20, from `.artifacts/v1/research/deep-research-opus-medium.js`. Its 103 agents ran on Opus 5.5 at the effort `medium`. Each claim below passed three checks; the vote is in each line. Sources were read on 2026-11-20.

- Mantine (@mantine/core) exports both ways from one package and on one export. The ready-made Modal is configured by props: opened, onClose, title, centered, size, fullScreen, withCloseButton, overlayProps, transitionProps and closeButtonProps. The same Modal export carries the granular parts Modal.Root, Modal.Overlay, Modal.Content, Modal.Header, Modal.Title, Modal.CloseButton and Modal.Body. The docs call the parts 'compound components' and say to use them 'to have full control over the Modal rendering'. The props-configured Modal appears first in the Usage section and in almost every example, so it is the de facto default, although the docs never use the word 'default'. The docs also say that Modal.Stack works only with Modal, not with components built from Modal.Root. Evidence: Claims 0 and 1, both voted 3-0 on the primary docs as scraped on 2026-11-20. Quote: 'You can use the following compound components to have full control over the `Modal` rendering: `Modal.Root` – context provider ...'. The page does not state that the simple Modal is built internally on these parts. The Mantine version shown was not recorded. Confidence high; vote 3-0. Source: https://mantine.dev/core/modal/, checked 2026-11-20.
- Carbon React (@carbon/react) exports both ways from one package, as two sibling components. Modal is configured by props such as modalHeading, primaryButtonText, secondaryButtonText, passiveModal and danger. ComposedModal is composed from ModalHeader, ModalBody and ModalFooter. The docs call them 'both modal variants'. Searches of the two docs pages found no use of 'compound', 'primitive' or 'layered'. ComposedModal 'provides more flexibility when it comes to custom content'. The docs tie the choice to button layout. With Modal 'you have limited control over the set of buttons': a one-button modal says 'Use <ComposedModal>'. Three buttons appear only in the ComposedModal guidance, as Button children of ModalFooter, which also needs application-level CSS. The docs name neither way as the default. Evidence: Claims 2 and 3 were voted 3-0 and claim 4 was voted 2-1, all on Storybook MDX from the current main branch. The evidence does not show that Modal is built internally on ModalHeader, ModalBody and ModalFooter. The two ways are not fully equivalent, because a one-button footer is possible only with ComposedModal. Confidence high; vote 3-0 (button-layout guidance 2-1). Source: https://react.carbondesignsystem.com/?path=/docs/components-composedmodal--overview and https://github.com/carbon-design-system/carbon/blob/main/packages/react/src/components/ComposedModal/ComposedModal.mdx, checked 2026-11-20.
- Carbon Components Svelte (carbon-components-svelte) offers the same pair from one package. ComposedModal is used with ModalHeader, ModalBody and ModalFooter, and Modal is the simpler component. The docs say: 'The composed modal provides a composition-based approach ... for maximum flexibility. For simpler use cases, use Modal instead. Both components share the same events, accessibility features, and focus behavior.' This library is a Svelte port of Carbon and is not on the list of systems the question asks about. Its docs name no default and do not say that Modal is built on the parts. Evidence: Claims 9, 10 and 11, all voted 3-0, from the primary docs scraped on 2026-11-20. This is a neighboring data point only. It is not evidence about Carbon React or Carbon Web Components. Confidence high; vote 3-0. Source: https://svelte.carbondesignsystem.com/components/ComposedModal, checked 2026-11-20.
- Chakra UI v3 splits the two ways across delivery channels. @chakra-ui/react exports only the granular parts, for example Field.Root, Field.Label, Field.RequiredIndicator, Field.HelperText, Field.ErrorText and Field.ErrorIcon. This parts composition is the default in the Usage section. The out-of-the-box form is a 'closed component composition'. It is a user-owned snippet built on the same parts and configured by the props label, helperText, errorText and optionalText. It is copied by hand or added with 'npx @chakra-ui/cli snippet add field'. It is not a package export. The migration guide says: 'Snippets provide pre-built compositions of Chakra components to save you time and put you in charge.' Evidence: Claims 5, 6, 7, 8 and 13, all voted 3-0 on primary docs dated 2026-11-20. Quote: 'If you prefer a closed component composition, check out the snippet below.' The parts are styled wrappers of Ark UI. Confidence high; vote 3-0. Source: https://chakra-ui.com/docs/components/field and https://chakra-ui.com/docs/get-started/migration and https://chakra-ui.com/docs/get-started/cli, checked 2026-11-20.
- Chakra UI v3 removed the v2 Modal family (Modal, ModalOverlay, ModalContent, ModalHeader, ModalBody, ModalFooter, ModalCloseButton). Its replacement is the compound Dialog: Dialog.Root, Dialog.Backdrop, Dialog.Positioner, Dialog.Content, Dialog.Header, Dialog.Body, Dialog.Footer and Dialog.CloseTrigger, used with a Portal. The package exports no single Modal or Dialog configured by props. For dialogs, @chakra-ui/react therefore offers granular parts only, and any ready-made form comes from CLI snippets. Evidence: Claim 12 (3-0). The verifier checked the type exports of @chakra-ui/react 3.38.0: there is no 'modal', and Dialog exports only parts and their flat aliases. The quote in the claim paraphrases the migration page and does not match it word for word. Confidence high; vote 3-0. Source: https://chakra-ui.com/docs/get-started/migration and https://unpkg.com/@chakra-ui/react@3.38.0/dist/types/components/index.d.ts, checked 2026-11-20.
- HeroUI v3 (@heroui/react) offers only granular compound parts for composite components. Its docs give no props-configured equivalent. Modal must be composed from Modal.Backdrop, Modal.Container, Modal.Dialog, Modal.Header, Modal.Heading, Modal.Body, Modal.Footer, Modal.Trigger and Modal.CloseTrigger. The migration guide says: 'Must use compound components'. The root Modal takes only children. The parts are available as dot notation or as named exports, for example AccordionItem and AccordionTrigger. They share state and styles through React context. Styles come from a second package, @heroui/styles. The v2-to-v3 comparison table lists 'Single components with many props' (v2) against 'Compound components' (v3). Evidence: Claims 14, 15, 16 and 17 were voted 3-0, and claim 23 was voted 2-1. The release page that announces v3 is dated March 2026. The verifiers did not check whether another HeroUI component, such as AlertDialog, acts as a pre-composed component. Confidence high; vote 3-0 (context-sharing claim 2-1). Source: https://heroui.com/en/docs/react/getting-started/design-principles and https://heroui.com/en/docs/react/migration/modal and https://heroui.com/en/docs/react/components/modal and https://heroui.com/en/docs/react/releases/v3-0-0, checked 2026-11-20.
- HeroUI names its approach in two ways. The first is 'Composition over configuration': 'v2 components were black boxes. v3 adopts compound components: every internal piece is a real element you can style, move, swap, or remove.' The second is 'Progressive Disclosure': 'Components support both simple and compound usage. Start with the one-liner. Add structure when you need it.' The only Progressive Disclosure example is Button, and its 'compound' form is children plus props, not dot-notation parts. HeroUI's use of 'Progressive Disclosure' therefore does not show a ready-made component built on parts. Evidence: Claim 21 was voted 2-1 and claim 22 was voted 3-0. The source is a vendor release announcement, which is promotional in tone, and the 'black boxes' wording is the vendor's own framing. Confidence medium; vote 2-1 / 3-0. Source: https://heroui.com/en/docs/react/releases/v3-0-0 and https://heroui.com/en/docs/react/getting-started/design-principles, checked 2026-11-20.
- Adobe ships its layers as separate libraries, not as one package. The 2020 launch post names three: 'React Spectrum — A React implementation of Spectrum'; 'React Aria — A library of React Hooks that provides accessible UI primitives'; 'React Stately — ... state management'. It says that React Spectrum 'splits each component into three parts: state, behavior, and the rendered component' and 'puts all of these pieces together and implements the Adobe-specific styling'. Its guidance on when to use which: React Spectrum if you want 'an end-to-end component library', and the hooks 'for even more customizability ... with your own DOM structure and styling'. Evidence: Claims 18, 19 and 20, all voted 3-0. The source is a primary blog post from July 2020, older than React Aria Components (2023) and Spectrum 2 (@react-spectrum/s2). The verifiers noted that the packages are still separate in 2026, but React Aria Components was not verified directly. Confidence medium; vote 3-0. Source: https://react-aria.adobe.com/blog/introducing-react-spectrum, checked 2026-11-20.
- MUI ships its headless and styled layers as two packages. MUI v6 docs describe MUI Base as headless components 'extracted from Material UI, and ... now available as a standalone package'. The styled components are in @mui/material. @mui/base has since been deprecated, and its successor Base UI (@base-ui-components/react, later @base-ui/react) is also separate from @mui/material. Material UI's own styled parts, such as Dialog with DialogTitle and DialogContent, ship within @mui/material. Evidence: Claim 24 (3-0) rests on v6 docs, so the package it names is out of date. The Base UI successor and the Material UI Dialog parts appear only in the verifier's notes; they were not verified as separate claims. Confidence medium; vote 3-0. Source: https://v6.mui.com/base-ui/getting-started/, checked 2026-11-20.
- No single name for the layered pattern was verified in the sources. The terms found are: - 'compound components': Mantine, for the parts layer; HeroUI, for its whole v3 pattern. - 'closed component composition': Chakra, for the props-configured wrapper. - 'pre-built compositions' and 'snippets': Chakra. - 'modal variants': Carbon React. - 'composition-based approach': Carbon Svelte. - 'Composition over configuration' and 'Progressive Disclosure': HeroUI. None of the verified sources used 'layered API', 'primitives and compositions', 'convenience component', 'open component' or 'inversion of control'. Evidence: This finding is synthesized from the quotes in claims 1, 3, 6, 9, 13, 21 and 22. No widely cited secondary writing, such as Kent C. Dodds on compound components or Radix on primitives, was among the verified claims. The finding covers only the term usage that was verified. Confidence medium; vote synthesized. Source: https://mantine.dev/core/modal/ and https://chakra-ui.com/docs/components/field and https://chakra-ui.com/docs/get-started/migration and https://react.carbondesignsystem.com/?path=/docs/components-composedmodal--overview and https://svelte.carbondesignsystem.com/components/ComposedModal and https://heroui.com/en/docs/react/releases/v3-0-0, checked 2026-11-20.

Limits that the run states: The verified evidence covers only Mantine, Carbon React, Carbon Svelte, Chakra UI v3, HeroUI v3, Adobe (React Spectrum and React Aria, from a 2020 post) and MUI (v6-era MUI Base). No claims survived verification for Ant Design, Microsoft Fluent UI (React v9 and Web Components), Atlassian, Shopify Polaris, GitHub Primer, PrimeReact, Carbon Web Components, Base UI or React Aria Components. Part (6) of the question, which asks which systems offer only parts and which only props-configured components, is therefore answered only for HeroUI v3 and the @chakra-ui/react package (parts only). For Mantine and Carbon React, the 'built on those same parts' condition was not confirmed. The Adobe and MUI evidence is dated (2020; MUI v6) and names packages that have since been superseded. Carbon Svelte is outside the requested list. 'Default' is inferred from page order wherever the docs do not state it. Two claims passed with split 2-1 votes: the Carbon button-layout guidance and the HeroUI context-sharing claim. The HeroUI release note is promotional in tone.

Other sources that the run fetched and that gave no verified claim: https://github.com/carbon-design-system/carbon/discussions/12726, https://github.com/adobe/react-spectrum/discussions/7398, https://alanbsmith.medium.com/layered-components-6f18996073a8, https://next.chakra-ui.com/blog/announcing-v3, https://maecapozzi.com/newsletter/77, https://ant.design/components/menu, https://ant.design/components/select, https://v11.primereact.org/docs/primitive/select, https://primer.style/product/components/select-panel, https://github.com/heroui-inc/heroui/discussions/5837, https://github.com/heroui-inc/heroui/blob/v3/CLAUDE.md.
