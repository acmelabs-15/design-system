Needed by IDEA-010#03, the decision which build tools, CI pipeline, release flow and deployment the new system uses.

**Patterns across the systems (facts, not ranked):**
- Monorepo tool: TanStack uses Nx with Nx Cloud remote cache and distributed agents; shadcn/ui and Radix Themes use Turborepo without a remote cache in CI; Radix Primitives, Chakra UI and Zag.js use pnpm workspaces alone; Ark UI uses Bun workspaces.
- Package manager: pnpm in every repository except Ark UI (Bun 1.4.2). Versions range from pnpm 10.0.0 to 12.18.0.
- Bundler: tsdown (Zag.js, TanStack Query and Table), tsup (shadcn/ui, Ark Solid), esbuild scripts (Radix), Rollup (Chakra UI), Vite library mode (TanStack Router and Form, Ark React and Vue).
- Browsers: wherever a browser runs in CI it is Chromium, except Radix Themes, which runs Chromium, Firefox and WebKit for visual regression on macOS. Chakra UI, Ark UI and TanStack Query run no browser in CI.
- Release: every public repository uses Changesets except Radix Themes (manual GitHub release); Geist's component release is not public. Package previews per pull request exist at TanStack (pkg.pr.new) and, on request by label, at shadcn/ui (npm snapshot versions).
- Deployment: documentation sites of shadcn/ui, Radix, Chakra UI, Ark UI and Zag.js deploy on Vercel with a preview per pull request; TanStack serves all documentation from one site on Cloudflare Workers that reads each repository's docs from GitHub.
- Main pull-request workflow medians range from 1.6 minutes (Chakra UI) to 13.0 minutes (TanStack Router).

**Limits and what could not be confirmed:**
- Run times include only successful first attempts, so failed and re-run runs are excluded. They are wall time from `run_started_at` to `updated_at`, so they include runner queue time inside the run. Radix Primitives and Radix Themes had few recent runs, so their windows are short (Radix Primitives pull requests: 2026-10-09 to 2026-10-14) or old (Radix Themes: 2026-02-03 to 2026-04-11).
- For TanStack, the time spent on Nx agents and the Nx Cloud cache hit rate are visible only in Nx Cloud (UNVERIFIED).
- How tanstack.com is deployed (no deploy workflow in its repository) is UNVERIFIED.
- The Vercel projects' build settings and any Vercel remote cache use are not visible in the repositories.
- Geist's components: the monorepo tool, package manager, bundler, tests, CI browsers, caching, workflows, release flow, package previews, CI times and how vercel.com/geist is built and deployed. Only the documentation site and the font repository are public.
- How the Nx agents of TanStack Router and Form install Chromium (UNVERIFIED; it may be set in Nx Cloud launch templates).
- No statement was found from shadcn/ui, Chakra UI or Ark UI on why their build or CI tools were chosen.
- No maintainer reason was found for most tool choices; the statements found are listed under "Maintainer statements".

## Findings

Method. Each repository was cloned at the head of its default branch on 2026-11-13 and its files were read; nothing was run. Commits are named per system below. Run times come from the GitHub REST API (`/actions/workflows/<file>/runs?status=success&per_page=30`): the 30 most recent successful runs, first attempts only, measured from `run_started_at` to `updated_at` (wall time of the whole run, queue time inside the run included). Deployments come from the GitHub deployments API (`/repos/<repo>/deployments`), checked 2026-11-13.

### shadcn/ui (shadcn-ui/ui at `e62c9435fff729a175f38983dee73b2cb4f6a069`, 2026-11-13)

Base URL for the file sources below: `https://github.com/shadcn-ui/ui/blob/e62c9435fff729a175f38983dee73b2cb4f6a069/`.

- Monorepo tool: Turborepo (`turbo` ^2.9.18). Build, lint, typecheck, format and test run through `turbo run`. `turbo.json` declares task outputs and no remote cache settings; no workflow sets `TURBO_TOKEN` or `TURBO_TEAM`. Source: package.json#L13-L47 and L77, turbo.json, checked 2026-11-13.
- Package manager: pnpm 10.33.4 (`packageManager`), with workspaces `apps/*` and `packages/*`. `pnpm-workspace.yaml` sets `minimumReleaseAge: 2880` (48 hours). Node in CI is 20, 22 or 24, depending on the job. Source: package.json#L50, pnpm-workspace.yaml, .github/workflows/*.yml, checked 2026-11-13.
- Packages: four published packages (`shadcn` CLI, `@shadcn/registry`, `@shadcn/react`, `@shadcn/helpers`) and one private test package. Each builds with tsup (^8.5.0); the `shadcn` config emits ESM only, with `dts: true`, `minify: true` and `target: "esnext"`. Source: RELEASING.md, packages/*/package.json, packages/shadcn/tsup.config.ts, checked 2026-11-13.
- Type check: `tsc --noEmit` per package, run as `pnpm typecheck` through Turborepo. Lint: ESLint 9 (`eslint-config-next`, `eslint-config-turbo`). Format: Prettier 3 with the Tailwind and sort-imports plugins. Commit messages: commitlint. Source: package.json, apps/v4/package.json#L11-L13, .github/workflows/code-check.yml#L151, checked 2026-11-13.
- Tests: Vitest 3.2 for unit tests. `@shadcn/react` adds Vitest browser mode with the Playwright provider in headless Chromium only ("Browser tests to cover what jsdom cannot"). The root `test` script builds the registry, starts the site on port 4000 with `start-server-and-test` and runs the package tests against it. Source: packages/react/vitest.browser.config.ts, packages/react/package.json#L51-L52, package.json#L45, checked 2026-11-13.
- CI browsers: Chromium only, installed with `playwright install --with-deps chromium`, in `browser-tests.yml`, which runs only when `packages/react/**` changes. Source: .github/workflows/browser-tests.yml#L1-L13 and #L54, checked 2026-11-13.
- Caching: `actions/cache` of the pnpm store, keyed on `pnpm-lock.yaml`, in every job; a separate `actions/cache` of `~/.cache/ms-playwright`. No Turborepo remote cache is configured in the repository. Source: .github/workflows/code-check.yml#L49, browser-tests.yml#L46, checked 2026-11-13.
- Workflows on pull requests: `code-check.yml` (jobs: registry changeset check, lint, format check, typecheck; typecheck first builds packages and the registry); `test.yml` (jobs: `pnpm test`, `@shadcn/react` tests, `@shadcn/helpers` tests); `browser-tests.yml` (path filter); `templates.yml` (a matrix that creates projects from templates with pnpm 10.33.4 and 11 and other package managers, timeout 45 minutes, path filter); `validate-registries.yml` (path filter on `directory.json`). Others: `release.yml`, `prerelease-comment.yml`, `monitor-registries.yml` (hourly cron, registry health), signed-commit checks and stale issues. Every job runs on `ubuntu-latest`. Source: .github/workflows/, checked 2026-11-13.
- Release: Changesets. On push to `main`, `changesets/action` opens or updates a "Version Packages" pull request; merging it publishes every package whose version is ahead of npm to `latest`. Publishing uses npm trusted publishing with OIDC and provenance (`id-token: write`, `npm@latest`, no `NPM_TOKEN`). A custom script publishes `@shadcn/registry` before `shadcn`, because `shadcn` pins an exact registry version. Source: RELEASING.md, .github/workflows/release.yml#L140-L190, checked 2026-11-13.
- Prereleases: a maintainer adds the label `release: beta` or `release: rc` to a pull request. The `prerelease` job (GitHub environment `Preview`) runs `changeset version --snapshot <channel>` and publishes `0.0.0-<channel>-<timestamp>` versions under that dist-tag; `prerelease-comment.yml` then posts install lines on the pull request and removes the label. Longer trains use Changesets pre mode. Source: RELEASING.md, .github/workflows/release.yml#L18-L117, checked 2026-11-13.
- Deployment: the site (`apps/v4`, Next.js) deploys on Vercel through the Vercel GitHub integration. The deployments API shows 73 of the last 100 deployments as "Preview – ui" and 26 as "Production – ui", all by `vercel[bot]`; the latest preview is from 2026-11-13 and the latest production deployment from 2026-11-11. So each pull request gets a Vercel preview of the site. Package previews are the label-driven snapshot releases above. Source: https://api.github.com/repos/shadcn-ui/ui/deployments, checked 2026-11-13.
- Run times (30 successful first-attempt runs each): `code-check.yml` 3.8 to 8.6 minutes, median 5.5 (2026-11-05 to 2026-11-13); `test.yml` 9.0 to 16.1, median 12.5 (same window); `templates.yml` 6.2 to 11.7, median 6.8; `browser-tests.yml` 1.6 to 10.2, median 2.2 (29 runs, 2026-09-12 to 2026-11-12); `release.yml` on push 0.8 to 3.3, median 1.2. Derived, not measured: the workflows run in parallel, so a pull request waits about as long as `test.yml`. Source: https://api.github.com/repos/shadcn-ui/ui/actions/workflows/test.yml/runs, checked 2026-11-13.

### Radix Primitives (radix-ui/primitives at `eb3a2b7091293e27df8f9ba906632d8daa3d81a3`, 2026-10-14)

- Bundler: an internal builder `@repo/builder` (command `radix-build`) that calls esbuild for CJS and ESM output with `target: 'es2022'`, and tsup only for declaration files (`dts: { only: true }`). Source: internal/builder/package.json, internal/builder/builder.js, checked 2026-11-13.
- Type check: `tsc --noEmit` per package (`types:check` at the root). Lint: oxlint (`oxlint --max-warnings 0 src` per package). Format: oxfmt (`oxfmt --check`). Source: package.json, packages/react/dialog/package.json, checked 2026-11-13.

- Caching: `actions/setup-node` with `cache: pnpm`, and an `actions/cache` of `~/.cache/ms-playwright` keyed on the Playwright version. No build cache. Source: .github/actions/ci-setup/action.yml, .github/workflows/build.yml#L62, checked 2026-11-13.
- Workflows: `build.yml` on pull request and push to `main` and `stable` (three parallel jobs: lint, composed-refs check and build; unit tests; Playwright end-to-end); `ssr.yml` on pull request (builds and tests an SSR test app); `chromatic.yml` on push to `main` and every pull request (Storybook to Chromatic with `chromaui/action`); `publish.yml` on push to `main` and `stable` and on manual dispatch. All on `ubuntu-latest`. Source: .github/workflows/, checked 2026-11-13.
- Release: Changesets. Stable: a maintainer recreates a `stable` branch from `main` and pushes it; `changesets/action` opens a release pull request; merging it publishes to npm; the branch is then deleted, and a job opens a backport pull request. Snapshots: on push to `main`, at most once a day (the job skips when `radix-ui@next` was already published that day), the workflow runs `changeset version --snapshot` with the template `rc.{timestamp}` and publishes under the `next` tag. Both publish with `--provenance` / `NPM_CONFIG_PROVENANCE` and `id-token: write`; the setup action pins npm 11.18.0 for OIDC trusted publishing and avoids npm 12, which changesets mis-parses. Source: release-process.md, .changeset/config.json, .github/workflows/publish.yml#L35-L74, .github/actions/publish-snapshot/action.yml, .github/actions/publish-stable/action.yml, .github/actions/detect-snapshot-changes/action.yml, .github/actions/ci-setup/action.yml, checked 2026-11-13.
- Deployment: the documentation lives in a separate repository, radix-ui/website (Next.js 16, pnpm 10.2.0, at `402e749613ab2e7ab7139c65b0029842b0360f07`, 2026-10-07). Its deployments API shows Vercel previews and production deployments by `vercel[bot]` (52 Preview and 48 Production among the last 100, latest 2026-10-07). release-process.md calls the documentation update "currently a manual process". The primitives repository itself has no current deployments (its last Vercel deployment is from 2020); its Storybook goes to Chromatic on each pull request. No package preview per pull request exists; snapshots come from `main`. Source: https://api.github.com/repos/radix-ui/website/deployments, https://api.github.com/repos/radix-ui/primitives/deployments, release-process.md, checked 2026-11-13.
- Run times: `build.yml` 1.8 to 3.2 minutes, median 2.2 (29 runs, 2026-10-13 to 2026-10-14, pull request and push); pull requests only 1.9 to 4.6, median 2.3 (24 runs, 2026-10-09 to 2026-10-14); `ssr.yml` 0.4 to 5.6, median 0.6 (27 runs); `chromatic.yml` 0.8 to 1.9, median 1.0 (30 runs). Source: https://api.github.com/repos/radix-ui/primitives/actions/workflows/build.yml/runs, checked 2026-11-13.

### Maintainer statements on tool choice and speed

- TanStack's CI/CD page: `pr.yml` "Runs nx affected, which only executes tasks with invalidated cache" and "uses pkg-pr-new to publish package previews and create links to our examples"; `release.yml` "Runs nx run-many, which executes all tasks and ensures the outputs are present (necessary for publishing builds)".
