# RES-067: Blocks and recipes of the reference systems

## Question
Which blocks and recipes do shadcn/ui, Radix (Primitives and Themes), Chakra UI and Geist have, and which AI components and AI blocks among them: for each, what it composes, which state and composition pattern it shows, and how the system gives it out?

Settled context: the glossary calls a documented arrangement of shared components for a particular use a Recipe. The library gives no recipe out as a component; the documentation website shows recipes in a section named Blocks (DEC-140). That section has four groups (DEC-146): agent interfaces, page sections for marketing and content sites, app layouts, and charts. In Chakra UI a "recipe" is a style configuration, which is another thing.

Needed by: IDEA-007#11, the decision which blocks the new system has, by name, in each of the four groups.

## Answer
Sufficient answer: (1) for each system, at a named version or date, every block, recipe, template, pattern or example layout, by name and category, with counts, or "none found" with what was checked; (2) how each system gives a block out; (3) for each AI component and AI block, the components it composes and the state and composition pattern it shows; (4) for other blocks, name, category and one line, or names and categories when too many; (5) where each source category falls among the four groups of DEC-146; (6) each AI component that is neither in the list of DEC-133/DEC-135 nor a block.

The evidence answers all six points.

1. Inventory (2026-11-13):
   - shadcn/ui: 21 AI Elements patterns (no sub-category), 27 blocks (dashboard 1, sidebar 16, login 5, signup 5; registry categories dashboard, sidebar, authentication, login, signup), 70 chart blocks in 7 chart categories (area 10, bar 10, line 10, pie 11, radar 14, radial 6, tooltip 9). It also gives out 8 chat components as components, not blocks.
   - Chakra UI: no blocks on chakra-ui.com; a chart package with documented examples. Chakra UI Pro: 338 blocks in 4 groups and 51 categories (application 151 in 19 categories, marketing 114 in 17, e-commerce 23 in 5, documentation 50 in 10), plus 7 free blocks, and 4 templates whose content was not read.
   - Radix Primitives: none found. Radix Themes: no blocks section; a Playground of components and three unlinked example pages (dashboard, e-commerce, music app).
   - Geist: none found.
2. Distribution: shadcn/ui blocks and charts are registry items copied by `npx shadcn@latest add <name>`; AI Elements patterns are code on the page that the developer copies, after `npx shadcn@latest add` of the components each needs. Chakra UI Pro is a paid site; code only with a subscription, by `chakra blocks add` with an API key. Chakra charts are an npm package. Radix Themes examples exist only as source in the website repository.
3. Every AI Elements pattern and every Chakra UI Pro AI block is listed under Findings with its parts and state pattern. For Chakra UI Pro, the parts come from the public preview images, because the code is gated.
4. Other blocks: names and categories for all; for shadcn/ui and Radix Themes also the composed components. For Chakra UI Pro, no per-block line on what it composes, because the code is not public (count 338).
5. Mapping to the DEC-146 groups is under Findings. Chakra UI Pro e-commerce and two Radix Themes examples fall in none of the four groups by name.
6. All 8 shadcn/ui chat components are in DEC-135. Items that are neither a listed component nor a block: the shadcn/ui utilities shimmer and scroll-fade and the @shadcn/helpers AI SDK and TanStack AI.

Disagreement with a record: DEC-146 says of page sections for marketing and content sites, "No reference system has them". Chakra UI Pro has 114 marketing blocks and 50 documentation blocks. They are on a paid site separate from the Chakra UI documentation, which may be how the statement was meant; DEC-146 does not say so.

Not confirmed: what each Chakra UI Pro block (other than the 5 AI blocks, by image) composes; the Chakra UI Pro templates' contents; whether the four Pro templates include AI screens; the chatbot template of shadcn/ui (https://github.com/shadcn-ui/chatbot-template), which was not read; the per-page props and API of the AI Elements patterns beyond the sections named.

### shadcn/ui: AI Elements (checked 2026-11-13)

Version: the docs carry no library version. RES-032 names shadcn CLI 4.23.0 and the changelog entry "October 2026 - Trace, Code Block and AI Elements" on 2026-11-12. The pages below were read on 2026-11-13, as the Markdown version of each page (`<page>.md`). The component lists come from the `@/components/ui/<name>` imports and the "built with" sentence of each page.

- The introduction page says: "AI Elements are patterns for building agentic interfaces. Each one is a composition of shadcn/ui components that you copy into your project. There is no package to install. The code is yours." It lists 21 patterns under "Patterns": Chain of Thought, Chat, Checkpoint, Confirmation, Context, File Tree, Inline Citation, Message, Model Selector, Plan, Prompt Input, Queue, Reasoning, Sources, Stack Trace, Subagent, Suggestion, Task, Terminal, Test Results, Tool. The pages carry no further category. Source: https://ui.shadcn.com/docs/ai-elements, checked 2026-11-13.
- The introduction page says: "A Chat is a list of Message turns inside a Message Scroller. The steps an agent takes inside a turn, like Reasoning, Tool and Plan, are built on Trace, so every step has the same shape". Source: https://ui.shadcn.com/docs/ai-elements, checked 2026-11-13.
- Distribution of a pattern: each pattern page has an Installation part with a Command tab (`npx shadcn@latest add <the components it needs>`, for example `npx shadcn@latest add trace code-block` for Tool) and a Manual tab. The pattern code itself is code on the page that the developer copies: "Open a pattern above and copy its code into your project. Each page lists any other components it needs." The introduction also offers a prompt for a coding agent. Source: https://ui.shadcn.com/docs/ai-elements and https://ui.shadcn.com/docs/ai-elements/base/tool.md, checked 2026-11-13.
- Each pattern page exists per base library; the sidebar links the `/docs/ai-elements/base/<slug>` variant. RES-032 (line 61) found 21 pages for each of aria, base and radix. Source: https://ui.shadcn.com/docs/ai-elements and docs/research/RES-032-components-of-shadcn-ui.md:61, checked 2026-11-13.
- The demos use the AI SDK (`useChat` from `@ai-sdk/react`, types from `ai`) and a scripted chat (`createChat` from `@/lib/ai`, documented as the @shadcn/helpers "AI SDK" helper). The sidebar also has a "TanStack AI" helper page. Source: https://ui.shadcn.com/docs/ai-elements/base/chat.md and https://ui.shadcn.com/docs/ai-elements, checked 2026-11-13.
- The introduction points to a separate chatbot template: "a Next.js app built with the AI SDK and shadcn/ui, with streaming chat, tool calls, web search and clarifying questions", at https://github.com/shadcn-ui/chatbot-template. Not read further. Source: https://ui.shadcn.com/docs/ai-elements, checked 2026-11-13.
- The 21 patterns replace AI SDK Elements (elements.ai-sdk.dev). The migration table maps 26 files of AI SDK Elements to a pattern, to a component (attachments.tsx to Attachment, code-block.tsx to Code Block, commit.tsx to Trace, question.tsx to Questionnaire) or to the shimmer utility. These AI SDK Elements files have no replacement, with the components the page names to build them: artifact (Card, Button, Tooltip), audio-player (audio element, Button Group, Slider), canvas, connection, controls, edge, node, panel and toolbar (React Flow, Card, Button Group), environment-variables (Item, Badge, Switch), image (img element), jsx-preview (a JSX parser), mic-selector and voice-selector (Combobox), open-in-chat (Dropdown Menu), package-info (Item, Badge), persona (a Rive animation), sandbox (Trace, Tabs, Code Block), schema-display (Collapsible, Badge, Code Block), snippet (Input Group), speech-input (Button, Spinner, Web Speech API), transcription (Button per segment), web-preview (iframe, Input Group). Source: https://ui.shadcn.com/docs/ai-elements#migrating-from-ai-sdk-elements, checked 2026-11-13.

Each pattern, with the shadcn/ui components it imports and the state and composition pattern its page describes. Source of each line: https://ui.shadcn.com/docs/ai-elements/base/<slug>.md, checked 2026-11-13.

- Chain of Thought (`chain-of-thought`). Imports Trace, Code Block, Badge, plus Message, Bubble and Button in the demo. "A summary line that expands into the steps an agent took", such as "Researched in 3 steps". Each step is a TraceLine with a status: running ("Searching for …"), done with detail, done with a link, failed ("Failed to search for …"). Web search results show as a Badge per hostname. The summary opens while the steps run. Built on a TraceCollapsible for the summary. Source: https://ui.shadcn.com/docs/ai-elements/base/chain-of-thought.md, checked 2026-11-13.
- Chat (`chat`). Built with Message Scroller, Message, Bubble and Input Group; the demo also imports Code Block, Dropdown Menu, Empty, Tooltip, Trace, Button, and `motion/react`. "The thread of a conversation with the agent." Each turn is a Message inside Message Scroller. The person's message is the scroll anchor (`scrollAnchor`), so the reply streams in under it; `autoScroll` follows the reply while the person stays at the live edge. The field is a Prompt Input. With the helper, each agent turn streams reasoning, a tool call and a reply. Source: https://ui.shadcn.com/docs/ai-elements/base/chat.md, checked 2026-11-13.
- Checkpoint (`checkpoint`). Built with Marker and Button. A Marker after a turn with a Restore button; Restore keeps that turn and drops every later message. Scripted as a data part with an `id` on the agent's turn. Source: https://ui.shadcn.com/docs/ai-elements/base/checkpoint.md, checked 2026-11-13.
- Confirmation (`confirmation`). Built with Item and Button; the demo also imports Trace. Asks for approval before a tool runs: an Item with Deny and Approve buttons, outside the Trace, while the tool part is `approval-requested`. Approve streams the tool output; Deny streams `output-denied`. Either way the part then becomes a Tool line. The chat continues by `sendAutomaticallyWhen: lastAssistantMessageIsCompleteWithApprovalResponses`. Source: https://ui.shadcn.com/docs/ai-elements/base/confirmation.md, checked 2026-11-13.
- Context (`context`). Built with Hover Card and Progress (and Button). Shows how much of the model's context window the conversation has used: a Hover Card with a Progress bar. Usage comes from message metadata when the stream finishes; the limit is set by the developer, because the AI SDK does not send it. Source: https://ui.shadcn.com/docs/ai-elements/base/context.md, checked 2026-11-13.
- File Tree (`file-tree`). Built with Collapsible and Button. The files the agent changed, as a folder tree: a folder is a Collapsible, a file a Button, rendered recursively. For one file the page points to a Tool line instead. Note: this is a pattern, while DEC-135 has File Tree as a component. Source: https://ui.shadcn.com/docs/ai-elements/base/file-tree.md, checked 2026-11-13.
- Inline Citation (`inline-citation`). Built with Hover Card and Button. A source inside the sentence that opens on hover. The citation is a `source-url` part; the title falls back to the hostname. Source: https://ui.shadcn.com/docs/ai-elements/base/inline-citation.md, checked 2026-11-13.
- Message (`message`). Built with Message, Bubble and Tooltip (and Button). One turn: the person's text is a Bubble on a Message with `align="end"`; the agent's reply is Markdown on a Message with actions in `MessageFooter`: Copy (swaps to a check for two seconds), Good response and Bad response toggles with `aria-pressed`, Retry, and Edit on the person's turn. Has a Markdown section. Source: https://ui.shadcn.com/docs/ai-elements/base/message.md, checked 2026-11-13.
- Model Selector (`model-selector`). Built with Dropdown Menu and Input Group. "Two menus. One picks the model the agent runs, the other picks how hard it thinks." The model and the effort are sent with the message and mapped to provider options on the server. Source: https://ui.shadcn.com/docs/ai-elements/base/model-selector.md, checked 2026-11-13.
- Plan (`plan`). Built with Trace. The steps the agent decides on before it starts; each step is done, running or pending, and the title counts how many are done. A description goes inside TraceCollapsibleContent. Streamed as a data part with a fixed `id`, so it updates in place. Source: https://ui.shadcn.com/docs/ai-elements/base/plan.md, checked 2026-11-13.
- Prompt Input (`prompt-input`). Built with Input Group, Attachment and Dropdown Menu. An Input Group with a textarea, an attach button, the two Model Selector menus and a send button. The attach button opens a hidden file input; each file shows as an Attachment chip in a `block-start` addon with a remove button. Enter sends; Shift+Enter adds a line. Sends the text and the FileList. Source: https://ui.shadcn.com/docs/ai-elements/base/prompt-input.md, checked 2026-11-13.
- Queue (`queue`). Built with Trace. The agent's todo list in two sections, To do and Completed. Todo status maps to a section, an icon and a TraceLine status: `pending` (To do, no status), `in_progress` (To do, `"running"` while the chat streams), `completed` (Completed). A todo with a description is a TraceCollapsible. Each `writeTodos` call sends the whole list; the last call is rendered and a call whose input still streams is skipped. Source: https://ui.shadcn.com/docs/ai-elements/base/queue.md, checked 2026-11-13.
- Reasoning (`reasoning`). Built with Trace. Reads "Thinking" and opens while the model thinks, then reads "Thought" and closes. It starts as a plain TraceLine and becomes a TraceCollapsible once text arrives. If the person opens or closes it, their choice wins. Duration is measured on the server and shown in a TraceDescription. Several reasoning parts are several lines in one Trace. Source: https://ui.shadcn.com/docs/ai-elements/base/reasoning.md, checked 2026-11-13.
- Sources (`sources`). Built with Trace. A line that says "Used 3 sources" and opens into one link per source. Collects the `source-url` parts, deduplicated by `url`. Has an Accessibility section: links open in a new tab with `sr-only` text. Source: https://ui.shadcn.com/docs/ai-elements/base/sources.md, checked 2026-11-13.
- Stack Trace (`stack-trace`). Built with Trace and Code Block. A line for a failed tool call (`output-error`); the error is the title, like "Failed: TypeError". Opens to the stack frames; own frames can link to the file and line; `node_modules` frames stay muted and fold into a collapsible line. The page says to send stacks only in development. Source: https://ui.shadcn.com/docs/ai-elements/base/stack-trace.md, checked 2026-11-13.
- Subagent (`subagent`). Built with Trace, Code Block and Badge. A line for work handed to a subagent, like "Ran the research agent", with a nested Trace for the subagent's tool calls. While it runs, the line has `status="running"` and shows the calls so far. Preliminary outputs (`output-available` with `preliminary: true`) still count as running. Details: the task at the top, model and tools as Badge items, duration in a TraceDescription. Source: https://ui.shadcn.com/docs/ai-elements/base/subagent.md, checked 2026-11-13.
- Suggestion (`suggestion`). Built with Button. A prompt sent in one click: a row of Buttons above the Prompt Input that scrolls sideways with the `scroll-fade-x` utility. Source: https://ui.shadcn.com/docs/ai-elements/base/suggestion.md, checked 2026-11-13.
- Task (`task`). Built with Trace. A piece of work whose steps appear as the agent takes them. Status from the steps: a running step gives `"running"` and a present-tense title, a failed step `"error"`, all done no status and a past-tense title. Several tasks sit in one Trace. Each task is a data part with its own `id`. The page has a table that compares Task and Plan: Plan knows every step from the start and has pending steps; Task has none. Source: https://ui.shadcn.com/docs/ai-elements/base/task.md, checked 2026-11-13.
- Terminal (`terminal`). Built with Trace and Code Block. A shell command the agent runs, with output streaming underneath. Exit code 0 gives no status ("Ran pnpm build"); another code gives `"error"` ("pnpm lint exited with code 1"). The line opens once the first output arrives. Output streams as a data part with the tool call's id. Source: https://ui.shadcn.com/docs/ai-elements/base/terminal.md, checked 2026-11-13.
- Test Results (`test-results`). Built with Trace and Code Block. A test run: the summary line counts passes and failures; each suite (grouped by file) is a collapsible line with a Trace of its tests; suites with a failure open. Source: https://ui.shadcn.com/docs/ai-elements/base/test-results.md, checked 2026-11-13.
- Tool (`tool`). Built with Trace and Code Block; the demos also import Item and Sheet. A tool call from input to output. Tool part states map to a TraceLine status and title: `input-streaming`/`input-available` give `"running"` ("Running …") while the chat streams, or `"error"` ("Failed to run …") after it stops; `approval-requested` is an Item outside Trace with Approve and Deny; `approval-responded` gives running or "Denied …"; `output-available` gives "Ran …"; `output-error` gives "Failed to run …"; `output-denied` gives "Denied …". A tool is a plain TraceLine while it runs and a TraceCollapsible once output arrives. Long output can go in a Sheet behind a SheetTrigger. Source: https://ui.shadcn.com/docs/ai-elements/base/tool.md, checked 2026-11-13.
